# 同一对话跨端继续

## 背景与问题

用户在手机创建对话后，需要在Web打开原有消息并继续交流。当前两端分别执行任务，各自保存工作文件和Claude会话转录。Web能够读取共享消息时，仍可能因本端缺少转录而发送失败。

## 目标与边界

用户在原对话继续发送消息，保留原对话身份、Claude会话身份、消息历史、登录和访问权限。手机工作区与Web云端工作区独立存在；普通工作文件继续保留在产生文件的执行端。

本期覆盖对话上下文准备与当前消息的一次提交。工作文件同步、离线数据库、设备管理、任务跨端接管和新会话框架退出范围。原端尚在执行或执行结果未确认时，当前端保留输入并等待核实。

本文定义跨端继续的产品规则。源码实施与技术验证见[实施记录](../../exec/cross-platform-chat-continuation-20261104.md)，正常服务启用、原生包采用与真实业务验收分别待执行。正式方案见[跨端交互设计与评审](../../design/multi-platform/cross-platform-chat-continuation.md)；其中Runtime恢复资格和Admin发布前提满足后，才进入实施验收。

## 概念与规则

| 对象或操作 | 产品规则 |
| --- | --- |
| 同一对话 | 两端使用同一条对话及其历史，继续发送保持原归属。 |
| 创建来源 | 对话创建时记录Web、iOS或Android执行端；后续打开和发送保留最初来源。旧对话来源显示为“待确认”。本期区分执行端类别，同类别的两台手机保持相同类别。 |
| 打开原对话 | 复用现有历史入口，只读取消息；打开、切换栏目、重新加载均不发送消息。 |
| 本端准备就绪 | 用户发送后沿原流程继续。历史在另一端新增时，发送前补齐已确认的上下文。 |
| 本端首次准备 | 用户发送后显示“正在准备对话”，保留输入和原消息；准备完成后沿本次操作提交一次。 |
| 准备失败 | 保留原对话、历史和待发送内容，显示对应反馈及“重试”；重试针对同一条待发送消息。 |
| 发送结果待确认 | 显示“正在核实发送结果”，提供“重新加载”；核实只读取原记录。 |
| 其他端运行中 | 显示“此对话正在其他端处理，请稍后继续”，保留输入；原端停止及完成沿原入口处理。 |
| 历史工具记录 | 作为既有上下文读取。准备过程不重新执行历史文件写入、网络请求或其他工具操作。 |
| 文件范围 | 当前工作区显示本端实际可访问的文件。历史提到的手机本地文件继续留在手机；需要时由用户通过已有上传入口提供。 |

创建来源仅供Admin识别创建位置和排查问题。原登录、对话归属与工具确认继续分别校验。普通Chat无需新增来源徽章、独立页面或确认弹窗。

准备期间允许修改草稿；已经点击发送的消息内容保持冻结，另行输入沿现有草稿规则保存。准备成功只提交冻结内容。准备失败时恢复该内容供用户修改；修改后使用新的消息身份。已提交消息沿原历史展示，待发送内容按消息身份去重。

## 桌面与窄屏反馈骨架

```text
桌面：沿现有Chat布局
┌──────────┬───────────────────────────┬──────────────────┐
│历史入口  │原对话标题／现有任务入口   │现有工作区栏目    │
│选择原对话│                           │文件／原资源入口  │
│列表独立滚│原消息列表，纵向滚动       │只列本端可用文件  │
│动        │原工具过程仍可展开         │栏目独立滚动      │
│          ├───────────────────────────┤                  │
│          │行内反馈：正在准备对话     │                  │
│          │失败说明 + 重试／重新加载  │                  │
│          │原输入区、附件、发送／停止 │                  │
└──────────┴───────────────────────────┴──────────────────┘
```

```text
窄屏：原Chat页，保持现有历史与工作区切换入口
┌────────────────────────────────┐
│返回／历史  原对话标题  工作区入口│
├────────────────────────────────┤
│原消息列表，纵向滚动             │
│原正文与工具过程                 │
├────────────────────────────────┤
│正在准备对话／失败说明           │
│[重试] 或 [重新加载]             │
│原输入区、附件、发送／停止       │
└────────────────────────────────┘
工作区沿原栏目打开；栏目内独立滚动，返回保留输入与阅读位置。
准备与失败反馈使用原行内区域；新增弹窗数量为零。
```

| 反馈条件 | 用户文案与可执行操作 |
| --- | --- |
| 正常缺少本端目录或转录 | “正在准备对话”；本次发送等待准备完成。 |
| 历史暂时无法读取 | “暂时无法读取对话记录，请重试”；保留输入并允许重试准备。 |
| 当前账户无权限 | 沿原登录或访问受限反馈处理，重新取得权限后读取原对话。 |
| 工作区访问失败或转录损坏 | “此端暂时无法准备对话”；提供原错误详情入口和重试，记录保持。 |
| 历史结构暂不支持恢复 | “此端暂时无法继续此对话”；可回原端继续，保留当前输入。 |
| 已提交后的网络中断 | “正在核实发送结果”；重新加载原任务及历史，恢复读取。 |

## 后续业务验收

1. 使用指定的现有账户在手机创建对话，完成一轮含明确约定的消息；Admin可查消息与创建来源。
2. Web打开原对话，显示原消息；首次发送自动准备并准确沿用前文约定。两端对话标识和Claude会话标识均保持。
3. Web再次发送、刷新重开后发送，均复用本端有效记录；原端文件和消息保持。返回手机时先补齐Web已完成消息。
4. 初始化失败及重试保留输入；同一次发送只出现一条用户消息和一次实际请求。历史工具操作的执行次数保持。
5. 两端同时发送时只有一端取得执行权；另一端保留输入。执行情况未确认时只读取核实。
6. 手机本地文件在Web缺失时准确显示文件范围；用户经原上传入口提供后，按普通文件操作继续。

验收前提、技术验证和真实模型调用次数归正式设计的后续验收矩阵。本轮只完成文档设计。
