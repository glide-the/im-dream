# 回归分析：分析内容

## 背景与问题

回顾分析已有统一的生成入口、Notion 开关和按 Deck 分组的分析 Agent 选择。当天已有报告时，再次点击“生成全新分析”进入日记范围选择弹窗。本次补齐弹窗中的分析内容选项，让用户在提交前调整日记、Notion 和分析 Agent。

Notion 的分析范围来自当前已挂载页面。生成时保存该范围，Agent 在分析期间按需读取正文。报告记录实际读取的来源。Deck 提供分组，Agent 提供分析视角。

## 目标与边界

总分析按钮旁提供“分析内容”展开面板，包含 Notion 整体开关和按 Deck 分组的 Agent 选择。关闭各栏目独立 Analyze，保留栏目配置、进度、错误、结果和历史。

所选分析 Agent 提供本次分析视角，三个栏目沿用当前分析规则、模型设置和权限。面板显示“分析 Agent”，Deck 提供分组；未选择 Agent 时使用默认分析。

配置入口位于回顾分析页和已有的当天再次分析弹窗。弹窗直接展开相同的分析内容选项，日记范围、Notion 开关与分析 Agent 在同一次提交中生效。取消弹窗保留本页内容选择；重新打开弹窗时，日记按当前可分析条目重新全选。刷新后内容选择恢复默认值，已有任务按原输入恢复。创建结果未确认或来源校验失败时，沿现有恢复和重试流程处理。

## 概念与规则

| 对象 | 本次规则 |
| --- | --- |
| 默认 | Notion 关闭，Agent 未选择；原日记全范围 |
| 面板选择 | desired 为下一次提交选项，只影响下一次提交，使用 AnalysisView 页面内存；收起面板、关闭弹窗后重开保留；离开分析页面或刷新重置；未确认提交例外按下方存储规则恢复 |
| 执行输入 | effective 为已创建任务的日记选择、Notion 来源范围和 Agent 指令；这些选择在任务启动后固定。Notion 正文在分析期间按需读取，首次成功读取后保存并供本任务复用 |
| Notion 范围 | 当前账户已授权、已挂载页面构成本任务的可读范围。Agent 按栏目需要选择页面，报告只记录实际读取的来源；本任务范围在创建时保存 |
| 日记范围 | 首次分析沿用原全范围；再次分析使用弹窗选中 session_ids；选择为空且 Notion 有正文时允许仅 Notion 分析 |
| 再次分析弹窗 | 直接展示分析内容、来源状态、分析 Agent 和日记列表；沿用本页内容选择。取消只关闭弹窗，提交时使用当时的内容选择和所选日记 |
| 正文版本 | 创建时保存索引版本；每个页面首次成功读取时保存正文、读取时间和摘要。同一任务后续读取复用该正文 |
| 空正文 | 读取为空的页面保留读取记录，分析结果引用有正文的来源。来源范围和日记均为空时提示没有可分析内容；零条分析结果沿原报告保存规则处理 |
| 读取失败 | 创建阶段处理授权、来源范围和 Agent 校验。分析期间的单页读取失败向 Agent 返回明确错误，失败页面无法作为结果引用；已保存证据保留供任务恢复 |
| 快照变化 | 预览与创建时的索引版本不匹配则拒绝创建，提示重新选择。执行期间每次读取均校验当前授权和挂载范围；后续新增页面留待下次任务，已撤销页面停止读取 |
| 引用 | 日记只写 related_session_ids；Notion 使用独立 related_notion_page_ids，经校验后将标题和安全 URL 写入 evidence；索引版本、读取时间及摘要保存在报告来源元数据 |
| 并发 | 立即锁定提交，复用已有任务恢复；配置变化不修改进行中任务；过期候选响应不覆盖当前页面 |
| 创建与启动 | 创建阶段保存来源索引，返回任务后沿原流程订阅事件并启动；页面正文在分析执行期间读取。创建结果未知时保留原提交标识恢复相同任务 |
| 存储 | default 为关闭 Notion 和未选 Agent；desired 保留在页面内存，effective 保存在任务；不增加全局配置或额外 revision；仅未确认创建结果的提交保存窄范围 request_key 与原始选项（无正文或凭证），成功或明确失败后清除；任务状态及 revision 沿用 Admin 合同 |

### 当天再次分析弹窗

当天已有报告时，点击“生成全新分析”打开原弹窗。分析内容直接展开在日记列表上方，开关和分析 Agent 继承本页当前选择。弹窗打开后读取已挂载资源状态和可选 Agent；确认前仅加载选项信息。已有报告和执行中的任务继续采用各自的原输入。

桌面：标题和底部操作固定，中间的分析内容与日记列表共同滚动。分析 Agent 的分组列表沿用现有浮层。

```text
┌ 当天已有回顾分析 ──────────────────────────────┐
│ 本次生成一份新分析，选择日记与分析内容         │
├ 中间内容区：纵向滚动 ────────────────────────┤
│ ┌ 分析内容 ─────────────────────────────────┐ │
│ │ [ ] 将 Notion 加入分析                     │ │
│ │ 已挂载页面范围 / 来源状态 / [重新加载]     │ │
│ │ 分析 Agent [默认分析 ▾] → Deck 组 / Agent  │ │
│ └───────────────────────────────────────────┘ │
│ [全选 / 清空] · 已选数量 / 日记数量           │
│ [✓] 日记摘要、日期、字数                     │
│ [✓] 其他日记…                              │
│ 来源为空时的反馈                            │
├ 固定操作区 ─────────────────────────────────┤
│                        [取消] [分析所选内容] │
└─────────────────────────────────────────────┘
```

窄屏：弹窗受视口高度约束，中间内容区滚动；分析内容随该区域滚动，底部操作保持可见。Agent 浮层在视口范围内展示，可独立滚动选项。栏目切换仍位于原报告阅读页。

```text
┌ 当天已有回顾分析 ────────┐
│ 选择本次分析内容         │
├ 中间内容区：纵向滚动 ───┤

│ [✓] 日记摘要 / 日期    │
│ 其他日记…              │
```

未选日记且 Notion 关闭时，“分析所选内容”禁用。开启 Notion 后允许提交，正文由 Agent 在分析期间按需读取。来源读取失败时显示原反馈和“重新加载”，成功后继续选择。修改分析内容时清除弹窗内原有的日记选择错误，按钮按当前来源选择更新。

### 状态与反馈

CREATED 表示已保存但尚未启动。进入页面只显示“有一项分析尚未开始”及“继续未开始的分析”，不自动调用模型、不锁定新生成。继续采用原任务输入；主生成采用当前选项。已启动任务仍自动订阅原任务并阻止重复生成。

未登录允许查看已有展示，但提交提示登录。Notion 按需读取沿用现有工作区模式；工作区关闭时提示在设置中启用。未连接或授权失效分别显示连接或重新授权提示；无快照提示完成已有资源同步，空索引显示没有挂载页面，读取失败显示重试。展开不执行同步、工作区扫描或正文读取。Deck 加载失败显示重试，默认分析仍可用；已选 Agent 失效须由服务端拒绝，不能退回默认。 已选 Agent 从候选中消失时显示不可用名称及重选提示；Notion 候选版本变化时保留原选择并提示重新开启，不静默换用新范围。

执行失败保留错误；部分成功保留成功栏目并显示失败栏目。断流按已有任务恢复，不能因查询失败清除活动任务后另建任务。创建响应丢失时显示恢复提示，并使用原 request_key 和选项查询原回执；明确尚未创建的失败允许调整选择。保存失败保留当前结果并提供重试保存。服务端任务报告持久化是历史来源，页面不创建第二份全分析报告。

### Analyze Chat 预览标签（已实现）

分析任务保留日记快照、来源范围和 Agent 上下文；实际读取的 Notion 正文与证据通过任务和 Chat 持久化边界保存。Chat 前端对能够精确识别栏目的服务器生成 user message 不再渲染原始 Markdown 气泡，只在原消息位置上方显示一个标签按钮：`回顾分析 · 重复回响`、`回顾分析 · 性格特质` 或 `回顾分析 · 行为模式`。

点击标签离开 Chat，进入现有回顾分析页，打开包含该栏目的最新已保存报告，并定位、聚焦 `ReflectionBlogPage` 已有的 `echoes`、`traits` 或 `patterns` 栏目按钮。Chat 不增加来源详情、展开、原文查看、加载、失败、重试、确认弹窗或第二个操作。

识别以服务器固定指令 `Complete this Reflections analysis in this turn.` 的最后一次出现为锚，只检查锚点之后的第一个 Markdown 一级标题是否完整等于三个默认工作流标题之一；不扫描锚点之前的 Notion/日记正文，也不按 XML、正文语义或大小猜测。锚点或首个标题不符合规则时保持普通消息渲染。现有消息没有 `task_id/report_id`，所以跳转语义是最新匹配报告，不猜测旧 Thread 对应的精确报告。

本规则只移除匹配消息的 `ChatMarkdown` 和超长 DOM，不减少历史消息的数据库读取、响应字节数或 JSON 解析。完整网络载荷仍是后续可测量风险，不在本轮通过新增接口解决。

桌面骨架：标签在原 user message 的右对齐位置，assistant final 保持原样；不显示空气泡或分析输入卡。

```text
┌ Chat 历史 ───────────┬ 当前会话 ────────────────────────────┐
│ <sessions_context>…  │                         [回顾分析 · 行为模式]
│ 普通对话             │                         （无原始 Analyze 气泡）
│                      │ 分析结果 final…                         │
└──────────────────────┴─────────────────────────────────────────┘

点击 → 现有回顾报告页 → [重复回响] [性格折射] [行为轨迹]
                                                    ↑ 对应栏目
```

375px 窄屏骨架：沿用单列消息滚动，标签空间不足时整体换行；跳转后目标栏目按钮进入视口并获得焦点。

```text
┌ 当前会话 ─────────────────┐
│       [回顾分析 · 行为模式]│
│       （无原始 Analyze 气泡）│
│ 分析结果 final…            │
└────────────────────────────┘

点击 → 回顾报告页的对应栏目按钮
```

### 按需读取与实际来源

用户操作入口和弹窗保持当前布局。“分析内容”显示可按需读取的已挂载页面数量。生成后直接进入原分析进度；已挂载页数表示可读范围，报告中的来源数量表示实际读取情况。报告保存页面标识、标题、链接、正文摘要和读取时间，来源定位沿用现有报告引用。旧报告继续使用当时保存的正文。

报告来源栏显示“日记范围 · N 篇”、已选择的分析 Agent、“Notion · 已读取 N 个页面”。日记数量表示本次分析选择，Notion 数量表示已保存的实际非空来源页数。仅 Notion 的报告显示日记范围 0 篇；日记报告保留日记范围。来源栏位于原返回按钮下方，Notion 标题展开原来源列表。桌面按行排列，窄屏自动换行，来源列表继续在原有高度内滚动。

```text
桌面报告：
┌ [← 历史回顾] ──────────────────────────────────────┐
│ 日记范围 · N 篇  分析 Agent：名称  [▸ Notion · 已读取 M 个页面] │
│ [重复回响] [性格折射] [行为轨迹]                    │
│ 原报告列表 / 详情；各区域沿用原滚动范围              │
└────────────────────────────────────────────────────┘

窄屏报告：
┌ [← 历史回顾] ──────────────┐
│ 日记范围 · N 篇           │
│ 分析 Agent：名称          │
│ [▸ Notion · 已读取 M 个页面] │
│ 展开来源列表：内部纵向滚动 │
│ 原栏目切换 / 列表 / 详情  │
└──────────────────────────┘
```
