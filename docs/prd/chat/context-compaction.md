# 上下文压缩提示

## 背景与问题

Claude Code 在用户发送 `/compact` 时整理当前上下文，也会在自己的上下文条件满足时自动整理。现有 Chat 能显示真实手动压缩的 `Compacted` 完成文字，但忽略 SDK 的压缩状态和边界消息，用户无法知道等待回复期间是否正在整理上下文。

## 目标与边界

在所属回复末尾显示独立、低干扰的状态行，沿用 Codex 参考交互的进行中/完成分隔行。正常回复、工具过程、图片和停止入口保持原有职责。压缩由 Claude Code 执行；本功能只展示它公开报告的状态，不设置触发阈值、不主动请求压缩、不重发模型请求。

正式方案：[上下文压缩交互设计](../../design/claude-agent/context-compaction-interaction.md)。压缩状态技术专项已通过；菜单使用比例已通过技术及正常模型/刷新/取消验证。用户授权重启正常Admin后，真实手动压缩完成、刷新保留和压缩后续聊均已通过，实际菜单从此前9%恢复为压缩后3%。实际自动压缩尚未发生，完整任务仍未完成；证据见[执行记录](../../exec/context-compaction-20261012.md)。

## 概念与规则

- 收到 SDK `status=compacting` 才显示“正在压缩上下文”。不根据等待时长、模型名称、Token 数或用户正文猜测状态。
- 收到实际 `compact_boundary`，并通过其 `compact_metadata.trigger` 判断手动或自动来源。手动完成显示“上下文已压缩”，自动完成显示“上下文已自动压缩”。Claude 的开始状态不携带来源，因此开始阶段使用通用文案；这是与 Codex 原生事件的差异。
- `status=null` 只表示 SDK 已离开压缩状态，不能证明成功。边界到达前显示“未确认上下文压缩完成”，后续边界可更新同一行。
- 失败或取消只终结尚未完成的压缩行。已经确认的边界不因后续回复失败而被改成失败。既有错误和重试入口继续解释整个回复的结果。
- 同一次压缩更新同一行；一次回复内允许真实发生多次压缩。重复事件不增加状态行。切换会话不会带入其他会话的状态。
- 完成或中断状态随所属回复保存，刷新和重开后仍可查看。历史状态行不播放进行中动画。
- 原手动 `Compacted` 文字仍保存在原回复中。只有服务端记录了实际 synthetic 完成文字且已有手动完成边界时，页面用一条状态行展示完成，避免重复；旧历史和普通模型写出的相同文字照常显示。
- 状态行没有新的操作按钮、确认弹窗或设置项。当前停止操作仍取消原回复；本功能不提供第二条控制路径。

### 内置 /compact 提示

- 输入 `/` 或 `/compact` 时，原斜杠指令菜单包含内置 `/compact`，说明为“压缩此聊天的上下文（已使用 42%）”。比例可用时配合小型进度环；缺少实际数据时显示“压缩此聊天的上下文（使用情况暂不可用）”，不显示虚构的 0%。无需安装 Skill，也不依赖 Workspace Mode。
- 比例沿用 Claude 状态栏口径：最近一次主对话模型请求完成时的 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`，除以该 CLI 通过公开 `ResultMessage.model_usage` 报告的实际 `contextWindow`，四舍五入并以 0–100% 展示。它是最近一次请求的上下文快照，不是实时草稿计数、账单额度或自动压缩触发阈值；不包含输出 Token，不累加不同请求和子 Agent 用量。
- 压缩事件使旧快照失效；只有压缩后新的实际请求与对应窗口到达才恢复比例。最新回复缺少数据、运行中、模型更换或尚无回复时显示暂不可用，不借用更早回复或其他会话的数据。
- 选择菜单项只把 `/compact ` 写入原输入框，下一次发送沿既有入口执行；输入、展开或选择提示均不发起模型调用，不增加确认弹窗。保留键盘选择、Escape 关闭及现有 Skill 指令。

## 页面骨架

桌面：

```text
┌──────── 会话栏 ────────┬──────── Chat 消息区：原有纵向滚动 ────────┐
│ 原会话/历史入口        │ 用户输入                                  │
│                       │ 工具过程/助手正文/图片                     │
│                       │ ── 正在压缩上下文 / 上下文已自动压缩 ──    │
│                       │ [既有错误反馈与重试入口，发生失败时显示]   │
│                       ├───────────────────────────────────────────┤
│                       │ 原指令菜单 /compact  已使用 42% [进度环]│
│                       │ 原输入框：/compact 或普通输入 [发送/停止] │
└───────────────────────┴───────────────────────────────────────────┘
```

窄屏：

```text
┌──────── 原会话标题/切换入口 ────────┐
│ 用户输入                           │
│ 助手正文、工具过程、图片            │  消息区独立纵向滚动
│ ── 压缩状态行，长文案可换行 ──     │  不产生横向滚动
│ 原失败反馈及重试                    │
├────────────────────────────────────┤
│ 原指令菜单：/compact               │  说明与使用比例可换行
│ 压缩此聊天的上下文（已使用 42%）   │  菜单内部滚动
│ 原输入框、附件入口 [发送/停止]      │
└──────── 原移动导航 ────────────────┘
```

状态行归属于一个回复，放在该回复末尾，以便流式等待时保持可见。历史折叠工具过程不隐藏状态行。它不是新消息或弹窗，不额外改变滚动容器。

## 验收

| 场景 | 必须观察的结果 | 证据要求 |
|---|---|---|
| 普通对话/工具 | 没有压缩事件时不出现状态行，原回复保持 | 生产链路技术回归 |
| 手动 `/compact` | 真实开始、真实手动边界、唯一完成行；后续对话继续 | 真实 CLI/模型及正常业务记录 |
| 自动压缩 | 实际自动边界和后续生成，页面完成来源准确 | 真实 CLI/模型，不用注入事件替代 |
| 失败/取消 | 不显示完成，不留下持续动画，原恢复入口可用 | 生产链路异常技术验证及实际取消 |
| 重复/延迟事件 | 同一压缩行更新，已完成状态不被旧事件回滚 | 确定性技术验证 |
| 重连/刷新/会话切换 | 回放去重、历史不假装运行、会话隔离 | 公开入口浏览器验证 |
| 桌面/窄屏 | 独立状态行可读、不遮挡输入和停止 | 浏览器布局证据 |
| /compact 菜单 | 最近实际用量比例、进度环、无数据反馈；选择不发送 | 公开入口与原输入组件技术验证 |
| 比例失效与恢复 | 压缩、模型/会话切换不复用旧数值；后续真实请求恢复 | SDK 合同、重连/历史、真实模型回执 |

技术验证、文档检查和真实模型验收分别报告，不能互相替代。
