# deploy/google-cloud/

## 架构概述
Google Cloud Run 脚本目录。frontend image 已使用根 Next.js/pnpm Dockerfile，但前端公开元数据参数与旧 SQLite 数据维护尚未迁移到当前合同，因此脚本存在不等于当前平台已通过发布验收。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| deploy.sh | Google Cloud 发布脚本 | 构建并推送 backend 与 standalone Next.js frontend image，部署 Cloud Run 服务并配置后端 OAuth/cookie/CORS；仍传递被当前 frontend Dockerfile 忽略的 `VITE_PUBLIC_SITE_URL`，不能据此声明前端公开元数据已配置 |
| setup-storage.sh | Google Cloud 存储初始化 | 创建 GCS bucket、服务账号、IAM 授权并输出根目录 `.storage-env`；根路径 `deploy/setup-storage.sh` 仅做兼容委托 |
| sync-data.sh | 历史 SQLite 数据脚本 | 与 Admin-owned PostgreSQL-only schema 合同冲突，不得用于当前 Dream 数据同步、备份或恢复；保留代码只用于后续显式退役或迁移审计 |

## Sync

- 2026-09-06: Google Cloud documentation now records that the Next.js Dockerfile ignores the legacy Vite build argument and that SQLite synchronization is unsupported under the Admin-owned PostgreSQL schema contract.
- Historical, 2026-06-14 Vite path: `deploy.sh` passed the frontend public URL as `VITE_PUBLIC_SITE_URL`; the current Next.js Dockerfile does not consume it.
- 2026-06-15: `deploy.sh` now uses the frontend origin root for `VITE_PUBLIC_SITE_URL`, `INK_PUBLIC_BASE_URL`, and deployment summary URLs.
- 2026-06-23: `deploy.sh` and `sync-data.sh` now preserve production Google OAuth URLs, Secure/SameSite cookie settings, and credentials CORS; `setup-env.sh` stores Google/JWT/session secrets in Secret Manager.
