# 分析任务的时间轴回顾记录

## 背景与问题

用户要的是在 TimelinePage 原有时间轴上放入分析任务对应的回顾记录。上一方案增加了独立报告卡片、历史控制区、顶部留白和窄屏行距，扩大了范围。现行方案撤回这些布局变化。

## 目标与边界

保留 AnalysisView 和 TimelinePage 原有页面结构、尺寸、间距、左右交替、重叠效果、滚动容器和导航。AnalysisView 仍显示最新三份历史，点击原“历史回顾”标题进入现有时间轴。没有历史时保持原分析首页，不添加空态区或占位管理面板。

TimelinePage 只把分析任务对应的已有回顾投影成一条时间轴记录。记录使用原 TimelineCard 的日期、正文区域和图块位置，正文为“历史回顾”，图块显示回顾图标。阅读沿用已有 ReflectionBlogPage，关闭后返回原位置。

不增加回顾管理页面、筛选、工具栏、专用加载更多按钮、栏目数量、摘要面板或确认弹窗。本次不扩展任务状态、持久化写路径、数据库结构或模型调用。

## 概念与规则

| 项目 | 规则 |
| --- | --- |
| 数据 | 使用已有保存的分析任务回顾；不另写一套时间轴数据 |
| 时间 | 任务关联回顾使用服务端 task.created_at；无关联旧回顾使用其记录创建时间；不使用分析范围、更新时间或浏览器现在 |
| 记录身份 | 同一任务的回顾使用已有唯一任务关联；同一天不同任务保留独立记录，重复页按记录 id 去重 |
| 位置 | 按账户时区的创建日期放入现有时间轴，保持较早在上、最新在下及稳定顺序 |
| 原布局 | 100px 条目高度、70px 步长及原重叠效果保持不变；窄屏顶部20px、桌面32px；外壳、宽度、图片大小和左右规则保持原样 |
| 条目呈现 | 复用原 TimelineCard。只增加“历史回顾”和图标，不增加新卡片边框、全文摘要或三栏目计数 |
| 较早记录 | 复用原向上滚动和“Load earlier days”入口；内部查询继续使用已有分页接口，不增加独立历史控件 |
| 失败 | 保留原记录和游标；原较早日期按钮在同位置提供重试，并通过可访问名称与 title 说明读取失败 |
| 阅读 | 点击或键盘激活回顾记录复用已有阅读组件；不创建任务或重复保存回顾 |
| 零记录 | 时间轴继续原来的日记、图片和日期条目，不添加分析空态提示 |

### 桌面骨架

```text
原 Story Workspace 侧栏 | 原 AnalysisView
                        | 原统计
                        | 原“历史回顾”标题（点击进入 TimelinePage）
                        | 原三张历史卡片，原网格与间距
                        | 原生成入口、内容选择与分析栏目

原侧栏 | 原 TimelinePage 的单一滚动容器
       | 原“Load earlier days”按钮（位置、尺寸保持）
       | 原左侧日期/日记/图片条目 ── 中轴
       |                  中轴 ── 历史回顾条目
       | 原左侧/右侧条目继续交替，保持重叠与间距
       | 回顾点击 → 原报告阅读 → 返回原位置
```

### 窄屏骨架

```text
原移动导航与外壳
┌ 原 AnalysisView ─────────────────┐
│ 原统计 / 原历史标题与三张卡片    │
│ 原生成入口和分析栏目             │
└─────────────────────────────────┘
┌ 原 TimelinePage ────────────────┐
│ 原较早日期按钮                  │
│ 原日期、日记或图片条目           │
│ 历史回顾：原文字区域 + 原图块位置│
│ 原100px高度、70px步长和重叠      │
│ 原底部导航、原单一滚动           │
└─────────────────────────────────┘
```
