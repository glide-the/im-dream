# iOS页面验证

| 文件 | 职责 |
| --- | --- |
| `DeckScrollUITests.swift` | 对显式指定的已安装应用执行原预览页只读滑动，以及已有维护表单/内容历史/插件栏目的原生导航；无编辑、消息、模型或业务写入 |
| `prepare-ui-runner.rb` | 使用现有CocoaPods的xcodeproj创建指定临时目录中的独立XCTest UI runner；可选择同目录Swift测试源，默认DeckScroll，生产Xcode工程保持，无依赖安装 |
| `tasks/` | 按业务任务归档系统脚本操作、原文件、脱敏回执和ZIP；[任务索引](tasks/README.md) |

运行由主Agent选择明确候选及设备；测试前确认普通账户页面已就绪。缺少页面时直接失败，不注入账户、业务数据、替代传输或模型。测试只激活既有应用，退出时保留其业务状态；截图/JSON经XCTest attachment保存在本轮私有xcresult。此验证与fixture组件资格、真实模型任务和商店发布分别记录。

## Notion链接技术验证

`NotionLinksUITests.swift`仅作用于显式指定的隔离fixture应用；入口为`../native/notion-links-entry.tsx`，标准内存DTO用于展示原授权控件。验证原组件默认Linking调用、系统默认浏览器、返回与同步失败反馈；原账户、真实授权、正文、数据库、模型及普通产品应用保持。该fixture验证与上方普通账户只读页面验证分别记录。
