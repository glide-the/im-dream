# 对话消息阅读

## 背景与问题

用户反馈长输入占满对话屏幕，Markdown代码出现长空白，最新消息难以到达。来源为[原问题页](https://app.notion.com/p/40b30b7547c380f7ac22f85fdd2dbdd0#40d30b7547c3804a8bbadaedf8408366)，读取日期为2026-11-03。

现行Native页面由页头、消息滚动区、输入区及底部栏目组成；长用户正文缺少收起入口。v3.1规范第6、8、11页定义可见区域、可达操作和独立消息滚动。本文细化上述区域中的消息阅读行为。

## 目标与边界

长用户消息提供预览和完整阅读入口；代码按实际正文占用高度；用户可以阅读历史并返回最新回复。调整范围为Native消息正文、局部代码/表格滚动及消息列表布局响应。桌面Web沿原页面；消息、复制、导出、附件、权限、工具、历史和任务状态由原业务模块所有。后台及进程重开恢复按APP-04暂停状态保留。

## 概念与规则

- **长用户消息**：正文实测高度超过当前预览与展开入口的合计高度，收起后减少屏幕占用。预览连同气泡内展开入口以消息可见区域的一半为布局目标，至少保留一行文字和44pt操作区域。该规则随键盘和可见区域变化，用于展示分配。
- **收起与展开**：长正文初次收起，末尾显示“展开消息”；展开后保留完整正文并显示“收起消息”。操作作用于当前对话、消息及正文段，切换对话后重新测量。短正文直接显示全文。
- **完整内容**：收起只裁剪展示区域。原文本、换行、Markdown、消息标识、复制和导出继续使用完整内容。附件和工具卡片由原独立区域展示。
- **代码与表格**：局部区域按正文实际高度展示；超宽代码和表格可横向滑动。纵向手势交给消息列表，空代码块保持紧凑尺寸。
- **最新位置**：初次打开对话到达最新消息。用户处于底部时，流式正文、异步高度、键盘及可见区域变化继续跟随底部。用户主动上滑后保留阅读位置，原“滚动到底部”入口恢复跟随。展开/收起保持原阅读意图，历史阅读期间不因新回复跳到末尾。
- **操作区域**：输入、Send/Stop和原返回入口保持可达；44pt触摸区域与图标视觉尺寸分别核对。沿现行主题、圆角、字号和页面间距。

## 页面数据缓存与重新进入（2026-11-03）

### 背景与问题

Notion「页面数据缓存」反馈指出 Chat 每次打开等待较久，退出对话后再次进入重新加载。当前调用证据包含三个串行读取阶段：消息、运行状态、空闲后的最新消息复核。原生选择对话会清空正文；网页栏目切换会卸载整个 Chat。

### 目标与边界

首次进入时，成功读到的正文提前显示。当前登录期间，当前对话与前一对话的已读正文可用于再次进入时的阅读预览。发送、工具确认、任务状态及停止继续由当前对话的实际状态决定。账户退出、会话更换和读取权限失效清理对应预览。

App 前后台和进程恢复沿现行流程；APP-04 保持用户暂停。离线保存、离线发送、新业务接口和后端运行策略退出本项范围。

### 概念与规则

| 对象 | 复用与刷新规则 |
| --- | --- |
| 当前 Chat 页面 | 网页首次访问后保留组件、草稿和消息阅读状态；离开时隐藏页面并关闭页面弹层，返回时刷新历史列表、可选卡片结构目录和原对话设置。原生继续复用 App 已持有的页面。 |
| 同一当前对话 | 从历史入口再次选择时保留现有对话、输入和正在进行的响应。显式外部对话交接和失败重试沿原读取流程。 |
| 当前与前一对话的正文 | 仅在当前登录期间保存最近一页已读消息，用于正文预览；重新打开其他未保留运行实例的对话时读取当前内容和状态。预览期间发送不可用，工具操作在状态核对完成后出现。 |
| 历史列表 | 保留已读列表，重新显示时沿原列表读取刷新；新建、发送完成、删除和搜索继续由原入口刷新。 |
| 配置、目录和任务 | 继续由各自页面及设置保存入口刷新。任务运行、工具确认、停止状态、资源权限和输入草稿具有各自所有者。 |
| 写入和删除 | 新消息提交使目标正文预览失效；原确认删除成功后移除目标预览。重新打开通过最新消息读取更新列表及正文。 |
| 失败 | 网络读取失败时保留已读正文，继续显示原失败及重试入口；登录失效、权限拒绝、对话不存在时移除目标正文预览。 |

桌面骨架：

```text
应用导航 | Chat 页面（离开后保留，返回时显示）
         | 对话工具栏：新建 / 活动 / 文件 / 分享
         | 消息阅读区 ↕
         |   首次：等待 → 已读正文预览 → 当前对话
         |   重开：目标正文预览 → 当前对话
         |   读取失败：已读正文 + 原重试入口
         | 工具确认 / 输入区（预览期间等待状态核对）
```

窄屏骨架：

```text
Chat 工具栏
消息阅读区 ↕：目标正文预览 / 当前对话
失败反馈与重试（按原入口）
确认区与输入区（核对完成后可操作）
底部导航：Chat / 卡片结构 / 更多
离开页面：隐藏 Chat，关闭原页面弹层
```

### 原生进行中对话的页面切换

用户在iPhone 0.1.0（32）反馈：进行中的对话重新进入仍出现加载。当前原生页面保留已读正文，切换Thread会关闭原本地流读取；本项补充进行中对话的保留规则。

1. 当前登录与业务页面实例内，进行中的Thread在切换栏目、新建对话或打开其他Thread时保留执行状态、消息与流读取。用户返回该Thread时直接显示最新进度，复用已有连接；未保留实例和失效连接继续原消息/状态恢复流程。
2. Chat页面隐藏时暂停向页面发布状态，后台事件继续处理；返回时一次显示当前状态。其他Thread的事件更新各自记录，当前页面只显示选中的Thread。后台工具确认保留待处理状态，用户进入对应对话后操作。
3. 服务端确认后台Thread空闲后释放其本地运行实例，已读正文沿原当前/前一对话预览规则保存。原输入队列、停止回执与确认接口继续由对应Thread所有。
4. 退出登录、会话范围更换和明确关闭所属业务页面时释放该范围的本地读取；页面切换不发送停止、取消或重复消息提交。iOS AppState前后台与进程恢复继续原流程，APP-04维持暂停。

桌面Web继续采用原保留Chat组件与显式Thread读取规则。原生窄屏沿上方骨架：底部栏目切换隐藏消息区，返回显示保留的进度；历史入口A→B→A在A仍运行时恢复同一运行实例。发送、停止、工具确认与错误重试入口保持原位置，无新增页面或确认步骤。
