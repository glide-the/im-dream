# 对话中的定时任务活动记录

## 背景与问题

ChatMessageList 已在成功的 create_scheduled_task 回执下显示 ScheduledTaskMarkerList，点击后由 ChatView 打开 ScheduledTaskDetailSidebar。任务与进度中的 TaskActivityContent 只读取普通任务会话和子智能体。用户离开创建消息后无法从活动入口找到任务；定时执行会话也缺少返回所属任务详情的入口。

## 目标与边界

创建对话在任务创建成功后显示定时任务记录；每个已关联的执行会话显示发起该会话的任务。点击两处记录都打开现有任务详情。复用现有任务与进度弹层、时钟图标、周期文案和详情面板，不增加确认、调度器或数据库表。

本需求不修改任务创建、调度、运行、工具审批或计费规则，也不把技术验证称为真实模型验收。

## 概念与规则

- 创建记录按数据库的 source_thread_id 归属当前对话，包含 active、paused、exhausted、deleted 状态的定义。尚未发生第一次运行也显示；不依赖当天日期或消息历史是否加载。
- 执行来源按 trigger.target_thread_id 匹配当前会话，并由 Admin 同时校验 Thread、定义、trigger 的用户归属。展示任务当前名称、周期、定义状态和本次执行状态，保持定义状态与执行状态独立。
- 当前会话也可以创建新的定时任务。按任务 ID 合并，来源任务只显示一条，其他创建任务仍显示。普通任务会话和子智能体继续保留。
- 仅有定时任务时也显示任务与进度按钮。完全无活动且查询成功时沿用隐藏规则。查询失败时保留入口与重试，已有同会话记录继续显示；不能把失败视为空列表。
- 任务创建回合结束、打开弹层、页面重新可见和现有活动刷新周期均重新读取关系。切换 Thread 时立即清空旧 Thread 投影，迟到响应不得串入新会话。
- 整行按钮的可访问名称与创建消息保持一致：打开定时任务：任务名称。点击先关闭弹层，再执行同一个 ChatView 详情回调；详情继续与文件、子智能体和普通任务侧栏互斥。
- 任务定义和执行状态以 Admin 返回结果为准，不从助手正文、标题或运行时间推断。周期只格式化已有 once、daily、interval 规则。

## 用户流程与页面骨架

用户创建任务后打开任务与进度，选择定时任务记录，再在现有详情中查看创建对话和执行会话。用户进入执行会话后重复同一流程即可找到任务详情。

桌面：

```text
┌──────────── Chat 当前对话 ────────────┬──── 现有右侧详情 ────┐
│ 顶部工具栏 [新建] [活动] [任务与进度] │ 任务名称 [关闭]       │
│                         ┌────────────┤ 任务信息 / 状态       │
│ 消息流（独立滚动）      │ 定时任务 ▾ │ 创建与执行会话        │
│ 创建消息 [任务标记]     │ 时钟 名称 │ 任务周期 / 下次运行   │
│                        │ 周期 状态 │ （详情自身滚动）      │
│                        │ 本次执行  │                       │
│                        │ 已创建任务│                       │
│                        │ 子智能体  │                       │
│ 输入框                 │ 计划/待办 │                       │
└────────────────────────┴────────────┴───────────────────────┘
```

弹层从顶部任务与进度按钮展开，自身纵向滚动。定时任务位于普通任务与子智能体之前，定时任务和已创建任务可独立折叠。点击记录关闭弹层后显示现有详情，消息流仍属于当前 Thread。

窄屏：

```text
┌──── Chat ─────────────────────┐
│ 顶部 [任务与进度]             │
│ ┌──── 活动弹层（自身滚动） ──┐│
│ │ 定时任务 ▾                 ││
│ │ 时钟 任务名称          ›   ││
│ │ 每隔 N 分钟 · 已暂停       ││
│ │ 本次执行：已完成           ││
│ │ 已创建任务 / 子智能体      ││
│ │ 计划 / 待办                ││
│ └───────────────────────────┘│
│ 消息流（独立滚动）           │
│ 输入框                       │
└──────────────────────────────┘
点击记录 → 关闭弹层 → 现有全宽任务详情
```

沿用当前断点、宽度约束和主题 tokens。名称可省略显示但保留完整 title 与可访问名称；周期允许换行；不得产生页面横向溢出。键盘 Enter/Space 激活记录，Escape 关闭弹层，按钮保留 focus-visible。

## 数据、权限与状态

Admin 拥有 PostgreSQL 定义和 trigger；Dream 只提供同源认证读入口；浏览器不持有 Admin 凭证。新增只读关系投影使用现有已发布 scheduled-task.v2 和链接生命周期 capability，不修改已有 operation hash 或 schema 历史。缺少新 operation 时 fail closed，分区显示读取失败与重试。

| 页面状态 | 用户反馈 | 恢复 |
|---|---|---|
| 加载 | 分区显示加载提示 | 等待当前 Thread 响应 |
| 有记录 | 名称、周期、定义状态；来源记录另列执行状态 | 点击现有详情 |
| 无记录 | 不新增空分区；其他活动维持现状 | 后续刷新 |
| 读取失败 | 保留同 Thread 已读记录并显示重试 | 重新读取 |
| Thread 切换 | 清空旧关系投影 | 读取新 Thread |

## 验收与追踪

| 需求 | 设计 | 实现责任 | 技术验证 |
|---|---|---|---|
| 创建后、历史重开都有记录 | source_thread_id 查询 | Admin read + PlanButton | 未运行任务、历史任务、创建后刷新 |
| 执行会话有来源任务 | target_thread_id 与 owner 校验 | Admin read + TaskActivityContent | 来源 trigger、越权、无关系 |
| 两个入口打开同一详情 | 共享 ChatView 回调 | ChatView + PlanButton | 任务 ID 一致、弹层关闭、侧栏互斥 |
| 仅定时任务也显示按钮 | visible 条件包含关系与失败 | PlanButton | 无计划、待办、普通任务的会话 |
| 状态、失败、切换正确 | 定义与执行状态独立、响应隔离 | DTO + PlanButton | paused/succeeded、失败重试、迟到响应 |
| 桌面和窄屏可用 | 既有卡片布局 | CSS + i18n | Chrome、键盘、无溢出 |
