# Dream Chat 单个 Thread 的用户消息轮次导航 — 页面结构草图

> `html-design-workflow` 阶段 2。结构依据[轮次导航 PRD](./turn-navigation.md)与两张参考截图；截图中的红框、Codex 文字和具体配色不属于 Dream 界面。图中的 A—E 延续 PRD 模块定义，横向比例仅表示相对关系，不作为像素尺寸。

## 桌面／侧边任务会话：默认状态

```text
┌──────────────────────────────────────────────────────────────────────┐
│ A1  现有 Chat 标题与操作                                             │
├──────────────────────────────────────────────────────────────────────┤
│ ┌──────── B1 ───────┐  ┌──────────────────── D1 ───────────────────┐ │
│ │ 用户消息导航轨道  │  │ 当前 Thread 的消息滚动区                    │ │
│ │                  │  │                                            │ │
│ │  ─ B2 第 1 条     │  │  历史消息与回复，沿用现有渲染              │ │
│ │  ━━ 邻近项        │  │                                            │ │
│ │  ━━━ B2 当前项    │  │  ┌───────────── D2 ─────────────┐         │ │
│ │  ━━ 邻近项        │  │  │ 当前定位的用户消息及其后续回复 │         │ │
│ │  ─ B2 第 3 条     │  │  └──────────────────────────────┘         │ │
│ │                  │  │  后续消息                                  │ │
│ └──────────────────┘  └────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────────────┤
│ E1  现有输入 Dock：草稿、附件、发送／停止／排队                       │
└──────────────────────────────────────────────────────────────────────┘
```

`B1` 位于 `D1` 所属的消息阅读区域左缘，与消息列表同高；`E1` 在阅读区域下方。轨道的视觉宽度约 `2.5rem`，短横紧凑排列，不画连接线。`B2` 的操作区域比视觉短横宽。每个 `B2` 仅对应一条当前 Thread 中已发送且可读取的用户消息，按时间顺序排列；刻度数量不从截图推定。长历史中 `B1` 可独立滚动；索引不完整时在轨道说明“仅显示已加载消息”。

## 桌面：悬浮／键盘聚焦某个刻度

```text
┌──────────────────────────────────────────────────────────────────────┐
│ A1  现有 Chat 标题与操作                                             │
├──────────────────────────────────────────────────────────────────────┤
│ ┌──────── B1 ───────┐  ┌──────────────────── D1 ───────────────────┐ │
│ │ 用户消息导航轨道  │  │ 当前 Thread 的消息滚动区                    │ │
│ │  ─ B2            │  │                                            │ │
│ │  ━ B2 聚焦项 ─────┼──┼──▶ ┌──── C1 紧凑摘要 ────────┐              │ │
│ │  ─ B2            │  │    │ 用户输入预览             │              │ │
│ │  ─ B2            │  │    │ 助手结果或当前轮状态     │              │ │
│ │                  │  │    └──────────────────────────┘              │ │
│ └──────────────────┘  │  ┌───────────── D2 ─────────────┐         │ │
│                       │  │ 点击后定位到这条用户消息      │         │ │
│                       │  └──────────────────────────────┘         │ │
│                       └────────────────────────────────────────────┘ │
├──────────────────────────────────────────────────────────────────────┤
│ E1  现有输入 Dock                                                     │
└──────────────────────────────────────────────────────────────────────┘
```

`C1` 的起点贴近 `B2`，向消息区域的可用空间展开。它是指向或聚焦时出现的覆盖层，打开本身不滚动 `D1`；点击 `B2`、Enter 或 Space 才将相应用户消息定位到 `D2`。卡片贴近容器边界时在消息区域内调整位置，不能盖住 `E1`。它仅呈现输入原文的短预览、附件名称，以及该轮可读的助手结果或“正在回复／本轮失败／暂无回复／状态待核对”等状态，不呈现工具流水。

## 约 390px 手机视口：展开式入口

```text
┌────────────────────────────────────┐
│ A1  现有 Chat 标题与操作           │
├────────────────────────────────────┤
│ B1  本对话消息  ▾                  │
│ ┌──────── 展开后的 B1 ───────────┐ │
│ │ B2  第 1 条用户消息             │ │
│ │ C1  用户预览 · 对应回复／状态   │ │
│ │ B2  第 2 条用户消息             │ │
│ │ C1  用户预览 · 对应回复／状态   │ │
│ └────────────────────────────────┘ │
│ ┌─────────── D1 ────────────────┐ │
│ │ 当前 Thread 的消息流          │ │
│ │ D2  选中后定位的用户消息      │ │
│ └────────────────────────────────┘ │
├────────────────────────────────────┤
│ E1  现有输入 Dock                   │
└────────────────────────────────────┘
```

手机上 `B1` 收为消息区内的轻量入口；展开后，`B2` 是按时间排列的用户消息行，`C1` 是行内摘要或选中时展示的摘要。选中 `B2` 后关闭列表并在 `D1` 内定位到 `D2`。展开层避开 `E1` 和现有底部导航，不需要悬浮操作。窄桌面与侧边任务会话若仍有可读空间，继续用桌面轨道，但允许 `C1` 换行并向右下调整。

## 模块索引

| 编号 | 对应 PRD 区块 | 结构与职责 |
| --- | --- | --- |
| A1 | A 顶部 Chat 标题与操作 | 沿用现有页头；本功能不加一级操作。 |
| B1 | B 轮次导航轨道 | 桌面为消息区左缘的细轨道；手机为“本对话消息”展开入口和列表容器。 |
| B2 | B 轮次导航轨道 | 单条用户消息导航项；当前项增强长度／形状并标明当前位置。支持点击及键盘激活。 |
| C1 | C 交互摘要浮层 | 桌面在 `B2` 右侧出现紧凑卡片；手机在展开列表中显示该条消息的摘要。 |
| D1 | D 消息正文 | 当前 Thread 的现有消息滚动容器及渲染路径。 |
| D2 | D 消息正文 | 被选中的用户消息锚点及其后续回复阅读起点。 |
| E1 | E 底部输入 Dock | 沿用现有输入与发送操作；与轨道和摘要互不遮挡。 |

## 结构约束与反馈位置

- `B1`、`D1` 在同一个阅读区域，`E1` 始终位于其下；现有右侧 Thread 历史面板属于外部布局，打开时只缩小本区域可用宽度，不改变模块顺序。
- 导航项来自已发送的用户消息，不包含草稿、未派发队列、工具事件、助手消息和系统注入输入。连续两条用户消息形成两个 `B2`。切换 Thread 后，`B1` 与 `C1` 立即改用新 Thread 数据。
- `C1` 对应的交互范围从当前用户消息开始，到下一条用户消息前结束。没有助手结果时显示实际进行中、失败、暂无回复或待核对状态，不把下一轮回复放入当前卡片。
- 历史仍在读取时，加载反馈放在 `B1`；选择尚未渲染的导航项时，定位进度及失败重试靠近该 `B2`／`C1`，失败后 `D1` 留在原滚动位置。摘要不可用不取消导航能力。
- 没有已发送用户消息时，`B1` 不占位。视觉焦点、读屏名称和当前位置语义附着于 `B2`；Escape 或焦点离开可关闭 `C1`。
