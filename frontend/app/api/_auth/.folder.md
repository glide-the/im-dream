# BFF authentication owner

| File | Pos | Function |
| --- | --- | --- |
| `login-boundary.ts` | Cookie and request boundary | Encrypted original PKCE transaction, relative return, exact origin, opaque handle and HMAC CSRF. |
| `admin-client.ts` | Strict Admin DTO transport | Separate service headers, no retries/redirects, bounded responses, capability/profile identity checks; strict required auth.delegations discovery matches actual Admin DTO. |
| `retired-auth.ts` | Legacy path owner | Shared public Admin authority parsing; 410 standard endpoints, no private credentials/body/forwarding. |
| `handlers.ts` | Product auth handlers | Start/callback/session/logout using actual Admin APIs; success-only cookie changes and original-transaction recovery. |
| `api-proxy.ts` | API credentials | Cookie-presence precedence, exact origin and mutation CSRF; native OAuth Bearer verified by Python, shared unbuffered HTTP/SSE transport. |
| `runtime-request.ts` | Node Apps adapter | Shared BFF credentials/CSRF, cookie/service/actor header removal, preserves opaque Apps session/workspace selectors for existing ownership checks. |
| `*.test.ts` | Technical contracts | Injected clock/config/transport; no real accounts, network or model calls. |

The new `/auth/session` DTO exposes decimal-string user ID, existing profile fields and `csrf_token`. It never exposes access/refresh tokens. Existing Python `/api/me` public projection remains separately owned by its router. Missing credentials return401; origin/CSRF403; invalid/unavailable Admin configuration/DTO503. Callback unknown exchange retains the original cookie for same-transaction recovery; failed revoke retains the same handle. Generic API and Claude SSE use the same credential owner/stream transport. Browser state, explicit MCP Apps adapters and long-turn/tool wiring remain active implementation work, so these route candidates do not prove complete migration or deployment.
