## 背景与问题

用户希望提出图片需求、看到结果，接着修改，之后仍能找到并使用。现有聊天有附件、工具反馈、图片查看和历史会话基础，缺少本次图像生成与编辑的完整体验。把图片仅留在工具详情或返回文件链接，不能满足持续交流的目的。

## 目标与边界

采用现有聊天入口，图片直接显示在回复中，沿用原查看器与会话历史。完整体验为提出需求、获得图片、查看下载、继续修改、重开后继续使用。

本次覆盖文字生成、当前会话参考图编辑、处理反馈、查看下载、会话保存及相关恢复。本轮交付包含对应代码与隔离技术验证；图片真实模型验收尚未执行。正常服务恢复与文字验收见末尾恢复范围。独立创作页面、画布和局部涂抹、图片管理中心、批量制作、跨会话图片引用、实时预览及后台生成不在范围内。

采用现有聊天和Agent执行方式。主对话与独立图片工具均经过Admin Gateway，但用途和图片调用协议不同。用户分别选择AI模型与Image模型，沿用原附件入口，不选择HTTP接口，不在前端填写图像Key。接入边界归正式设计与实施说明；当前安装Codex App的版本对应和界面尚未验证，不承诺逐项复制其体验。

## 概念与规则

- 图片结果直接出现在回复中；编辑产生新图，原图保留。
- 参考图使用当前会话已有图片或原附件入口，用户在原对话中说明要修改的图片。
- 再次生成是新需求，可能产生新的费用；重新加载只读取已有图片。
- 下载保存到用户设备；会话保存保留对话和图片引用。图片可见不代表会话已保存。
- 停止沿用原操作，已完成图片保留；上游工作和费用不保证撤销。
- 失败或断线不自动重复生成；原需求保留在会话中，不自动回填输入框。

## 功能描述

| 功能 | 用户获得的能力 |
|---|---|
| 图片生成 | 用文字描述画面，在聊天回复中获得图片。 |
| 图片编辑 | 指定参考图与修改要求，获得新图并保留原图。 |
| 处理反馈 | 了解需求处理、图片调用、授权、完成、失败和停止的情况。 |
| 查看与下载 | 查看结果，打开现有查看器放大、缩放或下载。 |
| 保存与历史使用 | 重开会话后查看图片，接着提出修改要求。 |
| 失败与恢复 | 看清问题，重新加载已有图或重新发送需求。 |

## 用户入口与完整流程

1. 用户在原输入框描述图片需求，参考图使用原附件入口或会话已有图片。
2. 用户明确要求image_gen时，Agent调用独立图片工具；普通需求仅使用主对话已支持且可调用的内置图片能力。独立工具执行时，原过程区显示“生成图片”或“编辑图片”，沿用原工具执行状态；授权沿用原授权区、批准、拒绝和停止。
3. 完成图片直接出现在回复中。用户打开现有查看器，查看、下载或关闭。
4. 对话与图片引用按原会话方式保存。用户继续修改，获得新图并保留此前结果。
5. 用户离开后重开会话，继续查看图片和提出需求。

生成、解析、文件保存、图片访问、断线、停止和会话保存问题分别反馈。重新加载只读取原图，重新发送才发起新需求；恢复使用原有入口，不新增生成确认弹窗。

## 桌面页面骨架

```text
┌ 现有会话/栏目导航 ┬──────────── 当前聊天 ─────────────┬ 原文件侧栏（按已有设置） ┐
│ 原栏目切换入口   │ 顶部：会话标题与原菜单             │ 当前会话文件             │
│ 原会话列表       │ ┌ 消息独立滚动范围 ─────────────┐ │                          │
│                  │ │ 用户需求与参考图片            │ │                          │
│                  │ │ 原过程区：调用反馈/工具授权    │ │                          │
│                  │ │ 回复：图片结果、查看入口      │ │                          │
│                  │ │ 后续修改与新图片              │ │                          │
│                  │ └─────────────────────────────┘ │                          │
│                  │ 原输入框：附件、输入、发送/停止   │                          │
└──────────────────┴───────────────────────────────────┴──────────────────────────┘
点击图片/放大 → 原共享查看器覆盖聊天 → 关闭回到原位置和焦点
查看器：图片查看区域 + 原缩放/下载/关闭入口
```

栏目切换沿用原导航；图片没有独立栏目。消息区独立滚动，输入区不进入消息滚动范围。授权使用原会话授权区，图片查看器是唯一需要打开的查看弹层，不新增生成确认弹窗。

```text
┌──────────── 当前聊天 ────────────┐
│ 原导航/栏目切换、标题、原菜单    │
│ ┌ 消息独立滚动范围 ───────────┐ │
│ │ 用户需求与参考图片          │ │
│ │ 调用反馈/原工具授权区       │ │

│ └────────────────────────────┘ │
│ 原输入框：附件、输入、发送/停止 │
└────────────────────────────────┘
原文件入口 → 沿用既有侧栏方式
图片/放大入口 → 共享查看器覆盖聊天
查看器保留可达的缩放/下载/关闭；关闭回原位置与焦点
```

图片宽度适应消息区域，不产生横向溢出。窄屏与桌面使用相同操作名称和恢复方式。图片说明、键盘操作及焦点恢复沿用现有可访问性要求。

## 验收要求

- 一段会话中完整完成生成、参考图编辑、查看下载、保存、重开与继续修改。
- 结果直接可见，原图保留，处理与授权反馈符合实际情况。
- 拒绝或授权等待中停止不开始生成，已经完成的图片继续保留。
- 重新加载不触发生成；失败或断线恢复不自动重复提交需求。
- 图片可见但保存失败时有独立反馈，不宣称已保存。
- 桌面、窄屏及受影响的原文本、工具和媒体体验保持可用。

具体场景与验证编号见正式设计。已接入独立Images及主对话内置结果的源码、文件和会话边界；正常服务发布与真实模型验收尚未完成，技术验证与真实业务验收分别记录，不因文档或隔离测试宣称功能已上线。运行实例必须具备Admin图片能力与授权、对应通用delegation合同、图片模型以及持久工作区。
