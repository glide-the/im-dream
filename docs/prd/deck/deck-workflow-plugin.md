# Deck 工作流插件产品需求

## 背景与问题

Ink & Memory 中的 Deck 承载一种思维模式。Dream 类型 Deck 进一步把这种思维模式用于持续创作：用户在同一 Chat 中向 Dream Agent 提出目标、调用创作 Skill，Agent 生成内容，Story Workspace 展示项目、Episode、剧本、分镜和审阅结果。

此前的独立稿把“选择工作流版本”写成了 Deck 工作流插件的全部目的。这个定义过窄：版本选择只是进入工作流前的配置，不能说明工作流如何组织 Dream Agent、创作阶段、工作台内容、审阅和同步失败恢复。

历史稿的另一类问题是把 Voice、Paperclip 任务过程、测试 Harness 和 Claude Agent 运行准备写进产品设计。这些内容不帮助用户完成创作，也不能定义 Deck 工作流插件。

## 目标与边界

Deck 工作流插件是一套带明确版本的 Dream 业务工作流。它定义：

- Dream Agent 可使用的业务 Skill 与创作阶段指引；
- Agent 生成内容与 Dream 工作台内容类型之间的对应关系；
- 项目级共享内容和 Episode 级重复创作；
- 工作流允许的确认点、审阅要求和同步恢复边界；
- 每次 Dream Run 实际使用的工作流名称与版本。

本次范围包括：

- 设置页中现有工作流目录的用途说明、清单和详情；
- 内置 Dream Story Workflow 的创作范围说明；
- Dream 类型 Deck 的工作流版本查看、选择和下一次 Run 生效；
- 工作流包含的业务 Skill、阶段说明和内容类型；
- 工作流对 Project 级共享内容与 Episode 级内容的定义；
- 工作流允许的初次确认和同步恢复规则；
- 工作流来源与版本追踪。

本次不包括：

- Claude Code Plugins 的清单选择；
- Deck 工作流插件的创建、编辑、审核、发布和下架后台；
- 远程 Marketplace；
- Voice 会话、Paperclip 任务、测试 Harness 和运行环境准备；
- 工作流画布、节点编排或脚本编辑器；
- 把阶段指引实现为强制步骤、审批流或新的任务状态机；
- 尚未实现的渲染、配音、后期和宣发功能。

Dream 首页、Run 重入、同一 Chat、初稿/同步、Project/Episode 页面、内容版本和失败反馈由 [Dream 工作台独立 PRD](../dream-workspace/dream-workspace.md)负责。本稿不再重复定义工作台页面。

## 概念与规则

### Deck 工作流插件

Deck 工作流插件是 Dream 类型 Deck 使用的版本化业务工作流。它定义创作目的、可用 Skill、工作台内容结构、用户确认点、同步反馈和恢复方式。它不是 Claude Code Plugin，也不是独立运行进程。

### 工作流版本与 Run

- Dream 类型 Deck 保存一个用于后续新 Run 的明确工作流版本。
- 新 Run 开始时记录该版本，之后不随 Deck 的配置变化而改变。
- 工作流版本变化只影响之后新建的 Run，不改变正在执行和已经完成的 Run。
- 当前版本不可用于新 Run 时，页面保留原版本信息，不自动替换成其他版本。
- 工作流版本可映射到其执行所需的 Claude Code Plugin，但该映射由系统处理，不成为用户维护第二类工作流的入口。

### Dream Story Workflow

Dream Story Workflow 是内置的短剧创作工作流，属于 Deck 工作流插件。它把用户的创作目标连接到项目准备和分集创作，并把 Agent 生成的内容呈现在 Dream 工作台。

| 功能模块 | 功能描述 |
| --- | --- |
| 项目准备 | 建立 Project 和分集计划，整理各集共用的角色卡与场景卡。 |
| 分集创作 | 为每个 Episode 生成剧本、分镜、Prompt 和审阅结果，支持继续修订与重新生成。 |
| 持续协作 | 在同一 Chat 与 Dream Agent 协作，按需要调用或重复创作 Skill。 |
| 内容展示 | 在 Dream 工作台按 Project 和 Episode 展示生成内容。 |

首次创作从 `/drama-init` 开始。后续 Skill 没有固定调用顺序。渲染、配音、后期和宣发尚未开放。

“Dream Story Workflow”是一个具体工作流的名称；“Deck 工作流插件”是它所属的功能范围。Claude Code Plugins 是 Deck 创建或维护时选择的插件清单，使用独立入口与设计。

### 设置目录的职责

`StoryWorkspaceSettingsPage` 的工作设置中，`PluginAdminPage` 显示工作流目录；相邻 `ClaudePluginAdminPage` 保持独立。工作流区域没有插件类型切换，不把执行依赖显示为另一类插件，也不给执行依赖提供管理操作。

目录展示服务端返回的工作流名称、版本、来源、状态和已有授权维护动作。普通用户查看清单和详情；管理员可继续使用现有安装与维护入口。本次不新增安装流程、发布规则或 Marketplace 平台；工作流版本的 Deck 选择仍在 Deck 维护侧栏完成。

### 创作阶段

短剧工作流使用三段创作指引。指引用来说明创作范围，不限制用户在初始化后的 Skill 调用顺序。

| 阶段 | 功能描述 | 当前边界 |
| --- | --- | --- |
| 跨集准备 | 建立项目、分集计划、角色卡和场景卡，供后续 Episode 复用。 | 当前可用。 |
| 分集创作 | 为每个 Episode 生成剧本、分镜、Prompt 和审阅结果。 | 当前可用，可按 Episode 重复。 |
| 成片制作 | 渲染、配音、后期和宣发。 | 仅作方向说明，当前不可执行。 |

首次启动默认使用 `/drama-init` 建立项目。初始化完成后，用户可以按创作需要调用或重复已安装的 Skill；页面不得把阶段指引解释为代码强制的下一步。

### 与 Dream 工作台的关系

- 工作流定义项目级与 Episode 级内容的用途，不定义工作台页面布局。
- 工作流可以声明一次项目初稿确认，不扩展为每个阶段的审批。
- 工作流可以声明允许一次自动修正的同步问题范围，不拥有 Chat 消息、SSE 或页面恢复实现。
- Dream 工作台按照 Run 记录的工作流名称和版本解释内容，但页面交互以其独立 PRD 和正式设计为准。

### 配置状态

| 状态 | 含义 |
| --- | --- |
| default | 新建 Dream 类型 Deck 使用的服务端默认工作流。 |
| desired | 用户已经选择、尚未保存的工作流版本。 |
| effective | 服务端最后确认保存、下一次新 Run 将使用的工作流版本。 |
| revision | 工作流选择每次有效变化后的版本号，用于识别其他页面已经修改同一 Deck。 |

## 功能描述

| 功能模块 | 功能描述 |
| --- | --- |
| 工作流版本 | 展示并选择 Dream 类型 Deck 用于后续新 Run 的工作流版本。 |
| 创作阶段指引 | 说明跨集准备、分集创作和暂未开放的成片制作范围。 |
| Skill 范围 | 说明工作流提供的创作能力和适用内容。 |
| 内容结构 | 说明项目级共享内容与 Episode 级内容的业务归属。 |
| 确认边界 | 说明工作流允许的一次项目初稿确认。 |
| 同步恢复边界 | 说明工作流允许自动修正的问题范围和次数。 |
| 工作流来源 | 展示本次 Run 使用的工作流名称和版本。 |

## 状态与失败反馈

| 场景 | 页面反馈 | 恢复方式 |
| --- | --- | --- |
| 工作流目录初次读取失败 | 显示目录暂不可用和失败原因。 | 点击重试，重新读取清单。 |
| 工作流目录刷新失败 | 保留上次成功清单，显示刷新失败。 | 点击重试。 |
| 工作流详情读取失败 | 保留所选工作流信息，在详情中显示读取失败。 | 在详情内重试，不创建其他插件对象。 |
| 未选择工作流 | 说明 Dream Run 尚无可用工作流。 | 选择可用版本。 |
| 工作流版本不可用 | 保留名称和版本，说明不能用于新 Run。 | 重新读取并选择可用版本。 |
| 版本保存冲突 | 说明其他页面已经修改工作流选择。 | 读取最新 revision 后重新确认。 |
| 保存结果无法确认 | 不显示成功，说明需要重新读取 effective。 | 重新读取，不自动重复提交。 |

## 影响范围

- 设置页 `PluginAdminPage`、清单、详情、状态和错误反馈；
- 前端工作流 API 与查询状态：删除独立运行时分类、联合类型、依赖清单投影及对应渲染分支；
- Deck 维护弹窗中的版本记录侧栏和工作流版本选择弹窗；
- Dream Run 创建时记录工作流来源的连接；
- Dream 工作台读取工作流名称和版本的连接；
- 现有“运行插件”“运行版本”等文案的后续统一。

工作流发布后台与远程 Marketplace 仍为空白范围。本 PRD 不用界面占位或技术描述补齐它们。

## 验收条件

- 设置页明确说明 Dream Story Workflow 是内置短剧工作流，展示项目准备、分集创作和制作范围。
- 工作流区域没有第二插件分类、执行依赖卡片或依赖详情入口；相邻 Claude Code Plugins 保持独立。
- 清单和详情读取失败均有重试，目录刷新失败保留上次清单，窄屏没有横向溢出。
- 用户能够理解 Deck 工作流插件组织的是 Dream 创作过程，而不只是版本选择。
- Deck 维护页与当前代码容器关系一致，工作流入口位于版本记录侧栏。
- 每次 Dream Run 显示实际使用的工作流名称和版本。
- 阶段指引明确区分跨集内容、分集内容和尚未实现的制作方向。
- 初始化后的 Skill 可以按创作需要调用和重复，页面不制造强制步骤状态机。
- 工作流只定义工作台所需的内容、确认和恢复边界，不复制工作台页面规则。
- Dream 工作台的页面、Episode、内容版本和失败恢复验收由其独立 PRD 负责。
- 页面不出现 Voice、Paperclip、测试 Harness、运行环境准备或含糊抽象标签。
- Claude Code Plugins、工作流发布后台和远程 Marketplace 没有被扩展进本需求。

以上是产品与文档验收标准。程序变更并完成对应业务流程验证前，不得宣称功能已按本文实现。
