# frontend/src/components/deck — Folder Contract

## Architecture Summary

Deck-specific presentation components. Server DTOs and mutations remain in `frontend/src/api/`, while the parent
`DeckManager.tsx` owns loading and action orchestration. Components in this folder must not invent Deck revision,
ownership, or capability facts.

## File Table

| File | Pos | Function |
|---|---|---|
| `DeckChatSelector.tsx` | Deck/Agent selector UI | Select a Deck and Agent only before a new conversation is fixed. |
| `DeckManagerPanels.tsx` | Deck home/management presentation | Render published-clean shortcuts, Available/System launcher groups, static system defaults, and the Work full inventory, switches, More menu, and related-Chat cleanup dialog. |
| `DeckManagerPanels.css` | Deck launch/management styles | Apply Ink & Memory tokens to complete spaced launch icons, static system rows/cards, Work rows, same-DOM narrow layouts, focus, reduced motion, and 44px targets. |
| `DeckVersionPanel.tsx` | folded content-version history | Render immutable Deck vN as the primary timeline and runtime binding history as a secondary disclosure. |
| `DeckVersionSubmitDialog.tsx` | explicit commit confirmation | Present server diff/source/target/impact and create vN only after confirmation. |
| `DeckPluginVersionPicker.tsx` | exact-version confirmation | Select a server-adjudicated exact version and explain next-run scope and conflicts. |
| `DeckPluginVersionCard.tsx` | version option row | Present exact semver, current/release state, compatibility, and recovery facts. |
