# backend/services/story_workspace — Folder Contract

## Architecture Summary

Server-owned Story Workspace application and infrastructure services. The folder resolves actor-scoped Dream launch/re-entry authority, validates immutable workflow provenance, projects canonical artifacts, and integrates successful Agent turns without adding a second Chat transport or runtime schema path.

## Key Constraints

- [Sync] 2026-09-01: an automatic repair Turn receives stale project roots only
  after the Hook reloads the authoritative Run and immutable launch message;
  changed actor/thread/run/Deck/plugin facts fail closed before Runner deletion
  capability assembly.
- [Sync] 2026-09-01: project-root repair messages persist allowlisted relative
  trusted/stale paths; missing or issue-inconsistent cleanup facts fail closed.
- [Sync] 2026-09-01: Episode public-text scanning distinguishes canonical
  workspace-relative references and prose range tildes from absolute paths or
  secrets; compact character refs and one-dialogue objects project safely.
- [Sync] 2026-09-01: `PROJECT_STORY_SLUG_MISMATCH`, duplicate canonical project roots, duplicate stage entity IDs, and workspace-derived stage schema failures are Agent-repairable through fixed templates. Validation runs before stage/private projection writes and cleanup requires move/merge rather than copy-only. Launch actor/workspace/thread/run/Deck/Agent/binding/runtime/plugin authority, database/CAS, permission, private `.dream` corruption, and infrastructure failures remain non-repairable. The service persists one normal user row before SSE, uses one deterministic message/claim, never edits trusted launch metadata or creates schema, and never starts a third Turn.
- [Sync] 2026-08-31: Dream launch metadata preserves the original Agent as immutable provenance and fingerprint input. `chat_thread.voice_id` is the mutable same-Deck next-turn Agent and supplies the effective Agent for later turns; changing it must not hide re-entry rows or create a binding conflict.
- Binding validation remains actor-scoped and fail closed for ambiguous retry leaves, malformed metadata, authorization drift, immutable Deck/revision changes, and top-level/nested launch-provenance disagreement.
- Binding failures happen before Runtime/model execution and must not create a ghost Run, duplicate message, or settlement side effect.
- PostgreSQL schema remains Admin Drizzle-owned; this folder must not add runtime DDL, Alembic, or SQLite production fallbacks.
