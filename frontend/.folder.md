# frontend/

## 架构概述
React 19 + Next.js 16 + TypeScript Web Shell。`frontend/` 是唯一 Node workspace、Web package 和 Next project root；`app/**` 是唯一 App Router 与应用源码 owner，`app/_dream/**` 是不可路由的 Dream 模块树。容器启动时生成 runtime-config，以保持现有跨域后端请求与 WebSocket 行为。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| Dockerfile | 容器构建 | 多阶段 Node 22 + frozen pnpm lock 构建并运行根 standalone Next Web Shell；不保留 npm/Vite 双路径 |
| nginx.conf.template | 历史回滚模板 | 不再由默认 Next image 消费；仅属于一个外部具名且已验证的 immutable Vite 回滚镜像 |
| docker-entrypoint.sh | 容器入口 | 渲染 `public/runtime-config.js`，注入 `API_BASE_URL` / `WS_BASE_URL`，然后启动 standalone `server.js` |
| .gitignore | 版本控制边界 | 排除依赖、日志和构建产物，包含 Next `.next/`；不删除本地生成文件 |
| .dockerignore | 构建优化 | 排除 node_modules、dist、.env 等 |
| package.json | 根 Web package | 默认 `dev/build/start` 均从 `frontend/` 运行 Next，pnpm workspace/lock 是唯一依赖安装合同 |
| eslint.config.js | 源码 lint 边界 | 校验 TypeScript/React 源码，并排除 `dist`、`.next` 与 Playwright `test-results` 生成物 |
| pnpm-workspace.yaml | workspace owner | 只声明根 `.` 与同级 `packages/*` |
| next.config.js | 构建配置 | 唯一根 Next 配置；保留 runtime-config cache 与本机同源 Python API/auth/OAuth fallback，并仅在受控 Docker build 中输出 standalone |
| next-env.d.ts、tsconfig.json | TypeScript owner | 唯一根 Next/TypeScript 配置；`@/*` 只解析到 `app/*`，生产 build 执行严格类型门禁并排除私有模块树内的测试 |
| app/ | App Router 与应用源码 | 唯一 layout、client boundary、catch-all 页面、公开 Route Handler，以及私有不可路由的 `_dream/` 应用模块树 |
| packages/ | Node workspace packages | 包含 MCP Apps 的唯一 server-only Runtime owner；Browser/RSC 不得导入其入口，依赖统一由根 pnpm workspace/lock 管理 |
| public/ | 公共资源 | 字体/图片、Story Workspace 创作阶段指引插图，以及 runtime-config 模板与默认配置 |
| e2e/ | 浏览器验收 | Playwright 业务旅程；包含隔离注册/模型链路，以及 Chat-first、Claude MCP Resources、三入口导航、剧本默认 Deck、默认插件与刷新持久化的 provider-free 可见流程 |
