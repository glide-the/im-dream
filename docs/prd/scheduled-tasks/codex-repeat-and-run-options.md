# 定时任务：Codex 风格周期与高级运行选项 PRD

## 1. 背景与问题

现有定时任务已经能持久化一次、每天和固定分钟间隔计划，并通过现有 Task、Thread、Turn、事件流与 Claude Agent 入口执行。当前编辑弹窗仍把数据库规则直接展示成“一次 / 每天 / 间隔”，用户无法按 Codex.app 的“每小时、每天、工作日、每周、自定义”方式选择周期，也不能控制每次触发是否创建新聊天，或固定执行模型。

本次在既有任务系统上补齐这三项配置。保存、暂停、恢复、删除、立即运行、运行历史、自动笔记工具策略和异常恢复继续沿用现有语义。

## 2. 目标与边界

### 2.1 目标

- 重复菜单固定提供“每小时、每天、工作日、每周、自定义”。
- “高级日程”承接时间、星期、分钟间隔、一次性日期与 IANA 时区。
- “高级”折叠区只增加“每次运行时都开启新聊天”和“模型”。
- 新建任务默认复用创建任务的源 Thread；用户开启开关后，每个 trigger 创建独立 Thread。
- 模型从当前用户可调用目录中选择，随 definition revision 保存，并在 trigger 领取时快照。
- 桌面与窄屏都明确滚动范围、二级弹层、错误反馈和焦点返回。

### 2.2 边界

- 不增加项目、推理强度、成功记录归档、结束次数、节假日/调休或月份规则。
- 不向用户暴露或要求输入原始 RRULE；页面只提交受限结构，服务端生成规范化规则。
- 不增加第二套 Task、Thread、Run、消息、事件或调度系统。
- 不改变定时会话自动笔记工具白名单；模型选择不扩大工具权限。
- 不在 Dream 运行时建表。共享 PostgreSQL schema 和 capability 只由 Admin Drizzle 管理。

## 3. 概念与规则

### 3.1 配置状态

| 概念 | 定义 |
|---|---|
| default | 新建表单初始值：新聊天开关关闭，模型为创建任务当前选择的可调用模型；周期来自用户请求。 |
| desired | 用户在编辑弹窗尚未保存的完整草稿。关闭二级编辑器只恢复进入该编辑器前的 desired。 |
| effective | Admin 事务成功提交并完整返回的任务 definition；调度器只消费 effective。 |
| revision | effective 的正整数版本；周期、Thread 模式、模型、标题或提示词保存后均递增。 |

已领取 trigger 保存 definition revision、Thread 模式和模型 alias 快照。后续编辑只影响新 trigger。

### 3.2 重复菜单

| 菜单项 | 产品语义 | 高级日程字段 |
|---|---|---|
| 每小时 | 每个自然小时的 `00` 分，在任务时区运行 | IANA 时区 |
| 每天 | 每个当地日的指定时间运行 | 本地时间、IANA 时区 |
| 工作日 | 任务时区的周一至周五，在指定时间运行 | 本地时间、IANA 时区 |
| 每周 | 每周在一个指定星期和时间运行 | 星期、本地时间、IANA 时区 |
| 自定义 | 一次性日期、每隔 N 分钟/小时，或多个星期组合 | 规则类型及其条件字段、IANA 时区 |

规则要求：

- 每小时规范化为 `FREQ=HOURLY;INTERVAL=1;BYMINUTE=0`。
- 每 10 分钟等间隔规范化为 `FREQ=MINUTELY;INTERVAL=10`；正安全整数由服务端校验。
- 每天、工作日、每周和自定义星期组合按当地日历计算，不能换算为固定分钟数。
- 工作日固定为周一至周五，不推断法定节假日或调休。
- 页面和 Tool 只提交 `once`、`interval`、`daily`、`hourly`、`weekly` 结构化规则。Admin 是 canonical RRULE 的唯一生成与解析方；前端和 Dream 不实现 serializer。
- Admin 内部受限规则只允许 `MINUTELY`、`HOURLY`、`DAILY`、`WEEKLY` 及 `INTERVAL`、`BYDAY`、`BYHOUR`、`BYMINUTE`；未知字段或非法组合保存失败。
- 一次性任务继续存在，在“自定义 → 一次”中编辑。
- 夏令时缺失时刻跳过；重复时刻沿用现有 daily 选择规则。页面展示服务端返回的 `next_run_at`，不自行推算。
- 进程恢复后错过多个触发点时只创建最近一个到期 trigger；更早范围记录为 skipped，不回放风暴。

### 3.3 每次运行时都开启新聊天

持久化枚举：

```text
run_thread_mode = source_thread | new_thread_each_run
```

| 开关 | 执行行为 | 结果入口 |
|---|---|---|
| 关闭（新建默认） | 把 scheduled turn 追加到创建任务时服务端捕获的 `source_thread_id` | 打开源聊天并定位本次 turn |
| 开启 | 每次 trigger 通过现有 TaskSession/Thread 入口创建独立聊天 | 打开该 trigger 的 `target_thread_id` |

- prompt、浏览器参数、最近打开聊天不能改写 `source_thread_id`。
- 源 Thread 正在运行普通 turn 时，最终提交仍经过现有 ThreadFactory 的 per-thread 原子 admission：可安全排队则串行执行；明确拒绝时，本次 trigger 失败并显示可行动原因。不得静默切换为新 Thread。
- 删除源聊天沿用现有外键级联语义，同时删除其定时任务和运行历史；不保留失去所有者的任务。
- 创建新 Thread 失败时也不得回退到源 Thread。
- 同一 source Thread 同时只能有一个 open 定时 trigger。多个任务同时到期时，第一个进入 open 状态，其他任务各自产生 `failed/SCHEDULE_SOURCE_THREAD_BUSY` 历史并推进本次计划，不因唯一约束异常进入热循环。
- 存量任务保持原有 `new_thread_each_run`，避免迁移改变既有行为。

### 3.4 模型

- 下拉数据复用现有 Admin Gateway 模型目录，只显示当前用户 `enabled=true`、`callable=true` 且包含在可用范围的 alias。
- 主文案显示模型名称；保存精确 `modelAlias`，不保存“自动”“默认”等动态占位符。
- 新建任务预选当前 Chat 已解析的模型；Tool 创建时由服务端捕获，prompt 不能伪造。
- 已保存 alias 后续不可用时仍展示原值并标记“不可用”；不得静默替换为目录默认模型。
- v3 新建与编辑必须提交精确 alias；trigger 领取时快照 alias。执行入口按当前用户身份重新做模型与权限校验。失败只影响本次 trigger，任务保持原状态并按计划继续。
- 存量 v1/v2 definition 的 alias 可以为 null，继续沿用原先“执行时解析当前默认模型”的兼容语义；页面明确显示“存量任务未固定模型”。用户第一次用 v3 保存该任务时必须选择精确 alias，之后所有 trigger 都使用快照语义。

## 4. 用户交互流程

1. 用户在 Chat 要求创建周期任务，或从 Calendar 打开已有任务编辑。
2. 创建工具按自然语言产生受限规则；服务端捕获源 Thread、当前模型和 Editor 目标。
3. Chat 显示任务标记卡。点击后在右侧详情展示任务信息、Conversations 和任务周期。
4. 用户点编辑，在“重复”选择五类周期；“高级日程”编辑具体时间、星期或间隔。
5. 用户展开“高级”，选择是否每次新建聊天以及执行模型。
6. 保存提交完整 desired 和 expected revision；成功回执整体替换页面 effective。
7. 到期后，调度器领取 trigger 并使用已快照 Thread 模式与模型执行。
8. 用户从详情或历史打开本次结果；复用模式打开源聊天，新建模式打开独立聊天。

## 5. 页面骨架

### 5.1 桌面编辑弹窗

```text
┌────────────────────────── 编辑任务 ────────────────────────── [×] ┐
│ 任务标题 / 提示词                                               │
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │ 多行任务内容                                                 │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │ 重复                                      工作日         [⌄] │ │
│ ├─────────────────────────────────────────────────────────────┤ │
│ │ 高级日程                    周一至周五 · 09:00       编辑规则 │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ 高级 [⌃]                                                       │
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │ 每次运行时都开启新聊天                              [开关]  │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │ 模型                                      GPT-5.6 Sol    [⌄] │ │
│ └─────────────────────────────────────────────────────────────┘ │
│ 行内错误 / revision 冲突 / next run 摘要                        │
├────────────────────────────────────────────────────────────────┤
│                                           [暂停/恢复]   [保存]  │
└────────────────────────────────────────────────────────────────┘
```

标题栏和底部操作固定，中间正文为唯一滚动区。重复菜单从重复行展开；高级日程使用二级 dialog。二级 dialog 只更新 desired，主弹窗“保存”才持久化。

### 5.2 桌面详情与 Chat

```text
┌──────────────── Chat（独立滚动） ───────────────┬──────── 任务详情（独立滚动） ────────┐
│ assistant 结果                                  │ [时钟] 任务标题               [关闭] │
│ ┌ [时钟] 周报 · 每周一 09:00          [打开] ┐ │ 状态 / 下次运行                       │
│ └────────────────────────────────────────────┘ │ 任务信息：标题、提示词、模型           │
│                                                 │ Conversations                         │
│ 输入区固定                                      │ 最近结果 / 历史        [打开聊天]      │
│                                                 │ 任务周期：每周 / 周一 / 09:00 / 时区  │
└─────────────────────────────────────────────────┴───────────────────────────────────────┘
```

任务标记展示任务，不以 Conversations 列表替代任务。详情的 Conversations 展示每次执行会话；复用源 Thread 时多次 trigger 可以指向同一聊天，但各自保留 turn 和结果记录。

### 5.3 窄屏 sheet

```text
┌────────────── 编辑任务（全高 sheet） ──────────────┐
│ [返回]                 编辑任务              [关闭] │  固定
├────────────────────────────────────────────────────┤
│ 标题 / 提示词                                      │
│ [重复：每周                              ⌄]        │
│ [高级日程：周一 · 09:00             编辑规则]      │
│ 高级 [⌃]                                           │
│ [每次运行时都开启新聊天                  开关]      │
│ [模型                              GPT-5.6 Sol ⌄]  │
│ 错误与 next run 摘要                               │  唯一滚动
├────────────────────────────────────────────────────┤
│                              [暂停/恢复] [保存]     │  固定
└────────────────────────────────────────────────────┘
```

重复、模型和高级日程在窄屏均使用 bottom sheet；关闭后焦点返回触发行。底部安全区不得遮挡操作。

## 6. 状态与失败反馈

| 情况 | 页面行为 |
|---|---|
| 模型目录加载 | 模型行显示局部 loading；其他 desired 保持可编辑。 |
| 模型目录失败 | 保留已保存 alias，显示“模型列表暂不可用”和重试。 |
| revision 冲突 | 保留 desired，展示最新 effective 与冲突字段，用户重新保存。 |
| 同源 open 定时 trigger 冲突 | 新 trigger 记录失败并推进计划；详情显示原因和“打开原聊天”。 |
| 普通 turn 与定时 turn 竞争 | 由 ThreadFactory 原子锁串行或明确拒绝；拒绝时 trigger 失败，已持久化输入仍由 trigger 关联。 |
| 模型不可调用 | trigger 失败；展示失效 alias 和“编辑模型”。 |
| capability 缺失 | 整个定时任务区 fail closed，显示“定时任务暂不可用”和重试。 |
| `state_unknown` | 不重复执行；按现有恢复逻辑查询持久化终态。 |

暂停、恢复、删除只影响尚未领取的 trigger。进行中的 trigger 按领取快照结束。

## 7. 验收标准

- 创建和编辑可选择五项重复菜单，页面不要求输入 RRULE。
- 每小时、每天、工作日、每周、自定义一分钟间隔与一次性规则均得到正确 `next_run_at`。
- 关闭新聊天开关后，定时 turn 写入源 Thread；开启后每个 trigger 得到独立 Thread。
- 同源 Thread 不产生并发定时 turn；失败不静默切换模式。
- 模型选择保存到 revision 并在 trigger 快照；模型失效不自动替换。
- 编辑 revision、暂停、恢复、删除、立即运行、历史、重启恢复保持原有行为。
- 普通 Chat、resume、cancel、SSE、TaskSession 和自动笔记工具策略回归通过。
- PRD 骨架、正式设计 Mermaid、接口实现和 E2E 追踪矩阵一致。

## 8. 非目标与后续事项

- 推理强度、项目选择和归档策略另行设计。
- 月度、节假日、结束次数与通用 cron 文本不进入本次能力。
- 若未来支持多个 source Thread 或跨项目运行，需要新的业务需求和权限设计，不能扩展当前字段猜测实现。
