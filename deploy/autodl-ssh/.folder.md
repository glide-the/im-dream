## 必须保留的安全边界

- Dream 只消费 Admin DTO API；部署器把同一个注册 service identity 投给 FastAPI 与 server-only Next BFF，并单独投影 BFF cookie secret。Dream 不持有 PostgreSQL 凭据，也不执行 SQL、migration、runtime DDL、备份或恢复。
- Dream workspace、Notion credential、Artifact、本地文件、plugin Runtime 与 service home 必须位于显式数据根，拒绝符号链接并保持既有 owner/group/mode。
- 历史 AutoDL 外层容器固定 `INK_AGENT_SANDBOX_ENABLED=false`；这意味着 approved Bash 以 Dream root 身份运行且没有 bubblewrap 文件系统或网络隔离。迁移不得隐去或自动改变该事实。
- 发布、启动、停止和回滚只能影响本目录明确命名并拥有的 Dream release、process 和 link，不能替换未知进程或修改 Admin 数据。
- Claude Runtime、Node MCP Apps、内置 Skill catalog、默认 Deck Plugin、crawler routes 与 rollback 都必须在 Next.js release 形状上验证。
- `AUTODL_PREBUILT_FRONTEND_ARCHIVE` 只跳过目标机的 pnpm install/build；目标机必须校验 SHA-256，并继续创建 backend venv、打包候选、隔离冒烟、原子切换及公网验证。
- 独立启动器没有用户 access token，因此不调用需要 `dream:read` 的 `deck.default-plugin.resolve`。它只验证持久目录内每个内容寻址插件制品的目录名、digest 与可解析路径；用户默认 Deck 仍由正常请求流程通过 Admin 解析。
- 部署器在替换 `dream.env` 和标记 qualified 前必须确认 `INK_GATEWAY_SERVICE_KEY` 对应 Admin 当前 active canonical-subject key；失效 key 必须阻断发布。
