# 移动端异步启动与开发者页 PRD

当前名称规则见[应用名称需求](app-brand.md)。默认展示Kastention，中文本地化应用称谓使用卡片结构。

本次任务的产品设计集中在本文。页面骨架见[启动页](#启动页)和[开发者页](#开发者页)；操作时序、状态和生命周期见[独立交互设计](../../design/multi-platform/mobile-startup-interaction.md)。

## 背景与问题

用户希望Python异步启动，前端在准备期间可见，并能查看最简运行状态。当前后台启动路径直接复用；首次登录与业务操作继续等待原依赖。

## 目标与边界

新增状态展示和入口已接入源码：复用现有异步启动、原准备页面和同一个只读开发者页。原登录、权限、输入、任务和恢复规则保持。技术回归和模拟器专项回执归[专项评审](../../exec/mobile-startup-design-review-20261101.md#模拟器验证2026-11-01)。此前模拟器验证复用原Native/运行资源；新增原始错误日志已通过技术与模拟器验证，回执归专项评审。构建24已覆盖安装至原iPhone并普通启动，物理页面与完整业务验收待执行。

启动性能优化、重启、停止、清理、终端和自动修复保持各自任务范围。开发者页的CPU与活动观察按下方专项定义。普通Web沿原页面，桌面骨架作为宽屏布局参照。

## 概念与规则

1. 打开应用先显示原框架和准备反馈；后台启动完成后检查原会话，再显示原登录或业务导航。开发者入口在准备、未登录及错误视图均可达。
2. 登录后沿“更多 → 设置 → 关于 → 开发者控制页”进入同一页。返回保留原页面实例、输入和已有任务；会话失效与进程重开沿原恢复规则。
3. 页面显示原启动调用保存的启动中、就绪或失败、总耗时、更新时间和启动错误码。原会话读取结果单独展示；公网连接显示“未单独观测”。总耗时在启动返回后显示，准备中显示尚未完成。
4. 错误日志显示本次应用中启动、登录会话、配置读取及Agent目录各来源最近一次错误的时间、来源和原文。原始错误信息、错误码、路径和堆栈直接展示，复制保留相同原文。读取恢复后保留最近错误，当前运行状态单独显示；进程重开清空本次记录。
5. 刷新只重读已有状态；复制诊断摘要在原位置显示结果。离页释放观察，后台暂停，前台重读。记录范围为原调用返回的错误，页面仅读取本次记录。
6. 启动失败沿原边界提示重开应用；原登录、配置与历史失败继续各自读取重试。准备期间业务操作按原条件等待，自动业务重发为零。
7. iOS应用图标使用用户第一张参考图的高清方形稿，保留黑色笑脸与浅米色纸张。开屏角色采用透明矢量，只保留轮廓、五官和蓝白帽子，脸部与外围透出当前主背景；角色四周无矩形背景或容器边框。开屏与屏保共用[v4.2角色时钟](../Kastention-时钟交互规范-v4.2.md)：开屏显示开心表情，屏保将同一脸型作为表盘，显示离散跳针、发丝及当日已知心情。线稿随深浅色主题显示，减少动态效果时取消形变并直接更新时间。
8. 品牌区由角色和现有手写字体的Kastention组成，位于页面中部偏上；准备状态与开发者入口位于底部安全区，保留独立触控范围。窄屏和横屏缩小角色，角色、名称与底部反馈保持间距。角色隐藏、后台及开发者页打开时暂停自有动效和计时。图标与系统启动资源本次接入iOS，Android系统资源及设备显示继续单独交付。
9. 每次冷启动和从后台重新进入App，开屏至少显示一秒。只累计前台可见时间，准备页进入开发者页或登录窗口遮挡时暂停，返回后补足剩余时长；后台返回重新计时。短暂系统窗口引起的inactive沿当前周期继续。原服务和会话准备并行执行；一秒完成且原页面已具备展示条件后显示原页面，准备仍在进行时保留准备反馈。
10. 再次进入的开屏覆盖已有页面，底层草稿、选择、任务和页面实例保持。覆盖期间业务页面关闭触控与无障碍入口；开发者页继续可达。开屏结束恢复当前页面，业务重发和额外运行库初始化为零。

## 验收

### CPU与任务活动观察

背景与问题：用户使用App时感到手机发热，需要看到处理器占用随时间变化，并判断同一时间有哪些运行活动。当前启动总耗时和错误日志提供调用结果，CPU与活动通过本节新增真实采样展示。

目标与边界：在原开发者控制页内观察整个App进程CPU、可测OS线程排行、原命令实例CPU及原请求活动。业务任务使用共享执行线程时显示共享或未归因。系统热状态按原状态展示，摄氏温度和发热原因保持未测量。原页面、诊断入口、登录、权限及任务控制保持原行为。

概念与规则：

1. 打开控制台且页面处于前台时开始采样。暂停保留当前图表；恢复先建立新基线。离开可见页面、切后台或关闭后停止采样，业务运行实例继续原生命周期。
2. CPU趋势来自App进程累计用户态与内核态CPU时间的区间增量；100%表示占满一核，多核并行可超过100%。设备核数归一化另行标注。WebKit独立进程和GPU退出该进程计量范围。
3. 线程排行使用同一OS线程的连续计数。主线程与Node/RN的共享线程标明共享。新建、已结束或无法读取线程的CPU保持未归因。业务Thread ID与OS线程ID分别显示其各自含义。
4. 命令活动复用原命令实例标识、代次与宿主OS线程映射；CPU值仅对应该主执行线程，子线程保持未归因。原请求活动复用请求标识和等待/读取状态，等待状态只说明活动，不分配CPU比例。原启动状态以活动条带同步观察。
5. 图表同时呈现App CPU趋势、可测线程的趋势和排行，以及采样时观察到的活动条带。条带使用实际观察点，CPU缺失或暂停处保留断点。任务持续时间、网络等待和内存数据退出CPU换算。
6. 默认每次读取完成后间隔2秒；内存最多保留120点及采样期间最近4分钟。该参数属于采样开销预算，界面展示采用实际采样区间。图表仅保留有界观察，不持久化正文、凭据或采样历史。
7. 首个样本显示等待连续样本；无样本、能力不足、读取失败、后台暂停和手动暂停分别反馈。读取失败保留旧图表及其原时间，下一次成功先建立基线。
8. 系统热状态显示正常、略高、较高、严重或未知。采样自身原生耗时、采样线程CPU和桥接往返独立展示；图表渲染的CPU包含在App总量内。物理能耗和发热原因按实际设备证据确认。

账号入口失败时，用户关闭原登录窗口后可在现有开发者控制页查看最近一次登录、注册或Google错误及时间。取消授权继续原返回行为。刷新与复制读取当前记录，错误恢复后保留最近记录至进程退出；页面入口、骨架和启动状态保持。

## 登录后开发者入口与App弹窗（2026-11-02）

### 背景与问题

原开发者入口位于准备页或关于页。用户登录后打开业务页面或弹窗时，需要继续访问同一控制页和已有错误日志。

### 目标与边界

登录后提供App内浮动入口，复用已有开发者页。业务页面、输入和弹窗保持原实例，账户、登录和启动流程沿原规则。系统权限窗口和第三方认证页面的展示由系统所有。

### 概念与规则

- 已登录或原生登录展示期间显示同一个浮动按钮。准备、未登录及错误页保留原内联入口。
- 默认位于安全区右上，可拖动到安全区内其他位置；键盘打开时进入键盘上方可用区域，提供对应无障碍位置操作。
- 收起时仅按钮区域接收触摸，其他触摸沿原页面处理；原滚动、键盘及返回行为保持。
- 点击进入原开发者页，展示同一运行状态与日志，沿原刷新和复制操作。打开时结束当前输入焦点，业务内容和原弹窗继续保留。
- 返回只关闭诊断内容并回到原业务。退出登录、会话丢失或离开所属场景时撤销浮动入口。
- 深浅色和系统主题沿当前项目配色；输入恢复错误与其他原错误在同一日志列表展示。
