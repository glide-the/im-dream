# backend/mobile_runtime

## Architecture Summary

This package is the only Python entry intended for an embedded mobile interpreter. Importing it performs no service startup, Admin authentication, worker creation, CLI resolution, subprocess launch, database operation, or network request.

The iOS entry loads the original backend `.env` before original Python configuration consumers. The package validates bridge envelopes and reports Python-owned qualification facts for the interpreter, local transport, and Claude Runtime. Callers inject the target artifact version, embedded-build, native-extension, import-smoke, and module receipts. The Native host owns the composite snapshot and reports technical runtime and file integration facts; the existing web BFF owns authentication. Claude remains unavailable until a mobile target receives qualified artifact and protocol evidence.

The original Dream confirmation coordinator receives the existing Admin worker during iOS startup. Explicit confirmation requests schedule only their exact persisted message ID using original claim, lease, persistence and acknowledgement contracts. iOS does not start the coordinator's global reconciliation scan. Global worker recovery ownership remains a separate qualification item.

## Boundaries

- Do not import `backend.server` or `backend.agent_factory` from this package.
- Do not infer mobile support from a desktop or Linux package.
- Configuration remains private to the original Node/Python consumers; never return credentials through startup facts, bridge replies or React APIs. Current local env packaging requires a distribution credential review before external release.
- Do not infer the target interpreter version from the host process or claim ownership of Native authorization/file facts.
- The iOS composition root mounts shared public routes through `create_public_router`; the full server startup graph remains separate. React business transport requires the original authenticated routers, DTOs and execution ownership.
