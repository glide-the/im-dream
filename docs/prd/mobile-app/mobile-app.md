## 概念与规则

### React Native原生界面目标

移动主界面使用React Native原生组件，导航为Chat、Decks、More。首页、More、快捷操作与应用内链接均不提供工作台创建或审核确认入口。原Chat中的既有消息、结果和附件按原权限读取；本轮不新增Dream工作台原生页面。

Web继续通过Next.js发布。可移植的RN视图经React Native Web逐步共用，现有网页保持可使用；编辑器、系统文件选择等必要差异分别适配。工作台创建与审核确认保留原Web页面，退出跨端视图迁移范围。

打开App后显示准备状态，本地后端就绪后检查原会话。启动失败显示原因及重试。切换页面、退出登录和进入后台均不等于停止后端或取消任务。再次进入先读取原状态与历史；用户停止任务仍使用原停止操作。系统结束App后重新装配运行实例，读取原记录。

正式业务图见[RN交互稿](../../design/multi-platform/react-native-web-project-structure.md)，实例所有权见[运行时架构](../../design/multi-platform/mobile-runtime-architecture.md#实例所有权与生命周期)。原网页登录保留AuthEntry与原BFF；Cookie接入原生HTTP存储、HTTP增量与文件URI适配单独验收。

### 正常网页登录

使用现有`AuthEntry`：邮箱、密码、注册、Google入口和原错误信息保持一致。表单action由现有`/auth/options`返回；原Admin验证凭证，原Next BFF处理OAuth callback、会话Cookie和CSRF。取消、失败、过期和退出按照现有页面与接口处理。

会话检查或登录入口读取失败时，原错误区域显示`Try again`。用户恢复网络后点击，页面重新加载并读取已有会话与登录入口；未提交表单内容重置，密码登录继续由用户提交原表单。凭证校验失败保留原输入与错误反馈，用户修改后提交。

登录文档允许原网页表单和HTTPS导航。成功后本机BFF会话接入平台HTTP存储，RN读取原公开会话与CSRF。账号密码由原网页处理，禁止进入bridge、安装资源、普通日志或测试源码。设备码登录退出范围。

iOS独立路径由应用内原Next加载同一份React与原网页登录；原form、Cookie、callback和BFF协议保持。此前Mac relay联调已在iOS Simulator应用宿主完成正常密码登录与一次Chat，该历史回执保留Mac业务执行位置。当前独立路径已接入原配置，应用内原Next的登录动作读取返回200；原账号登录、端侧Python权限传递和真实任务分别验收。失败继续显示原页面反馈。

原生Chat首次读取配置失败时保留当前页面，发送与快捷操作暂不可用，原错误区提供重试。成功读取过的数据在刷新失败时保留；重试保留当前对话、草稿与附件。恢复读取完成后继续原操作，读取重试不发起新消息或停止已有任务。

### 原任务与数据

发送、队列、停止和恢复由[Chat Send](../Chat%20Send.md)、[队列输入](../chat/queued-input.md)及原业务实现定义。客户端前后台、网络和渲染进程变化属于页面状态；这些事件不创建新Run状态、不确认任务成功或取消、不自动重新提交内容。

正文逐步显示，消息内容保持完整。用户点击停止后显示处理中；停止已受理且任务继续收尾时保持“Stopping”，查询确认结束后恢复发送。停止已受理引起的当前读取关闭沿原状态查询恢复，页面保留当前消息。网络断开且结果待核实时继续原错误反馈和重试，恢复操作不重新发送消息。完整交互及生命周期见[现行停止收尾设计](../../design/multi-platform/react-native-web-project-structure.md#停止回执后的独立读取恢复)。

排队消息保留原调整方向、删除、编辑和侧边聊天操作。编辑失败时展示保留稿及原重试入口；用户可先检查队列状态。同一对话保持打开时，切到后台再返回保留已编辑草稿和重试反馈；离开对话后恢复区随原页面结束。窄屏侧边聊天使用全宽弹层，源对话和输入稿保持；关闭后回到源对话，已创建任务继续按原规则运行。当前Native实现及独立验收范围归统一工程设计和执行记录。

活动铃铛打开原最近Chat、今日定时任务及日期历史。搜索、显示来源、刷新、关闭和历史删除保留原入口；移动端工作台来源隐藏。选择定时任务进入只读详情，显示原任务信息、执行模型、规则及源/执行对话，点击对话返回对应Chat。打开面板保留底层输入和附件；关闭返回原对话。失败按来源显示原重试，切后台暂停读取，回到前台读取当前快照，任务执行状态保持原规则。

返回应用时读取现有状态和历史；缺少本机执行记录时使用原恢复错误。容器不增加自动改绑Thread、替代Agent、离线数据库、双向同步、后台常驻、后台落库或新的任务调度。

既有WebView中，已保存确认消息的恢复、原内容与权限保持原实现，见[iOS恢复设计](../../design/multi-platform/mobile-ios-interaction.md#已保存dream确认的进程重开恢复)。该流程退出RN移动适配与本轮验收。

### 页面与平台交互

移动导航为Chat、Decks、More及既有Settings入口，视觉沿用现有主题。窄屏适配区域尺寸、滚动和键盘可见性。iOS顶部操作位于系统安全区内，Settings搜索聚焦后保持页面尺寸。消息区纵向滚动，代码/表格在自身区域横滚，输入区增高后内部滚动；键盘打开时发送/停止可见，关闭键盘恢复原阅读位置。

iOS状态栏与底部手势区使用当前页面主背景色，跟随现有浅色、暗色和系统主题设置。状态栏文字与手势指示条保持可读；内容仍避开系统安全区，键盘打开时保留原输入与主操作可见性。主题变化只更新外观。

Chat切换到Decks、More，或打开覆盖输入区的面板时收起编辑键盘；草稿、附件、当前对话与任务保留。返回Chat后展示原草稿，由用户点击输入区重新聚焦。局部编辑器加载完成时采用当前页面可见状态，隐藏页面保持失焦。正常/异常时序与状态图归[输入焦点设计](../../design/multi-platform/react-native-web-project-structure.md#持久输入文档与软件键盘焦点)。

iOS保留原页面返回和系统弹窗关闭；Android返回先处理键盘和当前弹窗，再按原页面历史返回。网页授权与外链使用原链接目的地；远程网页无法调用本地bridge。加载、空内容、失败和重试复用原页面反馈，容器错误单独处理。

## 用户业务旅程

安装 → 打开Dream原生应用 → 准备本地后端 → 原网页登录 → 原callback与会话读取 → 原生工作区 → 范围内核心任务与结果 → 原退出 → 再次打开读取原会话与历史。

## 消息中的图表

### 背景与问题

现有Web消息支持Mermaid图表的预览、源码、复制、放大与PNG导出。移动端阅读同一消息时需要保留这些操作，普通文字、代码和输入区继续沿当前页面。

### 目标与边界

用户阅读消息中的图表，切换源码、复制完整Markdown图表、放大查看并保存PNG。图表不发起对话、工具调用或新任务；打开、关闭和切换图表保留当前对话与草稿。完整交互和平台资格见[正式设计](../../design/multi-platform/react-native-web-project-structure.md#mermaid图表的平台适配)。

### 概念与规则

- 默认显示可渲染图表。输出尚未形成有效图表时显示源码；后续内容形成有效图表后恢复预览。
- “源码”保留完整图表文字；复制包含Mermaid代码围栏。普通代码保留代码展示。
- “放大”打开图表预览，支持原缩放操作；关闭后返回原消息位置，保留对话和输入内容。
- “导出PNG”由用户发起。移动端打开系统文件导出界面，取消导出返回图表。图表内容变化或离开消息时释放尚未交付的临时图片。
- 图表加载失败显示重试入口，重试读取当前图表内容。原消息和当前任务状态保持。

桌面页面骨架：

```text
Chat页面
├─ 消息滚动区
│  ├─ 普通正文/普通代码
│  └─ 图表 [预览 | 源码] [复制] [放大] [导出PNG]
│     └─ 图表或源码区域
├─ 原输入区与发送/停止
└─ 放大 → 原图表预览弹窗 [关闭] [导出PNG] [缩小/当前比例/放大]
```

窄屏页面骨架：

```text
Chat / 原对话
├─ 消息滚动区
│  ├─ 普通正文/代码
│  └─ 图表操作栏与图表/源码
├─ 原输入区
└─ 放大 → 独立全屏预览
   ├─ 安全区 / 关闭
   ├─ 图表预览与原工具栏
   └─ 原缩放控件；关闭回到原消息
```

## 写作排版与心情入口

### 背景与问题

手机写作需要更紧凑的正文行距、随文字排版对齐的稿纸线，以及能够完整触摸访问的心情选择内容。当前心情入口在正文首行，端侧已有写作导航栏可承载当前心情。本文产品规则已接入最小源码实现；正式交互、源码依据和平台差异见[写作移动布局设计](../../design/multi-platform/writing-mobile-layout.md)，[评审与验收计划](../../exec/writing-mobile-layout-review-20261101.md)分别记录交付状态。

### 目标与边界

用户从原“更多 → 写作”进入，在同一页面编辑、保存及恢复。保留当前字体、稿纸色彩、写作工具、手动建议、会话日期及心情选项。心情选择仍由原会话与偏好恢复结果触发，自动出现频次继续沿用当前规则；账户首次使用、每日计数及新的跳过规则退出本轮范围。桌面Web保持当前可用布局、行距与正文心情入口。登录、权限与原保存接口保持。

### 概念与规则

1. 移动正文保持18px默认字号，行高采用有效字号的1.6倍，默认28.8px；桌面继续18px、1.8倍。字体、浏览器文字放大及可用宽度改变时，输入、高亮和稿纸线一起重新排版；字号取样用于验收，字号设置退出范围。
2. 横线属于稿纸背景，每一段正文的横线按实际行框下沿重复，段落首线分别对齐。用户换行保持原文；连续正文段落不补空行，建议和对话卡片沿原间距。字体加载中继续使用原后备字体，完成后保留文字、光标与阅读位置；加载失败仍可写作。
3. 原生心情入口位于既有“返回更多 / 写作”导航栏右侧；Web窄屏采用同样的本页导航关系。入口显示原图标和当前名称，长名称省略并提供完整辅助功能名称。无选择显示“选择心情”，读取中显示加载占位并禁用。正文日期及标签保留并允许换行，正文移除重复的心情入口和专用空白槽。
4. 原Calendar、新建和Agent三个工具保持同组与原动作，在导航栏下方留出操作区域；心情入口、工具和正文互不覆盖。返回更多仍进入原五项菜单，不增加全局导航入口。
5. 心情展开占本页编辑内容区域，页头返回仍可见。问候、完整立方体及说明共同纵向滚动；短内容居中，长内容从顶部排布。实际可用高度随横竖屏、安全区和键盘变化，所有原可选项均可滚动触达。纵向拖动只滚动，抬手后不误选。
6. 点击原已解锁选项沿现有反馈与淡出提交，随后返回同一写作页并显示当前心情。选项承担确认动作，原选择器内部无独立确认或关闭按钮，本轮保持该规则。取消通过所属页返回更多，保留已选心情和草稿；重进时按原恢复结果显示正文或自动展开。尚未提交的淡出回调随页面退出取消，已经提交的原保存继续执行。
7. 打开心情前收起正文键盘；返回写作不自动聚焦。正文编辑时光标与末段可滚到键盘上方。原生宿主与网页内容分别处理所属安全区，避免重复留白。系统文字放大在原生编辑文档中的实际效果分别进行iOS与Android验收。
8. 心情保存失败时保留当前选择，在原反馈区域显示失败与重试。重试只保存同一选择的偏好；本地显示变化与服务端保存结果分别反馈。写作会话、局部文档加载失败重试和登录过期继续原恢复流程。

## 写作记录与关联对话

### 背景与问题

用户反馈端侧打开不同写作记录后，进入关联对话的体验存在差异。本轮根据现有Web入口与实现整理规则，设备故障阶段继续采证。普通时间线日期卡展示图片、评论和报告；打开指定写作记录使用写作页日历中的日记入口。

### 目标与边界

保留“更多 → 写作 → 日历 → 选择记录 → 卡片Chat入口”的既有操作。用户主动点击卡片后打开准确的关联对话；单纯选择记录只更新编辑内容。当前修复让移动端原卡片入口直接可点，并在发送前保存和核对对应笔记。草稿、任务、登录和权限继续沿原规则执行，设备采用与源码交付分别验收。

### 概念与规则

1. 一份写作记录可含多个对话卡片，每个卡片打开其已经关联的对话。不同记录允许复用既有Voice对话。手动写作建议使用其原记录关联，建议卡与对话卡分别按已有入口操作。
2. 原对话不存在于当前卡片时，保持原编辑和创建入口；折叠卡片及缺少关联的卡片均不渲染Chat按钮。移动展开卡片直接显示同一按钮并允许单次触摸打开，桌面保留原悬停方式。原卡片、对话关系和所在位置保持，新增全页“对应对话”按钮及时间线跳转退出本轮范围。
3. 桌面Web保留写作与Chat分栏。端侧使用已有侧会话，关闭后返回原写作；底层主Chat的未发送稿保留。侧会话关闭及Web面板关闭后的组件内未发送稿沿当前释放规则，跨关闭或跨对话的稿件恢复退出本轮范围。
4. 返回记录A恢复其已保存正文、卡片和引用；进入记录B后，只有点击B中的卡片才打开该卡片的对话。已有任务继续按原状态运行，打开、关闭和重试读取均不停止任务、不重新发送消息。
5. 读取失败显示原反馈并提供当前入口已有的重试操作；登录失效进入原登录恢复。网络恢复后重新读取同一记录或对话，旧读取结果按原身份校验处理。额外确认和后台同步服务退出本轮范围。
6. 从写作卡片打开的对话，每次发送前使用该笔记当前已保存内容；保存失败、笔记已切换或页面失效时保留输入并反馈本次准备失败，用户返回写作核对后可再次发送。原重新读取操作不重复发送消息。侧会话中改选其他对话或新建聊天后，发送沿该对话自己的原规则执行。

## 前后台与进程重开恢复（2026-11-02）

### 背景与问题

用户在手机前台启动Agent任务后，希望切到其他应用或锁屏时继续计算，需要语音输出时再播放。Agent在手机本机运行，联网模型及数据访问沿原业务；再次打开需要恢复原对话、未发送输入和已保存结果。

### 目标与边界

iOS与Android分别支持其系统允许的后台计算和按需播放，Web沿用原运行方式。首要目标为同一次任务继续计算，音频资源就绪后开始播放。有限后台时间只覆盖其实际允许的区间，持续计算目标须独立验收。

系统拒绝、时间到期或进程结束时，按原记录核实任务并保留输入。长期空闲常驻、跨进程自动续跑、自动重发、离线消息数据库和跨设备同步退出范围。

### 概念与规则

- 用户发送一次任务，应用在工作开始时申请后台运行能力；进入后台无需重复确认。iOS合格持续任务显示系统进度和取消入口，其他任务依当前系统能力运行；Android合格后台工作显示任务通知和返回对话入口。
- 当前iOS后台执行适配、Android本机运行与后台适配、两端按需语音播放均有待完成；实施状态与证据归独立执行记录。
- 计算期间保持原任务和真实进展。原任务要求语音且内容就绪时，应用在可执行且平台允许的条件下开始播放。语音暂停、结束和失败分别反馈，原任务结果由实际计算及保存确认。
- 任务完成后释放计算占用的后台资源，实际播放可继续到结束。用户播放控制只控制音频，原任务停止按钮继续控制计算。
- 系统拒绝后台能力时保留前台任务；系统收回能力后尽快结束对应任务，保留已保存结果。系统挂起期间暂停本地计算，运行进程结束会结束对应本机执行。
- 返回前台读取同一对话和原结果；重新打开先验证账户，再恢复已选对话、已保存消息、独立草稿和已上传附件。未完成上传提示重新选择。
- 主对话与侧对话分别保存输入。写作关联上下文尚未就绪时保留发送保护和返回写作入口；关闭、导航或改选后退出旧侧对话恢复。
- 网络失败保留原输入与读取重试。恢复只读取，自动重发和自动上传次数为零；旧响应保持原对话归属，账户切换保持数据隔离。

#### 应用内静态动画与iOS活跃Thread组件（源码候选）

用户需要在离开应用后查看当前账户在本机有无活跃Thread，并通过组件返回应用。使用Kastention现有图标，显示固定栏目“活跃 Thread”和二值“有／无”；多个活跃Thread汇总为一张组件。活跃沿原任务运行状态定义，等待工具确认或停止收尾期间仍按原运行状态计算。页面隐藏、流读取关闭及系统暂停CPU调度均保持任务原状态。

组件按最近一次确认显示：至少一条原任务仍运行时为“有”；完整核实本机当前账户的运行任务均已结束时为“无”。只打开某个对话的页面、未来定时任务、已结束历史和单独音频播放均不增加活跃Thread。网络失败、状态读取失败或系统挂起保留最近确认值，展示固定说明“最近确认”；首次状态尚未取得时保持组件未展示。状态选项始终只有“有”和“无”。

iOS使用锁屏／灵动岛Live Activity承载本轮活动入口。原任务在前台启动时准备组件，切到后台前同步已知值；最后一条任务结束时以“无”结束本轮组件，由系统决定保留与移除。未创建活动时使用应用原入口。点击组件启动应用，经原登录和恢复流程进入Chat；恢复只读取，自动重发为零。账户退出或更换时清理原账户组件。系统移除组件只影响展示，任务继续沿原执行规则。

App内增加无操作时的屏保静态动画层：已登录业务页面在前台连续25秒没有用户操作时，在原页面上方显示Kastention时钟／表情画面和同一“活跃 Thread：有／无”；底层页面虚化并保留原位置、草稿和任务。触摸、滚动、键盘输入及实际页面操作重新计时；任务输出和网络回执保持原计时。键盘或编辑焦点、工具确认、未关闭弹窗及系统选择器存在时延后出现。点击任意位置只关闭屏保并重新计时，关闭这一触摸不触发底层发送、删除或导航。

屏保与启动页共用[v4.2一体化角色时钟](../Kastention-时钟交互规范-v4.2.md)，原脸型直接承载三根离散指针。屏保视觉依据[v3.1界面规范](../Kastention-App-UI-Guidelines-v3.1.pdf)第3、5–7页：整页主题色与虚化背景，角色、字标及状态通过留白分组；内容区域透明，无面板边线、圆角底板与阴影。字标沿原开屏24／32字号行高，状态使用次级文本色，关闭提示位于底部安全区域；原时钟笔迹保持。

屏保动画采用来源页的时钟／心情视觉：时钟按实际时间逐秒读时；秒针逐秒6°、分针逐分6°、时针逐时30°离散推进；表情只读使用当日笔记中可确认的开心／悲伤，缺少对应心情时默认开心。屏保整层点击统一关闭。前台无操作只控制显示，原任务继续原执行路径，系统挂起仍服从APP-04。App进入后台时移除屏保并停止其动效，iOS系统组件继续显示最近确认值；返回前台恢复原页面并重新计时。系统组件仅使用静态图标及二值状态。

两处入口共用活跃Thread口径和Kastention视觉资源。状态尚未取得时，应用内保留画面并省略状态行，系统组件保持未展示；状态选项始终只有有／无。该需求随APP-04设计维护，后台执行资格、应用内显示和系统组件分别验收。桌面Widget、Android新增系统组件和Web改版保持原范围。正式交互、状态图和验收见[双入口组件设计](../../design/multi-platform/mobile-recovery-interaction.md#应用内静态动画与系统组件2026-11-03)。

## 回顾分析失败反馈与原提交恢复（2026-11-02）

### 背景与问题

用户截图显示回顾页仍可查看历史报告，分析启动失败提示在页面中重复出现，恢复上次提交的操作含义需要明确。当前截图缺少任务和请求状态，首次提交失败原因继续按实际请求证据定位。

### 目标与边界

保留原分析来源、Agent、时间范围、任务、报告和权限。以原入口恢复上次提交，避免因重试重复创建分析。任务错误在一个区域显示，相同文案只显示一次；新增任务系统和Admin架构调整退出本轮范围。

### 概念与规则

- 没有待恢复提交时显示原生成入口。存在上次未确认或已创建提交时，主按钮显示“恢复上次分析”，说明继续使用上次提交的分析内容。
- 恢复先处理原提交及其任务状态。原任务已运行或结束时读取原进度和结果；已准备、尚未运行的任务沿原显式继续规则操作。需要创建恢复时沿用原请求身份及原输入。
- 明确未获接受的提交显示原失败，允许用户检查所选内容。结果尚未确认时保留原提交，禁止自动重新发起一份分析。
- 分析错误集中展示并按完整文案去重；不同原因保留各自信息。历史读取、报告保存及其重试保持所属区域。
- 分析完成后报告任务信息读取失败时，保留同一任务的“重试保存”入口，恢复原报告，不重新调用模型。
- 统计和日记候选日期采用页面传入的账户时区，偏好到达后刷新统计，迟到的旧统计退出当前展示；历史与运行任务保持原观察。

## iOS对话工具与Notion正文读取（APP-07）

### 背景与问题

用户在对话中搜索工作区文件和读取已选Notion页面。反馈截图显示工具执行失败及页面正文读取暂不可用，页面轻索引已有结果。用户需要原对话完成搜索和正文读取，并按实际失败原因恢复。

### 目标与边界

保留原对话、工具审批、停止、结果复制及历史重开。搜索、命令和读取由原工具完成；Notion沿现有连接和已选范围提供实时正文。新增工具、授权方式、确认窗和资源范围变更为0。物理iPhone构建29继续供用户手动测试，APP-04保持暂停。

### 概念与规则

1. 工具卡片显示原工具名称、输入、执行状态及结果。命令失败保留原错误，停止沿原会话终止执行。再次发起由用户在原对话明确操作。
2. Notion连接成功表示授权记录可用；页面轻索引表示选定范围内的标题等信息可读。页面搜索和正文读取分别使用实际任务结果确认可用状态。读取失败保留原索引、原资源选择及对话。
3. 授权过期沿“更多→设置→资源链接→Notion”重新连接；资源权限不足沿原页面授权恢复；命令暂不可用沿原反馈重试。用户无需管理平台二进制或目录。
4. 重开历史读取已保存的工具结果和回复；再次读取正文沿当前连接与已选范围校验。旧失败记录保留。
