## 3. 任务目标

端到端验证 Agent 产出 → 页面渲染 → 用户审阅确认的完整工作流。包括：Agent 生成数据后前端正确展示、审阅状态标记正确、确认/驳回/编辑后确认操作完整、批量审阅可用、状态流转正确。

---

## 4. 实现步骤

1. **准备联调环境**
   - 确认前端所有组件已完成（FE-001 ~ FE-006）
   - 确认后端 API 已实现（BE-002, BE-003）
   - 确认共享类型包已对齐（SH-002）

2. **数据流验证**
   - 模拟 Agent 生成数据存入后端
   - 验证 Dashboard 显示「N 项待审阅」
   - 验证故事列表中新生成项左侧显示 Memory Yellow 竖条

3. **审阅流程验证**
   - 点击待审阅行 → 右侧 Review Panel 正确展示 Agent 生成内容
   - 点击「确认通过」→ 状态变为 confirmed → Toast「已确认」→ 表格刷新
   - 点击「驳回」→ 填写修改意见 → 状态变为 rejected → Toast「已驳回」→ 行变红色标记
   - 编辑模式：修改字段 → 「保存并确认」→ 状态 confirmed

4. **批量审阅验证**
   - 多选待审阅项 → Toolbar 替换为批量操作栏
   - 批量确认/驳回 → 确认弹窗 → 操作完成 → 表格刷新

5. **筛选排序分页验证**
   - 按审阅状态筛选后表格正确刷新
   - 按生成时间/标题排序正确
   - 切换页码正确加载数据

6. **空态错误态验证**
   - 无数据时正确显示空态引导
   - API 失败时正确显示错误提示

7. **Agent 生成时序验证**
   - 验证 Agent 生成中状态的 Loading 指示
   - 验证数据推送后前端实时刷新（轮询机制）

## 8. 测试策略

1. **端到端场景测试**：
   - 完整工作流：Agent 生成 → 页面展示 → 审阅确认
   - 边界场景：无数据、大量数据、网络中断

2. **API 契约验证**：
   - 请求/响应格式与共享类型一致
   - 错误码处理正确

3. **状态流转验证**：
   - pending → confirmed
   - pending → rejected
   - confirmed 后不可再次确认
   - rejected 后重新生成 → pending

4. **性能验证**：
   - 表格加载 < 2s
   - 审阅操作响应 < 1s
   - 分页切换 < 1s

5. **联调方式**：
   - 前端职责：审阅面板 UI、审阅操作交互、状态展示、表格刷新
   - 后端职责：审阅状态流转 API、数据持久化、批量操作
   - 建议轮询机制实现实时刷新（本期不建议 WebSocket）

### 明确排除项
- **复杂画布**：E2E 验证不涉及画布渲染正确性、图形操作验证、Canvas 性能测试等
- **视频**：E2E 验证不涉及视频播放流程、视频审阅流程、视频上传/处理等
- **移动端**：E2E 验证仅在桌面端（≥1280px）执行，不涉及移动端浏览器测试、响应式布局验证、触摸交互测试
- **用户手动创建内容**：E2E 验证的完整工作流为「Agent 生成 → 页面展示 → 用户审阅确认」，不包含「用户手动创建 → 页面展示」的验证路径
- **性能压测**：不涉及负载测试、压力测试、并发用户测试等性能测试（仅验证单用户响应时间目标）
- **安全测试**：不涉及 XSS、CSRF、SQL 注入、权限绕过等安全测试（另开 Issue）
- **跨浏览器测试**：E2E 验证以 Chrome/Chromium 为主，不涉及 Safari、Firefox、Edge 等跨浏览器兼容性测试
- **无障碍测试**：不涉及屏幕阅读器、键盘导航、WCAG 合规性等无障碍测试
