# Dream auth routes

| File | Pos | Function |
| --- | --- | --- |
| `start/route.ts` | Login entry | Admin code/PKCE redirect with restricted relative return. |
| `options/route.ts` | Login card configuration | Exact configured Admin password/Google actions; no secret, credential or token. |
| `callback/route.ts` | Exact registered callback | HTTP/HTTPS Web callback delivers tab credentials after state/issuer/PKCE; native private scheme retains original handle recovery. |
| `session/route.ts` | Browser state | Web Bearer principal/profile with public user only; native Cookie mode retains handle-bound CSRF. |
| `refresh/route.ts` | Web renewal | Exact-Origin JSON refresh grant via the existing public OAuth client. |
| `logout/route.ts` | Logout | Web exact-Origin JSON refresh revocation; native exact-Origin/CSRF handle revoke and success-only Cookie clearing. |
| `device/route.ts` | Device entry | Capability-checked redirect to Admin device review/approve/deny UI with optional user_code. |
| `me/route.ts` | Profile alias | Shared authenticated BFF proxy to existing Python/Admin public profile. |

All routes delegate to [the same private owner](../api/_auth/handlers.ts). No route owns a password hash, signs JWTs, reads PG, enables deferred ASR or changes Agent/SSE/lease behavior. Configuration must register the actual callback URI and exact Dream/Admin origins. Candidate routes are not a claim of frontend/Runtime/full-domain migration or deployment.
