## 0. 文档结论

本次不新增独立“定时任务页面”。定时任务继续进入已有日记日历的日期弹窗，但右侧详情区需从“日记卡片后直接追加一张任务卡”重构为清晰的日期工作区：日期摘要 → 定时任务 → 日记。任务区先回答“什么时候执行、现在是什么状态、我能做什么”，日记区继续承担阅读和删除日记的原有职责，执行历史作为所属任务的二级内容展开。

页面必须复用现有 CalendarPopup、定时任务 API、Chat 会话导航和服务端状态。浏览器只展示服务端返回的 effective 配置、revision 和运行记录，不自行推算下一次触发或伪造执行结果。

## 1. 背景与问题

用户会在 Chat 中让 Agent 创建单次或每日定时任务，并在日记日历中按日期查看计划、运行结果和关联会话。当前截图已经证明以下现状：

- 桌面端以遮罩层承载双栏弹窗，左侧是 2026 年 9 月月历，右侧是 2026 年 9 月 28 日的日期详情。
- 右侧先出现一条普通日记，再出现“晨间复盘”任务；任务展示“每天 09:00 · UTC”“下次执行：9月29日 09:00”和“待执行”。
- 任务提供“编辑、暂停、立即运行、删除、历史”操作。
- 日记和任务共用一个连续容器，但没有“日记”“定时任务”分组标题；顶部只显示“1篇”，没有表达当日另有 1 个任务。
- 操作使用密集的原生样式小按钮，主次不明确；截图没有展示加载、空、冲突、失败、执行结果待核查、删除后撤销、历史展开和移动端状态。

因此，当前界面可作为功能已接入的证据，不能直接作为完成设计。重设计需要补齐信息层级、运行反馈、操作风险、响应式和无障碍规则。

## 2. 目标与边界

### 2.1 目标

1. 用户选中日期后，能立即区分该日的定时任务与普通日记，并理解两者数量。
2. 用户不进入编辑态即可判断任务计划、时区、状态、下一次执行和最近一次结果。
3. 用户可按定义状态完成允许的任务操作，并得到与实际提交结果一致的反馈；`exhausted` 仅允许立即运行、查看历史和删除。
4. 每次执行有独立历史记录；建立真实目标 Thread 后，用户可打开对应会话。
5. 加载、空数据、revision 冲突、请求失败、执行失败和 `state_unknown` 都有可行动反馈。
6. 桌面、窄屏和键盘操作保持同一业务能力，不因布局变化丢失关键操作。

### 2.2 非目标

- 不在日期弹窗内新建定时任务；创建入口仍是 Chat 中由 Agent Tool 发起。
- 不新增周、月、自定义 Cron 或复杂工作流编排。
- 不在浏览器计算下一次运行时刻、补跑策略或重复触发判断。
- 不在本 PRD 中设计运行中远程取消 Claude turn。
- 不改变普通日记的打开与删除业务语义。
- 首期不在 A3 月历格显示任务或需处理标记；月任务摘要等待 Admin-owned 月摘要 operation。
- 不用部署环境名称切换页面能力，不建立第二套任务、Thread、Run 或历史模型。

## 3. 证据边界与当前界面缺口

| 类别 | 当前图片或代码能够证明 | 当前不能证明 / 需要本 PRD 定义 |
| --- | --- | --- |
| 容器 | 桌面双栏遮罩弹窗；月历在左、选中日详情在右 | 窄屏排列、焦点管理、滚动归属 |
| 日期 | 月份切换、日期选中、日记圆点或选中态存在 | 首期不增加任务或需处理标记；月任务摘要属于后续数据能力 |
| 日期摘要 | 日期标题与“1篇”日记计数 | 任务数量、运行异常数量、日记和任务的分组关系 |
| 日记 | 时间、摘要、删除入口 | 长文本、多条日记时的截断与排序细节 |
| 任务 | 标题、待执行状态、每日时间、时区、下次执行、五个操作 | 编辑表单、暂停/恢复差异、操作中反馈、最近结果摘要 |
| 历史 | 有“历史”入口 | 展开形态、记录字段、空态、失败与 `state_unknown` 展示 |
| 会话 | 当前截图未显示“打开会话” | 何时显示、从哪条执行记录打开、不可用时的说明 |
| 删除 | 当前截图有“删除” | 是否可撤销、删除后的视觉与恢复路径 |
| 异常 | 当前截图未显示 | 加载失败、保存失败、并发冲突、运行失败、结果待核查 |

### 当前界面必须修正的缺口

1. **计数语义错误**：顶部“1篇”只统计日记，用户无法从摘要获知任务数量。
2. **内容类型混排**：日记与任务之间无分组标题，任务容易被理解为第二篇日记。
3. **动作无主次**：五个同尺寸边框按钮形成视觉噪声；“立即运行”和低频“历史”权重相同。
4. **状态只给结论**：“待执行”没有明确当前计划是否启用、最近执行是否成功或失败。
5. **时区表达生硬**：“每天 09:00 · UTC”直接暴露缩写，缺少“按哪个当地时间运行”的易读表达。
6. **操作结果不可见**：截图没有提交中、成功、失败、冲突和撤销反馈。
7. **历史缺少归属层级**：历史应属于某个任务，不应与日记列表成为同级全局页面。
8. **小按钮可点击面积不足**：密集按钮不利于触屏和键盘聚焦，也无法表达危险操作。

### 4.2 信息优先级决策

日期详情采用固定顺序：**日期摘要 → 定时任务 → 日记**。

- 定时任务位于日记之前，因为任务具有时间约束、运行状态和待处理操作；失败或结果待核查时，用户需要先看到。
- 普通日记仍保留独立分组和原有打开能力，不折叠到任务历史中，也不混入任务时间线。
- 任务历史只在所属任务卡中展开；默认不占据日期主列表，避免多次执行淹没日记。
- 当当天没有任务时，不显示空的任务分组，日期详情直接显示日记；当有任务但没有日记时，任务区完整显示，日记区给出简短空态。
- 日期摘要分别计数，例如“日记 1 · 任务 1”，禁止用“2 项”混淆两种对象。

## 5. 功能需求

### 5.1 月历与日期选择

1. 月份导航沿用前一月、月份标题、后一月结构。
2. 今天、当前选中日必须使用不同视觉信号；不能只靠颜色区分，至少结合边框、形状或文字标识。
3. 首期 A3 只保留现有日记标记、今天和选中日，不展示任务或需处理标记，也不为任务构造月视图假数据。
4. 任务标题、状态、失败详情和操作只在选中日期的 B1/B2 区域展示。
5. 切换日期时，取消上一日期的未提交编辑提示或阻止静默丢失：若表单已修改，弹窗内提示“有未保存修改”，允许“继续编辑”或“放弃修改”。该提示只在确有未保存内容时出现。

### 5.2 日期摘要

1. 主标题使用本地化完整日期和星期。
2. 次级摘要分别显示日记数与任务数。
3. 当存在 `failed` 或 `state_unknown` 执行时，摘要增加“有 N 项需查看”，点击后将焦点移到第一张相关任务卡。
4. 日期摘要不显示 task ID、revision、Thread ID、错误堆栈或 capability 名称。

### 5.3 任务卡默认态

每张卡默认展示：

- 任务标题。
- 定义状态：已启用、已暂停、单次计划已完成、已删除。状态文案与颜色配对，同时提供图标或文本。
- 易读计划：如“每天 09:00（UTC）”或“2026年9月29日 09:00（Asia/Shanghai）”。若用户界面时区与任务时区不同，可追加换算后的本地时间，但必须明确两者标签。
- 下一次执行：仅在服务端返回 `next_run_at` 时展示；暂停、完成或删除时以原因替代空时间。
- 最近一次执行摘要：运行中、已完成、失败、结果核查中或已跳过；无历史时显示“尚未执行”。
- 定义级操作：`active` 可立即运行、暂停、编辑、查看历史、删除；`paused` 可恢复、编辑、查看历史、删除；`exhausted` 只能立即运行、查看历史、删除；`deleted` 只显示撤销删除。
- “打开会话”只在某条执行已建立真实 `target_thread_id` 后显示，并与该条历史记录绑定。`exhausted` 仅从执行历史进入会话，不增加第四个定义级操作；没有目标会话时不显示不可用按钮。

状态优先级从高到低：`state_unknown` → `failed` → `running/queued/claimed` → 定义已暂停/删除 → `succeeded` → 待执行。运行异常不能被“已暂停”徽标遮盖；定义状态与最近执行状态应分两行表达。

### 5.4 编辑任务

1. 只有 `active` 或 `paused` 定义显示“编辑”；点击后在当前卡内展开表单，不跳转新页面。
2. 表单字段：标题、执行提示词、计划类型（单次/每天）、单次日期、时间、IANA 时区。当地时间不存在时明确说明“该时刻不存在”；当地时间重复但 Admin 未返回可验证候选时明确说明“该时刻出现两次”，保留 desired 草稿并要求改用无歧义时刻。页面不自行计算 UTC 偏移，也不让普通用户填写任意偏移分钟；未来只有 Admin 返回可验证候选后才增加易懂的选择控件。
3. 打开表单时以当前 effective 配置填充。用户输入是 desired 草稿；保存成功后服务端返回的新 effective 配置替换卡片，并更新 revision。
4. 标题、提示词、日期、时间或时区无效时，在对应字段下方说明原因，保留其他输入。
5. “保存”是主按钮，“取消”是文字按钮。取消只放弃当前草稿，不修改 effective 配置。
6. 保存中锁定重复提交，并在主按钮内显示进行中状态；其他任务卡仍可阅读。
7. 不为普通编辑增加确认弹窗。
8. `exhausted` 表示单次计划已经完成，不显示编辑入口，也不能通过修改标题、提示词、日期、时间、时区或规则重新排期；需要新的计划时间时，用户必须回到 Chat 让 Agent 创建新的定时任务定义。

### 5.5 暂停与恢复

1. 活跃任务点击“暂停”后立即提交带当前 revision 的操作。
2. 成功后卡片显示“已暂停”，不再显示下一次执行时刻，改为“恢复后重新计算下一次执行”。
3. 暂停不删除历史，也不终止已开始的运行。
4. 恢复成功后展示服务端返回的下一次执行，不能沿用暂停前由浏览器缓存的时间。
5. 暂停和恢复均为可逆操作，不增加确认弹窗。

### 5.6 立即运行

1. “立即运行”是 `active` 或 `exhausted` 任务的主要动作之一，不修改原计划、定义状态或 revision；`paused` 与 `deleted` 不允许手动运行。
2. 点击后按钮进入“正在请求”，成功创建手动触发后卡片显示“已加入执行队列”并刷新最近执行摘要。
3. 为同一次用户点击生成稳定请求键；网络结果不明时不能通过连续点击制造新的执行。页面应先查询原请求结果或显示“正在确认”。
4. 正在提交时禁止重复点击；已有计划触发正在运行不自动隐藏“立即运行”，但是否接受并发由服务端裁决。服务端拒绝时展示明确原因，不改写原任务卡。
5. 立即运行失败不影响未来计划。

### 5.7 删除与撤销

1. 删除为软删除且已有恢复操作，因此不弹确认框。
2. 删除成功后，卡片在原位置折叠为“已删除「任务名」”的撤销条，提供“撤销删除”。历史不被删除。
3. 撤销成功后按服务端返回的状态和下一次时刻恢复卡片。
4. 删除不取消已开始的运行；若存在运行中记录，在撤销条中说明“当前执行仍在进行”。
5. 删除或撤销发生 revision 冲突时按冲突流程处理，不以本地状态覆盖服务端结果。

### 5.8 执行历史

1. 点击“历史”在任务卡下方展开，第二次点击折叠；同一时刻允许展开多张任务，移动端可按空间策略只保留当前展开项。
2. 历史按实际触发时间倒序，每条记录展示：计划或手动、时间、状态、可行动说明。
3. `succeeded`：展示“已完成”，有目标会话时显示“打开会话”。
4. `failed`：展示面向用户的失败说明和“重试加载/再次运行”中的适用操作；不展示内部堆栈。
5. `state_unknown`：展示“执行结果正在核查”，保留打开已建立会话的入口；不能显示为失败，也不能引导盲目再次运行。
6. `claimed/queued/running`：使用非阻塞进行中样式和 `aria-live="polite"` 状态更新。
7. `skipped`：说明错过或跳过的时间范围；不得假装已成功。
8. 无历史时显示“尚无执行记录”，仍保留立即运行。
9. 历史加载失败只影响历史面板，不清空任务卡；提供局部“重试”。
10. 首页使用固定页面容量读取；返回满页时显示“加载更早记录”，并把最旧记录的 `created_at` 作为 Admin `before_created_at` 游标。追加页按 trigger ID 去重；非满页后隐藏入口。

### 5.9 普通日记

1. 日记保持按时间排序，卡片显示时间和首行摘要。
2. 点击正文区域打开日记；删除保留既有入口和现有产品语义。
3. 当前打开的日记继续用文字标识与视觉高亮表达。
4. 日记删除反馈与任务删除反馈分开，禁止让“撤销删除任务”恢复日记，反之亦然。
5. 任务加载失败时日记仍可阅读和操作。

## 6. 状态与错误反馈

### 6.1 定义状态

| 状态 | 卡片文案 | 可用主要操作 | 下一次执行区域 |
| --- | --- | --- | --- |
| `active` | 已启用 | 立即运行、暂停 | 展示服务端下一次时刻 |
| `paused` | 已暂停 | 恢复 | “恢复后重新计算” |
| `exhausted` | 计划已完成 | 立即运行、查看历史、删除 | “单次计划已完成；重新排期需新建任务” |
| `deleted` | 已删除 | 撤销删除 | 不展示下一次时刻 |

### 6.2 执行状态

| 状态 | 用户文案 | 反馈与操作 |
| --- | --- | --- |
| `claimed` | 正在准备 | 页面可见时进入有界刷新；不允许把它当作成功 |
| `queued` | 已加入队列 | 页面可见时进入有界刷新；达到观察上限后保留手动刷新 |
| `running` | 正在执行 | 页面可见时进入有界刷新；有目标会话后可打开会话 |
| `succeeded` | 已完成 | 显示完成时间；可打开会话 |
| `failed` | 执行失败 | 显示可行动说明；允许再次运行或检查配置 |
| `state_unknown` | 正在核查执行结果 | 禁止盲目再次运行；有会话则允许打开查看 |
| `skipped` | 已跳过 | 展示被跳过时间范围和原因说明 |

### 6.3 页面与操作错误

| 场景 | 页面行为 | 用户可执行动作 |
| --- | --- | --- |
| 日期数据加载中 | 任务区显示与卡片结构一致的骨架；日记已有数据不被遮挡 | 等待或切换日期 |
| 日期任务加载失败 | 任务区显示 inline alert，日记区正常可用 | 重试 |
| 历史加载失败 | 仅历史面板显示错误 | 重试历史 |
| 编辑字段错误 | 对应字段下方显示错误，保留 desired 草稿 | 修正后保存 |
| 单次当地时刻不存在 | 卡片内说明时钟调整导致该时刻不存在，effective/revision 不变 | 修改日期或时间后保存 |
| 单次当地时刻重复且无候选合同 | 卡片内说明该时刻出现两次，保留 desired 草稿且不猜测偏移 | 改用无歧义时刻后保存 |
| revision 冲突 | 重新读取并展示最新 effective 配置；保留用户草稿，标出与最新值不同的字段 | 检查后再次保存或放弃草稿 |
| 普通操作失败 | 卡片内显示失败，不乐观改变 effective 状态 | 重试 |
| 立即运行提交结果不明 | 显示“正在确认是否已创建执行”，暂时禁用重复触发 | 等待查询结果或刷新 |
| `state_unknown` | 作为执行状态展示，不等同 API 错误 | 打开已有关联会话，等待对账 |
| 未认证或会话过期 | 任务区显示需要重新登录；不暴露任务数据 | 重新登录 |
| capability 不可用 | 任务区显示“定时任务暂不可用”，普通日记不受影响 | 重试或稍后再试 |

## 7. 关键交互流程

### 7.1 查看选中日期

1. 用户在月历选中日期。
2. 右侧立即更新日期标题，任务区进入加载态；已有日记可同步展示。
3. 服务端返回任务定义和该日触发记录。
4. 页面按“任务 → 日记”分组渲染，并分别更新数量。
5. 若请求失败，任务区显示错误与重试；日记不被清空。

### 7.2 编辑并处理并发冲突

1. `active` 或 `paused` 用户展开编辑，页面以当前 effective 配置创建 desired 草稿，并携带当前 revision；`exhausted` 不提供编辑入口。
2. 用户修改后保存。
3. 若成功，页面使用服务端返回的 effective 和新 revision 重绘卡片。
4. 若 revision 冲突，页面读取最新配置，保留 desired 草稿并标出差异。
5. 用户决定基于最新配置重新保存或取消草稿。
6. 用户需要重新安排已完成的单次计划时，返回 Chat 新建定义；页面不得把 `exhausted` 编辑包装成重新排期。

### 7.3 立即运行并打开会话

1. 用户点击“立即运行”，按钮进入提交中并阻止重复点击。
2. 创建手动触发成功后，卡片显示排队或准备状态。
3. 后台建立目标 Thread 后，当前执行记录出现“打开会话”。
4. 用户点击后进入既有 Chat，会话对象与该次执行记录一致。
5. 最终消息提交后，历史状态变为完成；失败或结果不明时按真实状态展示。

### 7.4 删除与撤销

1. 用户从更多操作选择删除。
2. 服务端提交成功后，原卡片折叠为撤销条，不弹确认框。
3. 用户点击撤销，页面使用服务端恢复结果重绘卡片。
4. 任一步失败都保留服务端已确认的状态，并显示局部重试。

## 8. 响应式要求

### 8.1 宽屏

- 保留截图中的左右双栏结构；左侧月历稳定，右侧详情独立滚动。
- 右侧日期摘要保持可见，任务和日记在其下滚动。
- 任务卡主操作保持一行，低频操作进入“更多”菜单，避免按钮墙。

### 8.2 中等宽度

- 双栏可收窄，但任务卡字段不能压缩成不可读的单行。
- 计划摘要、下一次执行和最近结果改为纵向排列。
- 主操作允许换行，仍保证“立即运行”和“暂停/恢复”先出现。

### 8.3 窄屏与触屏

- 弹窗占满可用视口，避免左右溢出；月历和详情改为单列或“月历/当日详情”两层切换。
- 进入当日详情后提供明确“返回月历”，系统返回键和 Escape 行为一致。
- 日期摘要固定在详情顶部；卡片内容单列；编辑表单字段占满宽度。
- 点击目标遵循现有设计系统的最小触控尺寸；危险操作放入更多菜单，与主操作保持间距。
- 打开历史后，滚动发生在日期详情容器，不让背景页面跟随滚动。

实现断点应复用现有设计系统 token，并由内容是否能完整展示决定；本 PRD 不把某个像素值定义成业务限制。

## 9. 可访问性要求

1. 弹窗使用对话框语义，提供可读标题，打开时焦点进入弹窗，关闭后返回触发按钮。
2. 桌面与窄屏都支持 Tab/Shift+Tab 顺序操作；焦点不能进入遮罩后的页面。
3. Escape 优先关闭任务的更多菜单或编辑/历史子面板，再关闭日期弹窗；有未保存 desired 草稿时先给出放弃提示。
4. 月历使用适合网格或日期选择器的键盘语义，方向键移动日期，Enter/Space 选择。
5. 状态不得只用颜色表达。徽标同时包含文字，错误使用 `role="alert"`，非紧急状态更新使用 `aria-live="polite"`。
6. 每个任务操作的可访问名称包含任务标题，例如“暂停：晨间复盘”。
7. 加载骨架标记忙碌状态；加载完成后将状态变化通知屏幕阅读器，不强制移动用户焦点。
8. 所有正文、次级文本、状态徽标、禁用态和焦点环满足现有设计系统的对比度标准。

## 10. 视觉与文案方向

### 10.1 延续的视觉资产

- 延续截图的暖白纸张背景、圆角卡片、手写感标题字体和柔和阴影。
- 月历保持留白和低干扰风格；日期选中态继续使用深色轮廓，今天可使用暖橙色圆环。
- 日记卡继续使用轻量白色卡片，避免与任务的操作型卡片混淆。

### 10.2 需要调整的视觉层级

- 定时任务卡增加左侧状态色条或状态图标，但必须配合文字。
- “立即运行”使用主按钮；“暂停/恢复”使用次按钮；编辑、历史、删除进入更多操作。
- 失败和 `state_unknown` 使用不同文案与图标：失败表示已有失败结论，结果核查中表示尚未确认。
- 时区文案采用“每天 09:00（UTC）”等自然格式，避免把原始字段标签堆进卡片。
- 删除使用危险色文字，但因可撤销不弹确认；成功后显示原位撤销条。

## 11. 技术建议

1. **复用现有边界**：扩展现有 `CalendarPopup` 的结构与样式，复用 `scheduledTaskApi`、浏览器会话头、i18n 和 `onOpenTaskThread`，不新增平行定时任务页或第二套请求层。
2. **服务端状态为准**：页面不计算下一次触发。编辑、暂停、恢复、删除、撤销都携带 `expected_revision`；成功后用响应或重新读取结果替换本地卡片。
3. **草稿与生效值分离**：组件内单独保存 desired 表单草稿；effective 任务对象保持只读。冲突时并列比较，不用草稿直接覆盖响应。
4. **局部状态隔离**：日期加载、单卡操作、历史加载分别管理 busy/error，避免一个任务失败使整个日期弹窗不可用。
5. **稳定幂等键**：立即运行的 `manual_request_key` 在一次用户意图和其结果恢复期间保持不变，确认失败前不生成新键。
6. **历史关联**：打开会话使用执行记录的 `target_thread_id`，不使用任务定义的来源 Thread 代替目标 Thread。
7. **国际化与时间**：日期、时间和星期使用当前 locale；任务时区显示服务端 IANA 标识。浏览器显示时区只用于日期查询和辅助换算。
8. **样式复用**：将任务卡、状态徽标、操作组、inline alert 抽为 CalendarPopup 内聚子组件；优先复用既有 Button、Menu、Dialog、Field 和 Toast 组件（如仓库已有），不要复制新的通用控件。
9. **数据能力缺失**：Admin capability 缺失时 fail closed，仅禁用定时任务数据与操作；普通日记保持正常。
10. **测试定位**：组件测试覆盖状态和操作映射；浏览器测试走真实同源 API 边界与既有 Chat 导航，不能复制 reducer 或伪造另一套生产入口。
11. **月摘要后置**：首期不请求月任务摘要。未来若在 A3 展示任务或需处理标记，必须先由 Admin 提供 owner-filtered 的月摘要 operation；浏览器不得对一个月逐日调用 28–31 次 `scheduled-task.day`。
12. **历史游标**：历史分页只消费 Admin 的 `before_created_at`，不在浏览器建立第二套历史索引；追加页按 trigger ID 去重。
13. **有界刷新**：仅当选中日期存在 `claimed`、`queued` 或 `running` 时，在页面可见且前一请求已结束后刷新；终态、页面隐藏或达到观察上限时停止，用户仍可手动刷新。
14. **DST 失败合同**：页面按稳定错误码分别显示不存在、重复和旧偏移失效；没有 Admin 候选时不得由浏览器推算 UTC 偏移。

## 12. 验收条件

### 12.1 信息架构与视觉

- [ ] 日期摘要分别显示日记数和任务数。
- [ ] 任务与日记有明确分组，任务固定在日记之前，历史归属到具体任务。
- [ ] 任务卡默认态可读出标题、定义状态、计划、时区、下一次执行和最近结果。
- [ ] 主操作和低频操作有明确层级，不再显示五个等权小按钮。
- [ ] A3 只展示今天、选中日和现有日记标记；不存在任务菱形、需处理标记或对应假数据。

### 12.2 完整业务操作

- [ ] 编辑打开当前 effective 值，保存后显示新 revision 对应结果，取消不修改任务。
- [ ] `exhausted` 只提供立即运行、查看历史和删除；不显示编辑，重新排期引导用户从 Chat 新建任务定义。
- [ ] 暂停后未来触发停止且历史保留；恢复后展示服务端新计算的下一次时刻。
- [ ] 立即运行不修改原计划；提交中阻止重复点击；结果不明时不盲目创建第二次运行。
- [ ] 删除无需确认弹窗，成功后原位提供撤销；撤销后恢复服务端返回状态。
- [ ] 执行历史展示计划/手动类型、时间、状态和可行动反馈。
- [ ] 执行历史满页时可按服务端游标加载更早记录，追加结果不重复。
- [ ] 真实目标 Thread 建立后才显示“打开会话”，并打开对应执行会话。

### 12.3 状态与错误

- [ ] 日期加载、历史加载和单卡操作有相互独立的 loading/error 状态。
- [ ] revision 冲突时显示最新 effective 配置，同时保留并标记 desired 草稿差异。
- [ ] `failed` 与 `state_unknown` 使用不同语义；后者不引导盲目重跑。
- [ ] capability 或认证失败不会清空或禁用普通日记。
- [ ] 任务、历史或操作失败均提供局部重试，且失败后不展示未经服务端确认的成功状态。
- [ ] `claimed/queued/running` 仅在页面可见时有界刷新，进入终态后停止请求。
- [ ] DST 缺失、重复和旧偏移失效使用不同提示，保留 desired 草稿且不由浏览器推算偏移。

### 12.4 响应式与可访问性

- [ ] 宽屏保持双栏，窄屏无横向溢出且所有业务操作可达。
- [ ] 键盘可完成选日期、展开任务、编辑、暂停/恢复、立即运行、历史和打开会话。
- [ ] 焦点被约束在弹窗内，关闭后回到原触发点。
- [ ] 状态有文字，错误和动态更新具备正确的 alert/live 语义。
- [ ] 触控目标、文本对比度、焦点环满足现有设计系统标准。

## 13. 后续事项

现行[页面骨架图](./scheduled-task-diary-page-structure-sketch.md)已经覆盖宽屏双栏、移动单栏、任务默认态、编辑态、历史展开态、删除撤销态和结果待核查态；[UI 设计与 HTML 原型](../../design/claude-agent/scheduled-task-diary-page-ui-design.md)负责尺寸、间距、配色、图标、响应式和可访问性细节。后续修改这些结构时，必须同步 PRD、骨架图、UI 设计和生产 E2E。

月历任务/需处理标记属于后续事项。进入后续设计前必须先定义 Admin 所有、按当前用户过滤、一次返回整月摘要的 operation，并完成鉴权、日期时区、失败与性能验收；没有该能力时 A3 继续只展示日记标记。
