# frontend/

## 架构概述

`frontend/` 同时是唯一 Node workspace、根 Web package 和 Next.js 16 project。唯一 App Router 与公开 Route Handler 位于 `app/**`；全部 Dream 浏览器应用源码位于私有、不可路由的 `app/_dream/**`；独立 server-only Node MCP Apps Runtime 合法保留在同级 `packages/mcp-apps-runtime/src/**`。

依赖安装只使用 `pnpm@10.28.1` 与根 `pnpm-lock.yaml`。生产 dev/build/start 只运行 Next；Vite 与 `@vitejs/plugin-react` 仅供隔离 browser harness 使用，不是第二套源码、构建或部署 owner。

## 边界规则

1. `app/client-shell.tsx` 是唯一允许装载浏览器 Dream 根的 client boundary；`app/layout.tsx` 不访问 Browser global。
2. `[serverRef]/route.ts` transport Route 只薄委派 server-only package；crawler Route 只代理 Python-owned public resource。`phase1-status/route.ts` 与 `mcp-apps-sandbox/route.ts` 当前仍反向导入 `app/_dream/**/host-policy` 并组合 preview policy，这是必须迁入中立 shared/server owner 的已知代码缺口。
3. Browser MCP Client 只连接同源 `/api/mcp-apps/{serverRef}`；Node Runtime 可读取短时 connection view，但不能把 upstream URL/header/env/credential 返回 Browser。
4. Python 仍拥有 actor、workspace、managed-MCP 配置与 credential；Node 拥有进程级 upstream session/catalog；Browser 拥有 iframe/Host 生命周期和用户交互。
5. `productionAppsEffective` 固定为 `false`。Phase 0–3 通过只代表 provider-free technical preview，不是公开部署或真实生产验收。
6. 测试中合法的 Vite、React Refresh、第三方 official AppServer/Inspector 引用必须按 harness 目的判断，不能通过机械搜索删除。
7. 生产构建固定 `NODE_ENV=production`。已知非标准 `NODE_ENV=development` 会在 Next prerender 阶段失败，不能被记录为产品缺陷或成功回执。
8. 当前 AutoDL direct-host、GitHub 静态前端 workflow 和 `wrangler.jsonc` 仍绑定 npm/Vite/`dist` 形状；它们是待迁移代码缺口，不是 fallback。
9. `public/runtime-config.template.js`、`public/runtime-config.js` 与 `app/_dream/App.tsx` 仍有把当前路径称为 Vite/static 或 Next/Vite compatibility 的旧源码注释；这些注释不是 Runtime 事实，后续代码维护应改为 Next/browser runtime-config 或明确 test-harness compatibility。
