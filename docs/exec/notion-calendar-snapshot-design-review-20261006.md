# Notion 日历快照优先独立设计评审

## 评审范围与结论

评审依据为 [Calendar PRD](../prd/calendar/calendar-right-panel-tabs-prd.md)、[正式交互设计](../design/claude-agent/calendar-right-panel-tabs-ui-design.md)、[影响评估](./notion-calendar-snapshot-repair-20261006.md)及现有 `backend/notion` 读取、过滤、同步和 operations 边界。本次独立评审没有执行测试，也没有修改实现文件。

**最终结论：可实施。** 复核现行正式设计 §3，G1、G2 已闭合，具体记录见本文末尾。快照先展示、历史日期创建筛选、今天更新项 metadata-only 校验可以复用现有组件和 JSON 索引，无 Admin schema 依赖；无需增加通用缓存、数据库表、后台任务或正文读取能力。

首次评审结论为“修改后可实施”，当时 G1、G2 为实施前正文门禁；下方保留首次发现及最小修正，不代表门禁仍未关闭。

用户最新要求取代原 Search 可发现今日列表及非今天禁读规则。范围为当前 actor 当前连接器索引与当前选择的交集；新页面和索引未记录的变化仍通过连接器同步发现。此范围不等于授权全集，不提供历史编辑事件全集。

## 正文澄清门禁

| --- | --- | --- |
| G1 | “409 context changed”未明确归属/选择/凭证变化时是否继续展示旧数据；临时失败保留旧结果可能误套在权限上下文变更。 | 明确任何 actor、连接归属、资源选择或凭证上下文变化立即清空旧列表；日期、时区、午夜变化清空原投影。仅索引版本变化也不能提交旧校验结果，应重新读当前索引或提示刷新。保留旧列表只适用于服务端确认上下文仍一致的临时上游失败。 |

## 通过的设计边界

1. 快照权威来自 `NotionSnapshotStore.load_current(actor, connector)`；每次投影使用 `filter_snapshot_for_connector` 求当前选择交集。服务器决定校验 ID，浏览器不能指定索引之外的资源。日历不会发布 canonical 快照、修改选择或扩大 Runtime 的正文读取范围。
2. 历史日纯本地索引读取，仅按上游创建时间命中；今天按上游创建和最近编辑时间归类。时区日边界为分别构造的本地两次零点，区间终点排除；最新编辑时间不代表完整编辑历史。
3. 首次请求返回快照及实际计数，列表显示后才启动元数据校验；仅服务端实际今天且索引最近编辑时间落在今天的页面远程读取。历史请求即使带校验参数仍不得远程读取。
4. `get_page` 当前同时调用页面、Markdown 和 blocks，不能复用。新增 `get_page_metadata` 仅调用 `v1/pages/{id}`，并验证资源身份、归档/删除及数据形状。
5. 旧索引缺创建时间不能用同步时间补齐。既有同步 owner 刷新选中独立页面元数据并保留 `created_time`、`last_edited_time`；数据库行继续通过既有 query 分页收集。索引继续 `pages={}`。
6. 不修改 Task/Diary/Chat 状态 owner，页签切换、原焦点陷阱、任务结果/草稿和既有导航保持。PRD 正文已经提供桌面/窄屏骨架，正式设计正文已经提供正常、异常及状态图。
7. 公开新路径与旧 today 路径调用同一处理函数，不保留一个绕过快照的 Search 业务分支。配置缺失不应再次使历史或初次快照列表 503。
8. 校验 401 清空列表；单页 403/404/归档删除移除该行并标记部分结果；限流或临时故障仅保留同上下文且允许展示的快照。已知数量与校验完成状态分别显示，部分结果 0 不冒充正常空清单。

## 实现检查点

- 快照存在但缺部分字段时仍可显示已经确定命中的行。`SnapshotShown` 应允许同时携带 partial 和 pending；`NeedsSync` 不能隐含隐藏所有已知行。
- 现有 `normalize_page_item` 和 `_build_index_entry` 把缺标题补成资源 ID。新增索引字段需保留缺标题语义，否则历史日不会正确显示“未命名文档”。Runtime 原有标题回退可以留在其展示边界，不能使日历把 ID 当上游标题。
- 归属校验、当前资源过滤与返回前提交检查均应使用相同规范化资源身份；去重不能通过扩大当前选择范围实现。远程 ID 不匹配不得把返回对象合并进列表。
- 校验事务建议复用现有 `INK_NOTION_OPERATION_TIMEOUT_SECONDS` 作为总预算；不新增任意产品限额。超预算返回同上下文 partial，遇限流停止后续读取并传递 Retry-After，禁止自动连环重试。
- 返回前重新比较服务端当前 todayKey；所选 dateKey 未变化但已跨午夜时，不能把旧今日校验结果覆盖历史创建投影。
- 隐藏页签不启动新的第二阶段读取；已发起请求可结束且不得夺焦点或播报隐藏内容。关闭、换日期/时区、连接、actor、登出时取消并让请求代号检查拒绝迟到响应。
- 远程结果覆盖、移除及临时失败保留只能作用于本次内存投影，不写 canonical 索引。下次查看可重新投影快照；页面“最近同步”与“本次校验”状态必须分开，不能把校验时间标为索引同步。
- 用户要求历史不远程校验，因此只能根据已知的本地授权、归属及凭证状态拒绝读取；不能声称历史快照已经实时重新校验 Notion 远程权限。已知撤销或失效必须清空。

## 必需验证门槛

由 `luna_test_runner` 执行确定性单元、公开接口、构建、静态和隔离浏览器验证，保留实际命令、退出码、首次失败与复测。至少覆盖：历史零远程、快照在慢校验前可用、当天更新 ID 最小校验集、无 Search/body/select/sync/Admin 写入、旧索引缺字段、当前选择缩小、401/403/404/429/网络/超时、资源 ID 不匹配、A→B→A、关闭/登出迟到响应、索引和凭证变化、午夜、DST 23/25 小时和半开边界。Task/Diary/Calendar 的既有完整旅程必须回归。

Markdown 清单、引用、历史原文和 Mermaid 检查是文档验证，不是业务验收。本评审可实施结论也不能替代代码完成或测试通过。

## 复核记录

已复核现行 PRD §3 和正式设计 §3：

- G1 闭合：`NOTION_CONTEXT_CHANGED` 明确归属/选择/凭证变化清空旧列表；`NOTION_SNAPSHOT_CHANGED` 停止旧版本校验并提示刷新；`NOTION_DATE_CONTEXT_CHANGED` 重新投影日期，禁止旧校验提交。临时上游失败的保留仅限同上下文结果。
- G2 闭合：正式设计明确 metadata-only GET 包括同步新增独立页面读取，统一服务器显式 API 日期，缺失 fail closed；同步失败保留 LKG，纯快照读不依赖远程版本配置。
- 正文同时补齐总 operation timeout 预算、429 停止后续调用、初次 partial 可同时 pending 且保留已知行。状态图已区分无快照 NeedsSync 与缺字段 Partial。实现负责人确认索引保留空标题语义。

PRD 的“配置缺失仅影响远程校验”摘要应同步表述为“依赖远程元数据的同步和校验 fail closed，快照读取仍可用”；状态图补 `Partial --> Validating` 的 pending/今天/可见条件可进一步对应正文。这两项是与已经明确的正式合同保持一致的文档收尾，不需要增加接口或产品范围。
