# Ink & Memory 移动应用产品需求

前端取舍：RN统一客户端与Next Web目标保持，按[RN框架内的复用方案](../../design/multi-platform/frontend-reuse-tradeoffs.md)逐区域推进。保留业务范围和规则；原生区域与网页区域分别验收，不默认将全部TSX/CSS列为改写项。

## 背景与问题

用户需要iOS、Android安装包，2026-10-27选择React Native原生界面，通过HTTP访问端侧Dream Python与现有业务接口。App级模块管理本地后端启动、就绪与释放；正常网页登录、账户、权限和计费保持。Admin由`https://ink-admin.suoxya.com`独立提供原有账户和数据服务。

Dream工作台创建模块退出端侧范围：隐藏创建、初始生成与审核确认入口，相关页面和流程退出移动适配及验收。Web模块、后端接口与已有数据保留。下文原WebView实现与回执保留各自适用范围；RN/RNW统一工程及原生业务界面处于接线阶段，完整业务继续验收。

前稿在容器设计中引入了独立认证、手机令牌保管、附件先本地准备、额外任务状态和入口裁剪。这些内容已经删除。当前设计以现有网页业务为基线；原业务未在手机接通的部分列为实施缺口。

当前物理iPhone已经执行内嵌CPython和11个现有业务模块。早期签名安装包通过局域网开发接线取得原React页面200响应，Simulator完成过Mac联调Chat。当前关闭Mac relay的独立Simulator已运行原后端与原Claude执行模块，通过原账号网页登录、会话、保护读取、真实回复、消息保存、计费结算及第五次Chat的页面结束反馈。普通重开已读取原历史，同一对话追问取得真实回复；结束反馈间歇失败。部分文件、工具、停止与恢复已有技术检查；稳定结束反馈、真实停止、完整工具和物理iPhone同项测试继续验收。详见[独立执行记录](../../exec/mobile-app-design-review-20261024.md#独立simulator原chat终态复验通过)。

## 目标与边界

| --- | --- | --- |

本轮用户未授权改造登录业务、数据权限、存储归属、任务状态、Agent工具和计费。账户删除、支付、举报等要求只核对既有业务与发布材料，缺口记录在发布验收中。

## 概念与规则

### React Native原生界面目标

移动主界面使用React Native原生组件，导航为Chat、Decks、More。首页、More、快捷操作与应用内链接均不提供工作台创建或审核确认入口。原Chat中的既有消息、结果和附件按原权限读取；本轮不新增Dream工作台原生页面。

Web继续通过Next.js发布。可移植的RN视图经React Native Web逐步共用，现有网页保持可使用；编辑器、系统文件选择等必要差异分别适配。工作台创建与审核确认保留原Web页面，退出跨端视图迁移范围。

打开App后显示准备状态，本地后端就绪后检查原会话。启动失败显示原因及重试。切换页面、退出登录和进入后台均不等于停止后端或取消任务。再次进入先读取原状态与历史；用户停止任务仍使用原停止操作。系统结束App后重新装配运行实例，读取原记录。

正式业务图见[RN交互稿](../../design/multi-platform/react-native-web-project-structure.md)，实例所有权见[运行时架构](../../design/multi-platform/mobile-runtime-architecture.md#实例所有权与生命周期)。原网页登录保留AuthEntry与原BFF；Cookie接入原生HTTP存储、HTTP增量与文件URI适配单独验收。

### 正常网页登录

使用现有`AuthEntry`：邮箱、密码、注册、Google入口和原错误信息保持一致。表单action由现有`/auth/options`返回；原Admin验证凭证，原Next BFF处理OAuth callback、会话Cookie和CSRF。取消、失败、过期和退出按照现有页面与接口处理。

会话检查或登录入口读取失败时，原错误区域显示`Try again`。用户恢复网络后点击，页面重新加载并读取已有会话与登录入口；未提交表单内容重置，密码登录继续由用户提交原表单。凭证校验失败保留原输入与错误反馈，用户修改后提交。

登录文档允许原网页表单和HTTPS导航。成功后本机BFF会话接入平台HTTP存储，RN读取原公开会话与CSRF。账号密码由原网页处理，禁止进入bridge、安装资源、普通日志或测试源码。设备码登录退出范围。

iOS独立路径由应用内原Next加载同一份React与原网页登录；原form、Cookie、callback和BFF协议保持。此前Mac relay联调已在iOS Simulator应用宿主完成正常密码登录与一次Chat，该历史回执保留Mac业务执行位置。当前独立路径已接入原配置，应用内原Next的登录动作读取返回200；原账号登录、端侧Python权限传递和真实任务分别验收。失败继续显示原页面反馈。

原生Chat首次读取配置失败时保留当前页面，发送与快捷操作暂不可用，原错误区提供重试。成功读取过的数据在刷新失败时保留；重试保留当前对话、草稿与附件。恢复读取完成后继续原操作，读取重试不发起新消息或停止已有任务。

### 原任务与数据

发送、队列、停止和恢复由[Chat Send](../Chat%20Send.md)、[队列输入](../chat/queued-input.md)及原业务实现定义。客户端前后台、网络和渲染进程变化属于页面状态；这些事件不创建新Run状态、不确认任务成功或取消、不自动重新提交内容。

排队消息保留原调整方向、删除、编辑和侧边聊天操作。编辑失败时展示保留稿及原重试入口；用户可先检查队列状态。同一对话保持打开时，切到后台再返回保留已编辑草稿和重试反馈；离开对话后恢复区随原页面结束。窄屏侧边聊天使用全宽弹层，源对话和输入稿保持；关闭后回到源对话，已创建任务继续按原规则运行。当前Native实现及独立验收范围归统一工程设计和执行记录。

活动铃铛打开原最近Chat、今日定时任务及日期历史。搜索、显示来源、刷新、关闭和历史删除保留原入口；移动端工作台来源隐藏。选择定时任务进入只读详情，显示原任务信息、执行模型、规则及源/执行对话，点击对话返回对应Chat。打开面板保留底层输入和附件；关闭返回原对话。失败按来源显示原重试，切后台暂停读取，回到前台读取当前快照，任务执行状态保持原规则。

返回应用时读取现有状态和历史；缺少本机执行记录时使用原恢复错误。容器不增加自动改绑Thread、替代Agent、离线数据库、双向同步、后台常驻、后台落库或新的任务调度。

既有WebView中，已保存确认消息的恢复、原内容与权限保持原实现，见[iOS恢复设计](../../design/multi-platform/mobile-ios-interaction.md#已保存dream确认的进程重开恢复)。该流程退出RN移动适配与本轮验收。

### 原附件与文件

保留[useFileUpload](../../../frontend/app/_dream/hooks/useFileUpload.ts#L104)的原上传时机、直传/服务端上传选择和[AIInputDock](../../../frontend/app/_dream/components/chat/AIInputDock.tsx#L312)的workspace写入顺序。系统文件选择产生的File/Blob、原附件DTO与现有提交链保持一致。导出、分享和系统文件打开由对应平台适配，不增加“先导入本机、再确认上传”流程，不重新划分本机和云端业务，不增加账户目录管理页面。

### 工作区结果查看与素材复用

用户从原Chat消息查看图片、打开Markdown报告及其相对引用，或下载原文件和目录。图片预览提供关闭、下载和“添加到当前消息”；添加后沿原输入卡上传，原Thread、草稿、权限和附件大小规则保持。报告按原Markdown内容展示，原HTML内容按文字展示。目录沿原规则下载ZIP，文件下载打开系统导出面板；取消后回到原内容，源文件和草稿保持。

预览只有当前文件的操作，不增加文件管理首页或账户目录。切后台释放显示资源，回到前台读取当前文件；读取失败显示原访问、缺失或重试反馈。关闭预览终止其读取，原Agent任务状态保持。文件侧栏列表与原维护操作已有独立Native组件及技术回执；普通RN入口接线与真实文件业务继续待完成。本段结果引用、预览、下载和素材接收沿原规则。

### 原工作区文件操作

用户从原Chat工作区入口打开文件侧栏，查看原目录树和当前位置，进入目录、选择文件或文件夹上传、下载文件或ZIP目录、删除原条目。删除失败保留条目并显示错误，用户可再次操作。选中文件夹保留顶层目录及子路径，一次提交原批量上传；取消选择保持原目录与草稿，无新增上传或确认步骤。

当前已实现原组件复用、原生文件能力及普通RN更多/文件/分享接线；设备操作、真实账户文件上传下载删除及完整主页面继续验收。原界面没有移动/重命名控件，本轮保持原入口范围。

### 页面与平台交互

移动导航为Chat、Decks、More及既有Settings入口，视觉沿用现有主题。窄屏适配区域尺寸、滚动和键盘可见性。iOS顶部操作位于系统安全区内，Settings搜索聚焦后保持页面尺寸。消息区纵向滚动，代码/表格在自身区域横滚，输入区增高后内部滚动；键盘打开时发送/停止可见，关闭键盘恢复原阅读位置。

iOS状态栏与底部手势区使用当前页面主背景色，跟随现有浅色、暗色和系统主题设置。状态栏文字与手势指示条保持可读；内容仍避开系统安全区，键盘打开时保留原输入与主操作可见性。主题变化只更新外观。

iOS保留原页面返回和系统弹窗关闭；Android返回先处理键盘和当前弹窗，再按原页面历史返回。网页授权与外链使用原链接目的地；远程网页无法调用本地bridge。加载、空内容、失败和重试复用原页面反馈，容器错误单独处理。

## 用户业务旅程

安装 → 打开Dream原生应用 → 准备本地后端 → 原网页登录 → 原callback与会话读取 → 原生工作区 → 范围内核心任务与结果 → 原退出 → 再次打开读取原会话与历史。

断网、取消授权、登录失败、会话过期、切后台和进程重开均沿原失败与恢复入口处理。平台生命周期不改变任务和数据状态。包内Python、实际Agent执行、网页登录和页面接线分别留验收回执。

背景与问题：更多中的设置需要保留原设置分类及内容。目标与边界：记忆回应沿原配置编辑和保存，订阅沿原只读信息，关于沿原静态内容；原生内容组件与完整设置导航分别验收。
