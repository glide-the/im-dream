> [Sync] 2026-09-18: AutoDL keeps public Admin issuer identity while routing server-only Dream DTO/token/JWKS traffic to loopback Admin.

## 架构概述
平台化发布脚本入口，按 local、docker、remote-ssh、autodl-ssh、google-cloud 分目录组织；阿里云 ECS 是 `remote-ssh` 的生产配置，不建立平行脚本目录。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| README.md | 脚本入口说明 | 当前 Next.js/pnpm 发布矩阵、平台命令、已阻塞入口、数据库与 Secret 边界，以及代码缺口 |
| local/ | 本地发布脚本 | 以 Next.js 与 FastAPI 启动，要求显式Admin DTO/BFF配置并拒绝旧数据库及Dream认证secret；尚未投影Browser Voice WS base，stop/clean也未强校验PID/容器所有权；仅允许显式选择已验证的不可变Vite回滚镜像 |
| clash/ | Mihomo TUN 配置 | 保存非敏感 TUN 片段和使用说明；真实 `config.yaml` gitignored，用于 Docker/Remote SSH Compose 的 `tun-proxy` |
| docker/ | Docker 发布脚本 | Compose 构建根 Next.js standalone image 与 FastAPI image；backend 共享 Mihomo `tun-proxy` 网络命名空间并取得 bubblewrap 所需权限；helper 仍有历史 Nginx 模板前置检查 |
| remote-ssh/ | Remote SSH 发布脚本 | SSH/rsync + Compose 的 Next.js/FastAPI 构建、启动、验证与回滚；当前仍传递被 Next Dockerfile 忽略的 `VITE_PUBLIC_SITE_URL`，不能宣称已完成前端公开元数据注入 |
| autodl-ssh/ | AutoDL 直宿主入口 | frozen pnpm 构建 standalone Next.js，运行 Node MCP Apps Runtime 与 FastAPI，并保留持久数据、安全和进程所有权门禁 |
| google-cloud/ | Google Cloud 发布脚本 | 使用当前Next.js Dockerfile构建frontend并过滤旧Dream认证投影；SQLite同步已fail closed，生产路径仍需修正被忽略的Vite参数并完成整体验收 |
| setup-storage.sh | 兼容：存储初始化 | 委托 `google-cloud/setup-storage.sh`，保留旧调用路径 |
| setup-env.sh | 兼容：环境变量初始化 | 读`backend/.env`，只将Dream Runtime所需key写入Secret Manager并丢弃旧Google/JWT/Session/OAuth secret；输出根目录`.cloud-env` |
| deploy.sh | 兼容：Cloud Run 部署 | 委托 `google-cloud/deploy.sh deploy`，保留旧调用路径 |
| sync-data.sh | 已退役的数据同步兼容入口 | 委托`google-cloud/sync-data.sh`并fail closed，不再处理SQLite/GCS数据 |
