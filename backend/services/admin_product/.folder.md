# backend/services/admin_product — Folder Contract

## Architecture Summary

Dream exposes same-origin Product BFF routes and validates their request/response
Pydantic DTOs. The shared Admin OAuth dependency supplies an immutable actor DTO;
the Product client forwards that actor's Admin-issued OAuth bearer without putting
the canonical user ID in request headers, query or body. Admin resolves the subject,
revalidates active canonical/platform identity and owns
all subscription, usage, model and payment persistence and transactions. Dream
does not open PostgreSQL, issue Product tokens or provide a local data fallback.

## File Table

| File | Pos | Function |
|---|---|---|
| `config.py` | server configuration | Validate Admin Product origin and timeout settings; no signing key/issuer/audience exists in Dream. |
| `models.py` | DTO boundary | Define strict Product requests, results and safe error envelopes. |
| `client.py` | Admin HTTP client | Forward one verified OAuth bearer, make one bounded no-retry Product call, and validate the response field firewall. |
| `service.py` | application service | Validate the Admin-authenticated actor DTO, required Product scope and canonical response binding. |
| `runtime.py` | composition root | Lazily construct and close the Admin HTTP client without database dependencies. |
| `errors.py` | safe error mapping | Preserve stable user-facing Product error codes and status. |

## Sync

- 2026-09-16: removed the redundant Dream PostgreSQL canonical-user lookup.
  `routers.deps.get_current_user` derives the subject from Admin OAuth, and the
  Admin Product API remains the authoritative active-user and data owner.
- 2026-09-16: removed Dream's Product HS256 signer. Read routes require
  `product:read`, writes require `product:write`, and only the verified Admin OAuth
  bearer crosses the client boundary. Admin derives the canonical subject again.
