# deploy/

## 架构概述
平台化发布脚本入口，按 local、docker、remote-ssh、autodl-ssh、google-cloud 分目录组织；阿里云 ECS 是 `remote-ssh` 的生产配置，不建立平行脚本目录。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| README.md | 脚本入口说明 | 三类平台脚本入口、旧 Cloud Run 脚本兼容映射、通用参数约定、生产 OAuth/CORS/cookie 配置要求 |
| local/ | 本地发布脚本 | 本地直跑检查、构建、启动、验证、停止和清理入口 |
| clash/ | Mihomo TUN 配置 | 保存非敏感 TUN 片段和使用说明；真实 `config.yaml` gitignored，用于 Docker/Remote SSH Compose 的 `tun-proxy` |
| docker/ | Docker 发布脚本 | Docker Compose 检查、构建、启动、验证、停止和清理入口；backend 默认共享 Mihomo `tun-proxy` 网络命名空间；backend 容器使用 Claude Code bubblewrap Bash sandbox 所需 runtime 权限 |
| remote-ssh/ | Remote SSH 发布脚本 | 通过 SSH/rsync 同步仓库到已安装 Docker 的远程服务器，并在远端执行 docker-compose 构建、启动、验证、回滚和清理；Remote SSH nginx 上游端口由同一组 `REMOTE_*_PORT` 环境变量渲染；backend 默认共享 Mihomo `tun-proxy` 网络命名空间；公开前后端 origin 同步给根路径 SEO 构建/生成配置；生产 OAuth URL、Secure cookie 和 CORS 由 Compose environment 覆盖；backend 容器使用 Claude Code bubblewrap Bash sandbox 所需 runtime 权限；阿里云 overlay 额外从 mode-0600 配置读取 block-device read BPS/IOPS budget，防止 Agent 读取风暴阻塞整机 |
| autodl-ssh/ | AutoDL SSH 发布脚本 | 直接宿主 Python/Node/screen 拓扑；验签并安装由通用 Runtime 流程在 Linux x64 Docker 中资格化的 2.1.88 local-core 制品，其中 `vendor/seccomp` 已恢复 Docker-style `apply-seccomp` passthrough；生成 env 固定 `INK_AGENT_SANDBOX_ENABLED=false`，Workspace Mode 不变，approved Bash 以 Dream root 直接执行；不在 AutoDL 重复构建或资格化，也不使用 Docker/nginx |
| google-cloud/ | Google Cloud 发布脚本 | Cloud Run 主发布入口，默认使用固定公开域名 `ink-backend.suoxya.com` / `ink-frontend.suoxya.com`，承载完整构建、推送、部署、OAuth/CORS/cookie/根路径 SEO public URL 回写和验证流程 |
| setup-storage.sh | 兼容：存储初始化 | 委托 `google-cloud/setup-storage.sh`，保留旧调用路径 |
| setup-env.sh | 兼容：环境变量初始化 | 读 `backend/.env`，指定 key 写入 Secret Manager，其余配置汇总；输出根目录 `.cloud-env` |
| deploy.sh | 兼容：Cloud Run 部署 | 委托 `google-cloud/deploy.sh deploy`，保留旧调用路径 |
| sync-data.sh | 兼容：云数据同步 | 委托 `google-cloud/sync-data.sh`，保留旧调用路径 |
