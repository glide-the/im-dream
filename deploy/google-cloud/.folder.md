# deploy/google-cloud/

## 架构概述
Google Cloud Run脚本目录。frontend image使用根Next.js/pnpm Dockerfile；Admin DTO数据边界、独立service account、逐secret IAM和SQLite fail-closed已经进入脚本，但前端公开元数据参数与完整Cloud Run旅程仍未重验，因此脚本存在不等于平台已通过生产验收。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| deploy.sh | Google Cloud 发布脚本 | 构建并推送backend与standalone Next.js frontend image，分别投影Admin DTO/FastAPI与Next BFF配置；过滤旧Dream认证authority，缺少Next service/BFF secret则构建前fail closed；仍传递被当前frontend Dockerfile忽略的`VITE_PUBLIC_SITE_URL` |
| setup-storage.sh | Google Cloud 存储初始化 | 创建GCS bucket及相互独立的backend文件服务账号、frontend BFF服务账号并输出`.storage-env`；根路径`deploy/setup-storage.sh`仅做兼容委托 |
| sync-data.sh | 已退役的 SQLite 兼容入口 | 所有非 help 调用均 fail closed；不再读取、上传、备份数据库，也不触发 Cloud Run 重启 |

## Sync

- 2026-09-06: Google Cloud documentation now records that the Next.js Dockerfile ignores the legacy Vite build argument and that SQLite synchronization is unsupported under the Admin-owned PostgreSQL schema contract.
- 2026-09-16: Cloud Run发布会过滤旧Dream认证Secret引用，无剩余合法引用时显式清空revision Secret绑定；Admin拥有Google/Better Auth/OAuth，Dream仅在Next侧保留BFF handle secret。
- 2026-09-16: backend与frontend使用独立Cloud Run service account；Secret Manager改为逐secret授权，BFF cookie secret只绑定frontend。
- 2026-09-16: Google Cloud SQLite同步/备份入口已退役并fail closed；共享文件维护继续使用独立文件系统拓扑。
- Historical, 2026-06-14 Vite path: `deploy.sh` passed the frontend public URL as `VITE_PUBLIC_SITE_URL`; the current Next.js Dockerfile does not consume it.
- 2026-06-15: `deploy.sh` now uses the frontend origin root for `VITE_PUBLIC_SITE_URL`, `INK_PUBLIC_BASE_URL`, and deployment summary URLs.
- Historical, 2026-06-23: Cloud Run once projected Dream Google/JWT/session secrets and Secure/SameSite policy; the 2026-09-16 Admin-auth cutover retired that behavior.
