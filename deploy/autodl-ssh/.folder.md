# deploy/autodl-ssh

## 架构概述

AutoDL/SeetaCloud 直宿主发布入口。使用唯一的 Next.js/pnpm workspace 构建 standalone frontend，与 FastAPI、Node MCP Apps Runtime 和持久 Dream 数据根共同运行。

## 文件清单

| File | Pos | Function |
|---|---|---|
| `README.md` | 当前操作合同 | 说明 Next/FastAPI/MCP Apps 拓扑、公网映射发现、发布、验收和回滚边界 |
| `deploy.sh` | 直宿主发布实现 | frozen pnpm install、standalone Next build、FastAPI venv、Info-ZIP 工作区导出依赖、Node MCP Apps 路由门禁、启动/验证/回滚 |

| `test-topology.sh` | 当前拓扑校验 | 断言 pnpm/Next/MCP Apps、环境投影、安全边界和旧 Vite/npm 路径清除 |

## 必须保留的安全边界

- Dream 只消费 Admin-owned PostgreSQL schema，不执行 migration、runtime DDL、备份或恢复。
- Dream workspace、Notion credential、Artifact、本地文件、plugin Runtime 与 service home 必须位于显式数据根，拒绝符号链接并保持既有 owner/group/mode。
- 历史 AutoDL 外层容器固定 `INK_AGENT_SANDBOX_ENABLED=false`；这意味着 approved Bash 以 Dream root 身份运行且没有 bubblewrap 文件系统或网络隔离。迁移不得隐去或自动改变该事实。
- 发布、启动、停止和回滚只能影响本目录明确命名并拥有的 Dream release、process 和 link，不能替换未知进程或修改 Admin 数据。
- Claude Runtime、Node MCP Apps、内置 Skill catalog、默认 Deck Plugin、crawler routes 与 rollback 都必须在 Next.js release 形状上验证。
