# Chat 活动视图与优先级

## 背景与问题

Chat 目前在“更多”菜单中打开右侧对话历史面板，列表可以切换 Thread、打开历史搜索及继续加载。用户需要在“新建”旁直接打开活动视图，在日期历史之前集中看到定时任务、最近五分钟更新的 Chat 对话和 Dream 工作台，以便先进入正在推进的工作。

参考图一采用铃铛入口、顶部优先级和下方日期历史；参考图二采用带勾选状态的显示菜单。本次复用这一信息结构，视觉沿用 Ink & Memory 的纸面、主题文字和当前图标体系。截图的红色框是需求标注，不成为界面元素；截图中的置顶、归档、标记已读不属于本次功能。

## 目标与边界

1. 在 Chat 顶部“新建”旁增加始终可见的铃铛按钮，名称为“活动视图”；有无当前 Thread 都能打开右侧面板。
2. 面板显示“优先级”和现有按日期组织的对话历史。优先级包含今日定时任务、最近五分钟更新的 Chat、最近五分钟有活动的 Dream。
3. 执行中的定时触发优先；Dream 使用服务器既有“生成中／进行中”阶段提高展示顺序。Chat 不根据更新时间猜测运行状态。
4. 复用已有历史分页、历史搜索、Thread 导航、Dream canonical href 和定时任务详情侧栏。右侧一次只展示一个侧栏，打开活动视图时收起文件、子智能体、独立任务会话和定时任务详情。
5. 打开、刷新、筛选及点击活动行只读取或进入既有页面/详情，不自动调用创建、发送、暂停、恢复、执行、删除、归档或标记已读接口。日期历史保留原独立删除按钮及 `handleDeleteThread`；近期 Chat 去重后可复用同一删除回调，不新增删除机制或确认。定时任务详情继续由原合同负责。
6. 不改变 `PlanButton` 当前 Thread 的任务与进度职责，不改变 `PluginReceiptBadge`、发送、排队、停止、恢复、Stream 或 Runtime 协议，不增加数据库 Schema 或后端控制系统。

本稿是已独立评审为可实施的现行产品合同。[正式交互设计稿](../../design/claude-agent/priority-activity-sidebar.md)正文已包含正常业务时序、异常恢复与页面/来源状态图；技能阶段材料是过程证据，不能替代现行文档。Stage 4 视觉规格、独立评审及最小源代码已写入，12项focused及最终全仓类型技术检查通过；先前并行Notion文件错误保留在回执，真实业务与模型未验收。

## 概念与规则

### 数据所有权和当前能力

| 来源 | 已实现公开读取与字段 | 本次用途与限制 |
| --- | --- | --- |
| Chat | `listChatThreads({ limit, offset })` → `GET /api/claude-agent/threads`；`id`、`title`、`updated_at`、Deck/Voice 标识 | Admin 按 `updated_at DESC` 返回当前用户有权读取的对话。`updated_at` 是 Thread 更新，不仅是消息时间；改名、绑定 Deck/Voice/SDK session 也会更新。列表不含跨对话 `running` 或普通正文预览。 |
| 定时任务 | `getScheduledDay(localDate, displayTimeZone)` → `GET /api/claude-agent/scheduled-tasks/day`；`tasks` 与 `triggers` | Dream 通过 `scheduled-task.day` 请求 Admin；Admin 负责日期、时区、规则计算、权限和持久化。此接口是日期视图，不是全部任务或全部运行触发的接口。 |
| Dream | `useStoryWorkspaceDreamRuns()` → `storyWorkspaceFetchDreamRuns()` → `GET /api/story-workspace/dream-runs` | 使用已校验的 `lastActivityAt`、`lifecycle`、`displayTitle`、`deckDisplayName`、`href`。原重入集合和顺序由服务端所有；本次只对活动视图派生数组排序，不修改原集合或原重入视图。 |

所有读取沿用同源 Cookie 身份认证和既有权限边界；不使用浏览器存储作为业务数据源，不读取其他用户数据。服务端字段缺失、时间无效或 DTO 校验失败时不能生成虚构时间、运行状态或链接。

### 时间与日期范围

- 五分钟是用户明确要求的展示窗口，统一由一个前端活动视图配置项定义为 `5 * 60 * 1000` 毫秒。筛选、自动移出和验证共用这一项，禁止在组件之间复制常量。
- 对 Chat 使用 `updated_at`，对 Dream 使用 `lastActivityAt`。以同一次展示计算的当前时间为基准，满足 `0 <= now - activityAt <= windowMs` 才进入最近活动；恰好五分钟仍显示，超过五分钟移出。无效和未来时间不进入最近活动，不以 `created_at` 或本地打开时间补齐。
- Chat 的含义是“最近更新的对话”，不承诺“最近发送消息”。Dream 的时间已经由服务端取 Run 创建、Thread 更新和阶段活动的最大值，前端不重新推导。
- 定时任务采用当前浏览器显示时区的今日日期，与 Calendar 现有时区处理一致。界面在定时任务行或标题旁明确显示“今日”；不把历史搜索日期或最后打开的 Calendar 日期带入活动视图。
- Admin 日期读取返回：计划发生时间落在今日的一次性或每日定义；定时触发按 `scheduled_at`，手动触发按 `created_at` 落入今日。定义仍可能是暂停或已耗尽状态。昨日开始且今日仍运行的触发、未来一次性定义不在此响应中。
- 日期变化时重新读取今日任务；最近五分钟窗口连续跨日计算，不在午夜清空 Chat 或 Dream。页面隐藏时暂停本功能刷新，重新可见时重算时间窗口并刷新数据。

### 纳入、状态和排序

| 对象 | 纳入规则 | 状态文字及证据 | 优先顺序 |
| --- | --- | --- | --- |
| 今日定时任务 | 使用今日返回的定义与触发，以 `task_id` 合并为一行。已删除定义且无执行中触发时不显示；孤立触发使用触发自带标题，不伪造定义。 | 触发 `running` 为“运行中”；`claimed` 为“待启动”；`queued` 为“排队中”；`succeeded` 为“已完成”；`failed` 为“失败”；`state_unknown` 为“状态待核对”；`skipped` 为“已跳过”。没有触发时依据定义显示“已启用／已暂停／已耗尽”。`active` 不代表运行中。 | 有 `running` 触发的行最先；其余行按更新时间从新到旧。 |
| 最近 Chat | 按近期分页扫描得到且时间窗口内的 Thread，每个 `id` 一行。 | 显示标题、Chat 类型及更新时间；列表无 `running`，不显示运行中徽标。已有搜索 `match.excerpt` 仅用于搜索，不为普通行增加正文请求。 | 进入非执行中的最近活动层，按更新时间从新到旧。 |
| 最近 Dream | 重入响应中时间窗口内的 Run，每个 `storyWorkspaceRunId` 一行。 | 复用 `generating` 的“生成中”、`waiting_confirmation` 的“等待确认”、`running` 的“进行中”、`recent` 的现有阶段文字。它们是 Dream 业务阶段：`generating` 可能因为阶段尚未齐全，`running` 可能因为确认尚未派发，均不等于当前 Runtime 实时执行。 | `generating` 或 `running` 属于进行中的工作层，排在其他最近活动之前；不把 `waiting_confirmation` 当作执行中。 |

统一顺序为：定时触发运行中 → Dream 生成中／进行中 → 其余符合条件的活动。同层按来源的活动时间降序，时间相同按带来源前缀的稳定实体 ID 升序。任务时间取已返回定义与触发的 `updated_at` 最大值；有多个触发时优先显示 `running`，否则显示更新时间最新的触发，时间相同按触发 ID 选择。任务运行和 Dream 阶段由不同字段负责，不能共用“运行中”标签。

最近 Chat 使用同一 `listChatThreads({ limit, offset })` 公开入口读取近期集合。已核实 Admin 按 `updated_at DESC` 返回：首批读取后，如仍全为窗口内记录，继续以原始响应条数推进 offset，直到遇到首个早于窗口的有效记录或响应为空，再停止；不设置固定最多页数，也不读取其后的全部历史。无效或未来时间不纳入，不能作为早于窗口的停止证据。各批结果按 Thread ID 去重，独立请求序号防止旧刷新覆盖新结果。日期历史保留原 `loadMoreThreads` 分页状态，近期扫描不得把历史分页误判为全部已显示。Dream 重入接口保留其当前集合边界，包括 recent 项服务端限量；本次不通过拉取每个 Run 的详情扩充集合。

### 去重与筛选

- 优先级内部按 `(source, entityId)` 去重。定时任务的定义和多个触发合并成一行；分页重复 Thread 不再添加；Dream Run ID 重复不再添加。
- 已显示在优先级的 Chat Thread 不在日期历史重复显示；关闭“优先级”或“Chat”筛选后，对应 Thread 回到原日期历史。合并仅发生在这一面板，Chat landing 的原列表不受影响。
- 不根据相同标题或 Deck ID 合并 Chat、Dream、定时任务。当前 Dream 重入 DTO 不含 source Thread ID，因此无法证明一个 Chat 与一个 Dream 是同一业务入口，不能猜测后跨来源去重。
- “优先级”标题右侧的显示菜单只有“优先级部分”“定时任务”“Chat”“Dream”。默认全部勾选，分类开关只影响优先级，日期历史始终保留。
- 关闭“优先级部分”时收起整个优先级内容，分类勾选仍保留。所有分类关闭时显示“选择要显示的活动类型”；已选分类读取成功但没有内容时显示“暂无需要关注的活动”。筛选是展示偏好，不写入业务数据库，本次在 ChatView 生命周期内保持即可。

## 页面信息架构与骨架

### 页面模块结构

| 编号 | 模块 | 位置、外观与职责 |
| --- | --- | --- |
| A | 活动铃铛 | 顶部新建旁；透明按钮，打开后使用现有选中表面。始终可见，不附加未读计数或红点。 |
| B | 面板标题栏 | 右侧顶部固定；“活动”、历史搜索、刷新和关闭入口。 |
| C | 优先级 | 列表滚动区最上方；标题及显示菜单。行显示标题、来源、状态或更新时间，当前 Thread 使用原有选中反馈。 |
| D | 日期历史 | 接续优先级，保留今天、昨天、最近七天、最近三十天和更早的现有分组、Thread 导航与分页。 |
| E | 显示菜单 | 从优先级标题的省略号打开；同一纸面，选项带勾选，关闭方式为外部点击或 Escape。 |
| F | 既有弹窗与侧栏 | 历史搜索是原居中弹窗；定时任务详情、文件、子智能体、任务会话复用原侧栏，和活动面板互斥。 |

### 骨架编号与尺寸依据

| 编号 | 骨架中的区域 | 对应现有模块或职责 |
| --- | --- | --- |
| A1 | Chat 顶部新建与活动铃铛 | `ChatView` 顶部操作；铃铛关闭为透明，打开为现有选中表面。 |
| A2 | Chat 消息／原 landing | 原主内容；桌面继续使用自己的消息滚动区。 |
| A3 | Chat 输入区 | 原输入与发送／停止操作；活动开关不改变草稿。 |
| B1 | 活动固定标题栏 | “活动”、搜索、刷新、关闭；标题栏不参与列表滚动。 |
| C1 | 优先级标题与省略号 | 始终保留筛选入口；关闭“优先级部分”仅收起 C2/C3 内容。 |
| C2 | 优先级活动行 | 混合三来源的统一排序列表；每行两层信息，不分成三套独立列表。 |
| C3 | 来源加载／错误／空状态 | 在优先级内表达来源状态；失败来源有独立重新加载入口。 |
| D1 | 日期分组与历史行 | 今天、昨天、最近七天、最近三十天和更早；保留原导航。 |
| D2 | 历史分页反馈 | 底部加载中、分页失败重试或全部已显示；没有第二个历史滚动区。 |
| E1 | 显示菜单 | 四个带勾选状态的选项；作为浮层不占列表高度，不被列表裁剪。 |
| F1 | 历史搜索弹窗 | 原 `HistorySearchDialog`；关闭搜索回到活动面板。 |
| F2 | 定时任务详情 | 原 `ScheduledTaskDetailSidebar`；进入后替换活动面板。 |
| F3 | 其他右侧栏 | `FileSidebar`、子智能体和独立任务会话；与活动面板互斥。 |

桌面结构宽度复用 `FileSidebar` 的 `20rem`（默认字号下约 320px）；历史稿中的 `16rem` 已由当前 `20rem` 替代，不作为同时出现的第二列。窄屏沿用 `App` 的 `useMobile` 判定，小于 768px 的视口进入窄屏布局；移动设备的既有判定同样保留。390px 是结构验证尺寸，五分钟以外的这些尺寸都不是业务规则。具体按钮、间距和文字视觉值由 Stage 4 在当前主题内统一。

390px 骨架使用可用视口全宽与可用高度，主 Chat 保留原布局和滚动位置，不在抽屉旁压缩成另一列。浏览器可见高度变化时抽屉适应可用高度；B1 保持可达，C/D 承担列表滚动，页面本身不产生横向滚动。显示菜单仍从 C1 的省略号展开，其左右边界不得超出抽屉；F1 搜索按原弹窗语义置于抽屉上层，受窄屏可用视口约束。

## 用户流程、加载和恢复

1. 用户点击铃铛。ChatView 关闭其他右侧栏，打开活动面板；已存在的 Thread、草稿、附件和当前发送流程不变化。再次点击铃铛或面板关闭按钮收起面板。
2. 首次打开分别读取 Chat 历史、今日任务和 Dream；每个来源有独立加载、成功空、错误和重试状态。先成功的来源即可显示，不能等待另外两项，也不能因其中一项失败隐藏全部内容。
3. 用户选择显示菜单中的分类。即时重算展示，不重新执行任务、不创建 Thread。关闭菜单仍保留当前勾选。
4. 点击 Chat 复用 `handleSelectThread`；点击 Dream 复用 `openDreamRun(run.href)` 并保留正常链接的修饰键行为；点击任务用现有 DTO 转换为 `ScheduledTaskMarkerSnapshot`，进入 `ScheduledTaskDetailSidebar`。任务详情失败反馈由其已有公开读取负责，不把缺失定义解释为可执行。
5. 在列表底部继续加载历史，仍使用现有 `loadMoreThreads` 与重复 ID 保护。分页失败保留已有记录并显示重试，不将错误当成“全部已显示”。近期 Chat 扫描途中失败时保留已读近期行、显示 Chat 分区重试；未走到停止条件前不能把该来源标记为读取完成。
6. 可见期间按集中定义的技术刷新间隔更新来源；最近活动到期时自动移出；刷新、页面重新可见和跨日时均使用当前时间重算。技术刷新间隔是请求调度参数，不属于用户配额。关闭面板、卸载或页面隐藏时取消本功能的计时与请求，不触发发送恢复。

| 来源状态 | 首次无成功数据 | 已有本来源成功数据 | 恢复行为 |
| --- | --- | --- | --- |
| 加载中 | 来源对应骨架占位 | 保留已有行并显示轻量更新状态 | 响应到达后只替换本来源；不清空其他来源。 |
| 成功且空 | 该来源没有活动；仅所有选中来源均空时显示整体空状态 | 移除该来源过期或不存在的行 | 按正常刷新继续读取。 |
| 读取失败 | 该来源显示“暂时无法加载”和重新加载按钮 | 保留最近成功行，同时说明本来源更新失败；旧运行/阶段状态以“上次状态”说明并退出当前运行优先层，行仍按时间窗口过滤 | 重试只刷新失败来源；成功后移除错误。 |
| 响应已过期 | 不提交被关闭、切换日期或旧请求的响应 | 保留后发请求的数据 | 使用 AbortController 或已有请求序号保护；不将乱序响应覆盖到当前日期。 |

实施前 `ChatView.fetchThreads` 将读取异常转成空数组，无法满足活动错误语义。当前实现已在相关历史／搜索边界保留错误，活动读取由 `useActivitySidebarData` 独立恢复；对应focused技术测试已通过，完整结果与初次夹具失败见实施回执；不作为真实业务验收。

## 响应式与可访问性

- 桌面为右侧纵向面板，标题固定，优先级与日期历史共用一个内容滚动区。宽度复用当前右侧栏的布局配置，再由 Stage 2/4 明确视觉值；不新增页面级横向滚动。
- 窄屏使用覆盖式抽屉，主 Chat 不被压缩到不可操作宽度；背景不能接收抽屉内的点击或键盘焦点。使用现有移动端导航断点，尺寸不成为业务规则。
- 铃铛、显示菜单、搜索、刷新和关闭按钮均有明确可访问名称。铃铛提供 `aria-expanded` 与面板关联；菜单选项提供勾选状态，不只用颜色表示。
- 打开后焦点进入面板标题区域，关闭后回到铃铛；Escape 先关闭菜单，再关闭抽屉。桌面面板不强制阻断主 Chat 键盘操作，窄屏抽屉按对话框语义管理焦点。
- 列表以标题、来源和文字状态表达含义；长标题省略仍能读取完整名称。动态刷新不抢走焦点、不重置滚动、不逐次朗读全部条目；失败和重试结果提供简短反馈。
