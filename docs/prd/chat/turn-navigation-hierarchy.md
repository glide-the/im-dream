# Dream Chat 单个 Thread 的用户消息轮次导航 — 页面层级与逻辑

> `html-design-workflow` 阶段 3。依据[轮次导航 PRD](./turn-navigation.md)、[结构草图](./turn-navigation-structure.md)和参考截图。截图的红框、Codex 内容、颜色、气泡和书签图标只用于辨认“左侧刻度＋悬浮摘要”这一结构，不作为 Dream 的文案或规则。以下 A1、B1、B2、C1、D1、D2、E1 与前两阶段逐项对应。

## 页面结构草图（模块分区，细化）

### 桌面与可容纳轨道的侧边任务会话

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ A1 现有 Chat 页头：Thread 标题、已有操作                                   │
├────────────────────────── 消息阅读区域 ────────────────────────────────────┤
│ ┌────── B1 用户消息导航轨道 ──────┐  ┌──────── D1 当前 Thread 消息滚动区 ─┐ │
│ │ 索引加载/仅已加载提示（如适用） │  │                                  │ │
│ │  │                           │  │  原消息列表：用户、助手、工具、错误  │ │
│ │  ─ B2 用户消息 1               │  │                                  │ │
│ │  │                           │  │                                  │ │
│ │  ━ B2 当前/悬浮/聚焦项 ────────┼──┼─▶ C1 交互摘要浮层                 │ │
│ │  │                           │  │    ┌──────────────────────────┐  │ │
│ │  ─ B2 用户消息 3               │  │    │ 用户输入预览／附件说明   │  │ │
│ │  │                           │  │    │ 本轮助手结果／明确状态   │  │ │
│ │  ……更多项时 B1 自身滚动        │  │    │ 定位进度／失败重试（按需）│  │ │
│ └──────────────────────────────┘  │    └──────────────────────────┘  │ │
│                                    │ D2 选中用户消息的现有渲染节点与      │ │
│                                    │    本轮回复阅读起点                  │ │
│                                    └──────────────────────────────────┘ │
├────────────────────────────────────────────────────────────────────────────┤
│ E1 现有输入 Dock：草稿、附件、发送／停止／排队                             │
└────────────────────────────────────────────────────────────────────────────┘
```

- `B1` 与 `D1` 同属消息阅读区域；`B1` 是窄轨道，不是另一个 Thread 侧栏。`C1` 以当前 `B2` 为锚覆盖在可用消息区域内，避开 `E1`，打开时不改变 `D1` 的滚动位置。
- 每个 `B2` 的视觉刻度细且紧凑、操作区域比线段宽；刻度顺序是当前 Thread 中已发送且可读取的用户消息顺序，数量不取自截图。当前／悬浮项形成最长线段，两侧按距离递减并平滑过渡；不画贯穿竖线。阅读位置仍由 `aria-current` 表示。
- `D2` 是 `D1` 中已有的消息节点定位目标，不复制一份正文。点击、Enter 或 Space 激活 `B2` 后，`D1` 才滚到 `D2`，并让用户消息开头可读；本轮回复仍由原消息列表呈现。
- 无可导航消息时省略 `B1`；历史索引未完整取得时，`B1` 明示“仅显示已加载消息”。右侧既有 HistorySidePanel 若展开，只改变本阅读区域可用宽度。

### 约 390px 手机视口

```text
┌─────────────────────────────────────────┐
│ A1 现有 Chat 页头                        │
├────────────── 消息阅读区域 ─────────────┤
│ B1 “本对话消息”入口                       │
│ ┌──── B1 展开列表（按消息顺序）────────┐ │
│ │ B2 用户消息 1  · C1 本轮摘要／状态   │ │
│ │ B2 用户消息 2  · C1 本轮摘要／状态   │ │
│ │ ……                                   │ │
│ └──────────────────────────────────────┘ │
│ ┌──── D1 当前 Thread 消息滚动区 ──────┐ │
│ │ D2 选中后进入视口的原用户消息节点   │ │
│ └──────────────────────────────────────┘ │
├─────────────────────────────────────────┤
│ E1 现有输入 Dock                         │
└─────────────────────────────────────────┘
```

手机上 `B1` 从固定细轨道折为轻量入口，展开后 `B2` 为可触摸的消息行，`C1` 为该行摘要或选中时显示的详情；选择 `B2` 后关闭列表并定位 `D2`。展开区域避开 `E1` 与现有底部导航，触屏不依赖悬浮。

## 页面层级结构图（Root → Section → Module → Component）

```text
Root：当前 Dream Chat Thread 页面／侧边任务会话
│
├─ Section：现有页头
│  └─ Module A1：Chat 标题与既有操作
│     ├─ Component：Thread 标题（告知当前会话）
│     └─ Component：既有操作入口（沿用原行为，不承载轮次导航）
│
├─ Section：当前 Thread 消息阅读区域
│  ├─ Module B1：用户消息导航容器
│  │  ├─ Component：桌面窄轨道／手机展开入口与列表容器
│  │  ├─ Component：索引加载、索引不完整提示
│  │  └─ Module B2：单条用户消息导航项（随消息数量重复）
│  │     ├─ Component：短横刻度或手机消息行；可点击／键盘激活
│  │     ├─ Component：当前阅读位置、悬浮／聚焦及可见焦点状态
│  │     └─ Component：目标消息 ID 与顺序；ID 只用于定位，不展示
│  │
│  ├─ Module C1：所指 B2 的交互摘要
│  │  ├─ Component：用户可见文本预览／附件名称或类型
│  │  ├─ Component：本轮助手可读结果预览，或进行中／失败／暂无回复／待核对
│  │  ├─ Component：定位加载、无法定位与重试反馈（需要时）
│  │  └─ Component：桌面锚定浮层／手机列表内摘要呈现
│  │
│  └─ Module D1：现有消息滚动容器及消息列表
│     ├─ Component：既有用户消息、助手内容、工具折叠区和错误块
│     ├─ Component：历史分页与滚动位置管理
│     └─ Module D2：目标用户消息的既有节点／本轮阅读起点
│        ├─ Component：稳定消息 ID 锚点与可见区域定位
│        └─ Component：定位后的短暂视觉提示，不修改消息正文
│
└─ Section：现有输入区域
   └─ Module E1：底部输入 Dock
      ├─ Component：草稿、附件、发送、停止、排队等既有操作
      └─ Component：供 B1／C1 避让的布局边界
```

`C1` 在渲染层可处于 `B1` 与 `D1` 上方，但逻辑上始终对应一个 `B2`，不对应整条 Thread；`D2` 则是 `D1` 的子节点。`B2` 与 `D2` 以同一稳定 `message.id` 关联。A1 与 E1 保持原有行为，只提供布局边界。

## 数据与动作责任

| 模块 | 读取的数据／判断 | 用户动作与输出 | 失败或边界处理 |
| --- | --- | --- | --- |
| A1 | 当前 Thread 标题与既有操作状态 | 显示会话上下文 | 沿用现有 Chat 反馈。 |
| B1 | 当前 `thread_id` 的可读取历史与实时消息；索引覆盖范围 | 按时间顺序容纳 `B2`；桌面内部滚动，手机展开／收起 | 无用户消息时隐藏；未取得完整索引时说明范围；读取失败保留已加载项并给出重试。 |
| B2 | 已发送的用户消息，以稳定 `message.id` 去重；排除草稿、未派发队列、助手、工具、系统输入和带系统注入来源的修复输入 | 悬浮／聚焦打开 `C1`；点击、Enter、Space 请求定位 `D2`；标记当前项 | Thread 变化立即清理旧项；连续用户消息分别建项；焦点可见且有读屏名称。 |
| C1 | 从当前 `B2` 到下一条用户消息前的可读取内容；用户正文／附件与最后一段助手可读结果；现有运行和错误状态 | 原文预览与明确状态；Escape、移开指针／焦点关闭；必要时提供定位重试 | 不跨轮取回复，不列工具日志，不生成模型摘要；摘要失败时显示已有用户预览和“摘要暂不可用”；内容安全转义并截断。 |
| D1 | 现有消息列表、历史分页、滚动容器与可见消息 | 执行目标查找、分页、滚动；滚动阅读时更新当前 `B2` | 目标未加载则通过既有受权分页读取；失败保持原滚动位置；切换 Thread／新目标使旧定位请求失效。 |
| D2 | 目标 `message.id` 对应的已渲染用户消息节点 | 将目标消息及开头移入可读视口，短暂强调 | 目标不可读时沿用认证／权限反馈；无节点时不猜测位置。 |
| E1 | 原有输入与运行状态 | 保持发送等原动作 | `B1` 和 `C1` 避让输入 Dock；导航不改变草稿或发送状态。 |

交互范围按用户消息切段：`[本条用户消息, 下一条用户消息)`。最后一条延伸到当前最新可读内容。仅在服务端确认的消息历史与现有轮次状态支持时显示“失败”或“完成”；SSE 暂断不等于失败。助手回复到达后更新同一个 `B2` 的 `C1`，不新增刻度。

## 关键状态流

```text
进入／切换 Thread
  → 读取当前 Thread 可见消息与索引覆盖范围
  → 按 message.id 去重并筛出用户实际发送的消息
  → 生成 B1 中的 B2；无结果则隐藏 B1
  → 与 D1 已渲染消息绑定 D2 锚点

指向或聚焦 B2
  → 以该消息为边界读取本轮可见内容和既有状态
  → 打开 C1（不滚动 D1）
  → 指针与焦点离开或 Escape → 关闭 C1

激活 B2
  → 目标 D2 已渲染？
       是 → 在 D1 内定位、标记当前 B2、让用户消息开头可读
       否 → D1 经受权历史分页取得目标
              → 成功则定位；失败则留在原位置，由 C1／B2 提示重试
  → 较早定位请求若遇新目标或 Thread 切换 → 丢弃其滚动结果

用户自行滚动 D1
  → 根据主要可见的用户消息更新当前 B2
  → 不修改消息、草稿或输入状态

新消息成功入历史／实时回复／刷新重连
  → 以服务端保存的 message.id 合并
  → 用户消息新增或复用 B2；回复仅更新对应 C1
  → 索引范围、处理状态与当前阅读位置重新核对
```

滚动定位遵循系统减少动态效果设置；定位之后键盘焦点留在可继续遍历的 `B2`。打开 `C1` 本身不会移动滚动位置，且浮层内容不会执行用户输入中的链接或 Markdown 指令。用户无权读取当前 Thread 时，沿用现有认证／权限边界，不生成或泄露 `B2`／`C1` 预览。

## 待实现时核对

- 现有历史查询是否能获得完整 Thread 的用户消息索引，以及跨分页对应轮次的助手结果；若不能，先沿用“仅显示已加载消息”反馈，再评估受权只读索引／预览投影。此处不假定已具备完整索引，也不引入数据库 schema。
- 现有消息来源元数据能否识别自动修复等系统注入输入，以及现有轮次状态能否区分“正在回复”“本轮失败”“暂无回复”“状态待核对”。不能判定时显示“状态待核对”，不按客户端猜测结果。
