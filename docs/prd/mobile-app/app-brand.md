# 应用名称

## 背景与问题

应用现有展示使用Ink & Memory、Ink Memory、I&M及ink-dream，分布于导航、启动、关于、输入提示、分享和公开说明。用户确定英文名称为Kastention，中文名称为卡片结构。各入口需要采用一致名称，用户原有账户、内容和操作继续使用。

## 目标与边界

完成Web、iOS与Android源码中的应用名称更新，同步现行设计资料和必要导出物。页面结构、主题、图标、启动插画和业务流程沿现行规则。远程服务、商店登记及已安装包的名称采用需要对应发布证据。

## 概念与规则

1. 默认品牌字标、系统应用展示名和公开网页元信息使用Kastention。现有中文本地化文案中的应用称谓使用卡片结构，跟随原语言切换。保留`ink-language`及原英文回退规则。
2. 中文名称为应用称谓；Deck继续使用现有“思维模式”，Dream、Chat及各栏目名称沿当前定义。
3. 用户提供“取自德语词根”的命名意图；正式文案仅使用确定名称。具体词源及语言学含义需要独立核验。
4. 登录表单原有Welcome Back/Create Account与操作保持。浏览器标题和原生登录外层展示新名称。
5. 用户自行命名的Deck、账户、Thread和历史正文保留。新生成的分享图片及文件名采用新品牌，已经导出的文件保留。
6. 应用标识、签名、账户回调、数据存储、环境变量和域名保留。更名沿原升级流程交付，无新增确认或迁移入口。

## 页面骨架

桌面：

```text
┌ Kastention ───────────┬ 当前业务页（原内容与滚动范围） ┐
│ Chat / Dream / Decks  │ 原输入、历史、工具与操作        │
│ 更多 → 设置 → 关于    │ 关于：Kastention、原介绍及链接  │
│ 原账户 / 语言 / 主题  │ 原弹窗关系与反馈                │
└──────────────────────┴────────────────────────────────┘
登录：原登录卡与表单；浏览器标题采用Kastention。
```

窄屏：

```text
┌ Kastention / 当前栏目 ┐     ┌ 准备页 ──────────────┐
│ 原页面内容纵向滚动    │     │ 原启动插画            │
│ 设置 → 关于           │     │ Kastention            │
│ 关于正文纵向滚动      │     │                       │
│ 原弹窗覆盖当前页面    │     │ 原状态 / 开发者控制页  │
├ Chat / Decks / 更多 ──┤     └───────────────────────┘
└──────────────────────┘
```

名称保持完整单词和原文字样式；关于页允许在原内容区域自然排版，保留纵向滚动。窄屏、短屏和标题栏检查裁切、横向溢出及操作入口；无障碍应用标签使用完整名称。
