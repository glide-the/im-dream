# 聊天图像生成与编辑

状态：上一轮父会话完成实际稿独立评审、五项修订与技术重验，回执见[原执行记录](../../exec/image-generation-design-20261007.md)。本轮仅补充两种API的接口调查和正式稿Provider边界，文档检查见[补充执行记录](../../exec/codex-image-call-comparison-20261007.md)。当前Codex图像界面未观察，不能声明交互完全一致。已有图片显示能力与新增生成能力分别记录。

## 背景与问题

用户希望像 Codex 一样在会话中提出图片需求，由 Agent 调用 Tool，等待后直接看到图片，并继续修改。Dream 已能显示 Thread 文件图片，但没有完整图像生成 Tool；Claude Code 通用扩展并不自动提供图像 Provider。调查依据见[源码研究](../../design/claude-agent/image-generation-source-research.md)。

## 目标与边界

- 在现有 Chat 中完成文字生成图片、以明确参考图编辑、等待、查看、下载、重新打开及继续引用。
- 复用发送/停止、Tool 过程、Markdown 图片、全屏查看器、Workspace 文件访问、Admin 消息持久化；不新增页面、栏目、任务中心或额外确认弹窗。现有权限策略要求授权时，使用原 ToolConfirmationDock 批准/拒绝，不为新图像 Tool 增加自动放行规则。
- 首期采用现有 Thread files。Workspace Mode 未开启、当前线程文件不可访问或 Admin 图像能力缺失时，明确反馈当前不能生成，不自动修改设置或用 SVG/text 假装成功。此边界来自现有文件访问合同，不是新增产品配额。
- 不设计局部遮罩、画布、批量画廊、实时 partial preview、精确尺寸保证、跨线程图片引用、云端永久图床或后台生成任务。
- 新功能尚未实现；本次仅产品/交互设计与现有能力技术检查。真实业务验收需功能完成、指定账户/模型/实体及正常业务服务。

## 概念与规则

| 对象 | 具体规则 |
|---|---|
| 图像需求 | 用户在原输入框描述内容；带参考图时明确编辑对象与修改要求。没有专门的“生成确认”。 |
| 图像 Tool | 建议 `mcp__image__generate`，未实现；Agent 根据请求调用。服务器选择已授权 Provider，浏览器和模型不能提交 Provider Secret、用户 ID、Thread ID 或绝对路径。 |
| 工具授权 | Tool 输入可用仅说明调用已登记，不能证明已获准或 Provider 已开始。依现有策略显示原等待授权、批准、拒绝与停止反馈；没有实际开始事件时显示“图片调用处理中”。 |
| 已生成图片 | Provider 返回有效图片且文件发布成功才成立；工具返回文本描述但没有图片字节时显示失败。 |
| 图片引用 | 同 Thread 的 `workspace://files/...`；消息保存引用，文件保存字节；blob 只用于当前页面。 |
| 图片显示 | final Markdown 使用已有 WorkspaceImage；Tool 成功但缺少图片引用时，建议 Service 补齐同轮图片引用，避免结果仅藏在折叠过程。 |
| 再次生成 | 用户再次发送需求会产生新调用和新文件；不覆盖已有结果，不自动重试可能已收费的请求。 |
| 再次加载 | 只重新读取已有图片，不调用图像 Provider，不产生新的生成费用。 |
| 停止 | 原停止操作作用于当前 Agent turn；系统停止本地等待和自有请求，不能承诺已撤销 Provider 工作或费用。已完成图片保留。 |
| 保存 | 图片返回成功时保存在当前 Thread 文件；“下载”把该文件下载到本机。没有二次保存到收藏或全局相册。 |

配置的默认来源、当前可用能力和实际选中 Provider 由现有服务器配置和 Admin catalog 决定；不新增 `default/desired/effective/revision` 管理页面。若未来新增可写资源策略，则另行遵循仓库配置状态合同。

上游可采用Image API直接图片请求或Responses内置图像工具，按已授权、发布的能力选一种；两种方案都保持上述用户流程，不增加“接口方案”栏目、选择器或确认弹窗。Claude CLI不会仅因配置Key而具备Responses图像工具。接口依据与Codex未知边界见[两种API/完整调用对比](../../design/claude-agent/codex-image-generation-call-comparison.md)，实施职责与可选验收由[正式设计§13](../../design/claude-agent/image-generation-interaction-design.md)所有。

## 用户入口与完整使用流程

1. 打开现有会话，输入图片描述，必要时沿用已有附件入口上传参考图。Agent 明确当前 Thread 中参考图；多张图片不能确定时仅询问对象。
2. Agent 调用图像 Tool，原过程区显示“图片调用处理中”，原输入框保留停止入口。若权限策略要求批准，原授权区显示“等待工具授权”，批准后继续处理；拒绝则结束该调用，不请求 Provider。没有 Provider 开始/百分比事件时不显示“正在生成”或伪进度。友好动作名称与状态映射是必要的小改动，尚未实现。
3. Tool 校验、请求和文件保存成功，Agent 在回复中引用图片；Service 的建议补齐机制覆盖只有 Tool 结果或漏写引用的情况。
4. 图片在回复中加载，点击图片或放大入口打开共享查看器，可缩放、下载、关闭。关闭回到原滚动位置和触发按钮。
5. 用户在输入框继续描述修改，引用刚生成的图片；以新调用和新文件完成编辑。重新打开会话通过历史 Markdown 和同 Thread 文件恢复图片。
6. 生成或解析失败保留原需求，用户可重新发送；图片读取失败按原文件错误反馈，“重新加载”只读文件。连接中断先恢复会话和运行状态，避免自动重复生成。

用户正文不展示调用 ID、磁盘路径、Schema、模型缓冲区或技术容量。缺少能力时提示“当前无法生成图片”；Workspace 关闭时提示“当前会话未启用工作空间”，不额外弹确认框。

## 状态与反馈

Tool 调用处理/授权状态、图片文件加载状态和会话运行/保存状态分别沿用原所有者；不能把“工具调用成功”“图片加载成功”和“消息已保存”混成同一个完成承诺。未注册图像能力时显示能力不可用，没有发生 Tool 调用。正式稿给出触发条件与异常路径。只有 Provider 返回并保存文件、消息中存在可恢复引用，才满足正常生成流程；下载是独立操作。

## 验收要求与追踪

| 需求 | 设计位置 | 实现状态 | 后续验收 |
|---|---|---|---|
| 文本生成、状态反馈 | 正式稿正常流程、协议、状态表 | Tool/Provider 未实现；通用过程已存在 | 从公开 POST /api/claude-agent 到有效文件与图片引用。 |
| 上传参考图、继续编辑 | 正式稿参考图授权与后续引用 | 图片附件已存在，编辑适配未实现 | 读取指定参考图、传入 Provider、新文件保留原图。 |
| 查看、下载、窄屏 | 本文骨架；正式稿结果交互 | WorkspaceImage 已存在 | 适配、焦点、Escape、缩放、下载及读取失败恢复。 |
| 历史恢复、仅 Tool 结束 | 正式稿引用补齐与持久化 | 原历史已存在；引用补齐未实现 | 刷新与重开不依赖过程展开或 Provider 重新执行。 |
| 停止、断线、重试 | 正式稿异常与恢复 | 原 turn 语义已存在；Provider 边界未实现 | 停止不伪称退款，断线恢复不重复调用，加载重试不生成。 |
| 既有权限与友好动作 | 正式稿调用/授权状态和界面名称 | 原授权区已存在；图像名称/状态映射未实现 | 等待/批准/拒绝/等待时停止；授权前无 Provider 请求；不展示原始图像 toolName。 |
| 同 Thread 文件权限 | 正式稿职责与文件规则 | 原读取已存在；生成写入待补齐 | 其他用户或其他 Thread/遍历/符号链接/关闭 Workspace/缺能力全部拒绝。 |

上表最后一行中的权限验收对象为其他用户或其他 Thread；以具体身份和路径判定，不增加概念标签。完整矩阵见[正式交互设计](../../design/claude-agent/image-generation-interaction-design.md)。
