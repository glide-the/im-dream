# Ink & Memory 定时任务 PRD 草案

> 参考图展示了一个桌面双栏工作区：左侧 Chat 中嵌入带时钟图标的任务卡，右侧为任务详情和频率配置。红色矩形是图片标注，不属于产品界面。本文在该视觉结构上补齐单次、每天和间隔三类规则，以及运行历史、会话入口和定时会话工具审批规则。

## 1. 背景与问题

用户会在 Chat 中用自然语言提出“明天 9 点提醒我”“每天 18 点整理当天日记”“每 10 分钟检查一次进展”等要求。系统需要把自然语言请求转为可查看、可编辑、可恢复的持久化任务，并让用户在原对话中确认任务已经建立。

当前需要解决四个连续问题：

1. 创建结果需要在产生它的 Chat turn 内留下稳定标记，刷新后仍能找到任务。
2. 用户需要在不离开当前 Chat 的情况下查看计划、修改间隔并判断修改是否已经生效。
3. 每次定时执行都要产生独立的 TaskSession、Thread 和 Turn 记录，供用户从任务详情回看真实执行过程。
4. 定时启动的会话没有用户守在输入框前，必须由服务端逐工具决定自动执行或等待确认，且目标笔记身份缺失时不能写到其他笔记。

## 2. 目标与边界

### 2.1 产品目标

- 支持单次指定时间、每天固定时间、每隔 N 分钟三种规则；首期重点保证“每 10 分钟”的创建、编辑、恢复和展示完整可用。
- 自然语言创建成功后，在对应 assistant turn 中显示任务标记卡；点击后打开当前任务的右侧详情。
- 详情提供计划摘要、可编辑表单、当前生效状态、下次运行、最近运行结果和执行会话入口。
- 服务重启后根据 Admin PostgreSQL 中持久化的 `next_run_at` 恢复 interval 调度。
- 同一任务始终只有一个 open trigger，避免相邻到期点产生并发重复执行。
- 定时会话使用服务端拥有的逐工具审批策略；普通交互会话继续使用既有 `tool_choice=auto/manual/none` 和前端确认规则。

### 2.2 本期包含

- Chat 自然语言创建任务后的任务卡和右侧详情入口。
- 任务详情中的查看与编辑：标题、运行目标、规则类型、日期/时间、`interval_minutes`、通知级别。
- 日历任务区中的计划列表、任务卡、最新运行结果、运行历史与 Thread 入口。
- desired、effective、revision 与应用状态的可见反馈。
- trigger 去重、跳过区间、服务重启恢复和定时会话逐工具审批规则。
- 桌面和窄屏布局、滚动范围、加载/空态/错误/恢复动作。

### 2.3 本期不包含

- 每周、每月、cron 表达式、节假日规则和按执行结束时间漂移的周期。
- 通过新增 Dream HTTP、消息队列、restart、kill 或 shell 控制通道驱动调度。
- 从浏览器参数、任务提示词、Deck、Plugin、workspace 或用户环境变量覆盖服务端审批策略。
- 因授权失败而改写其他笔记、扩大权限或选择“最近打开的笔记”。
- 把调度器内部 claim、lease、数据库字段或错误堆栈直接展示给用户。

## 3. 概念与规则

### 3.1 核心对象

| 概念 | 程序含义 | 页面用途 |
| --- | --- | --- |
| ScheduledTask | 持久化任务定义，包含标题、prompt、运行目标、规则、revision 和状态 | 任务卡与详情的主对象 |
| default | 未建立任务时的产品初始态 | 不提供隐含调度值；必须由自然语言解析结果或表单选择形成完整规则。间隔输入框可用“例如 10”作占位，但占位不是提交值 |
| desired | 用户最近一次保存并写入 Admin PostgreSQL 的任务定义与 revision | 编辑保存成功后的目标配置 |
| effective | Dream 调度器当前已读取并用于后续到期判断的配置与 revision | 页面判断“已应用”的依据 |
| revision | 每次有效保存后递增的任务配置版本 | desired 与 effective 的对应键 |
| ScheduledTrigger | 单次到期处理记录 | 表示本次运行、跳过或失败，并关联 TaskSession |
| open trigger | 状态为 `claimed`、`queued`、`running` 或 `state_unknown` 的 trigger | 同一任务同时最多一个 |
| TaskSession / Thread / Turn | 某次 scheduled trigger 新建的独立执行记录 | 历史行和会话入口 |

### 3.2 三类调度规则

| 规则 | 必填输入 | 计划摘要 | 校验与计算 |
| --- | --- | --- | --- |
| 单次指定时间 | 日期、当地时间、IANA 时区 | `2026-10-08 09:00 · Asia/Shanghai` | 必须形成一个有效未来时间；完成后不再生成下一到期点 |
| 每天固定时间 | 当地时间、IANA 时区 | `每天 09:00 · Asia/Shanghai` | 每个当地日计算一次；夏令时处理由调度层统一定义，页面展示真实下一运行时间 |
| 每隔 N 分钟 | `interval_minutes`、IANA 时区 | `每 10 分钟` | `interval_minutes` 必须为正整数；首期可快捷选择 10，但不得把 10 写成所有任务的隐含默认 |

### 3.3 desired、effective 与应用状态

1. 用户保存编辑后，Admin 只写 desired 并生成更高 revision；页面先显示“正在应用”。
2. 只有 fresh snapshot 的 revision 与该规则全部适用字段都匹配 desired，页面才显示“已应用”。不适用字段保持空值，不能用 0 代替。
3. 同 revision 且值相同只刷新 diagnostics；同 revision 值不同或 revision 回滚显示“配置异常”，保留 last-known-good effective。
4. desired 非法、PostgreSQL/capability 不可用或后台同步异常时，保存或应用失败应有可行动反馈；既有 effective 和 revision 继续运行。
5. 页面同时展示“已保存的计划”和“当前生效计划”仅限两者不一致时；一致时合并为一行，减少重复信息。

### 3.4 interval 持久化与不并发规则

1. `interval_minutes` 为正整数；空值、0、负数、小数、非数字和超出后端安全边界的值均不能保存。
2. interval 以持久化 `next_run_at` 为调度游标。服务重启后从 Admin PostgreSQL 读取该值恢复，不以进程启动时间重新起算。
3. 到期时先判断同一任务是否已有 open trigger。没有时创建新的 scheduled trigger，并为它新建 TaskSession、Thread 和 Turn；有时不创建第二个执行实例。
4. 上一次仍处于 `claimed`、`queued`、`running` 或 `state_unknown` 时，新到期点合并记录为 skipped 范围，包含首个和最后一个被跳过的到期时间及数量。
5. open trigger 结束后，后续到期点按已经推进的 `next_run_at` 继续，不因上次耗时而把周期改成“完成后再等 N 分钟”。
6. 更新 interval 只影响保存成功后的后续到期点和新 acquire；不改变既有 lease，也不重写已经产生的 trigger。

### 3.5 scheduled trigger 的真实执行记录

- 每个实际启动的 scheduled trigger 都新建 TaskSession、Thread 和 Turn，并执行真实 Claude Agent 生产入口。
- 详情历史以 trigger 为一行；有 `target_thread_id` 时提供“打开会话”，不得通过标题或最近访问记录猜测 Thread。
- skipped 范围是一条非会话历史记录，展示“因上一次仍在运行，已跳过 X 次”及起止时间，不伪造 TaskSession。
- `state_unknown` 仍占用 open trigger；在状态被服务端解析前不得并发补跑。

### 3.6 定时会话的工具暴露与审批

工具是否暴露由 `tools/allowed_tools` 决定，是否需要确认由服务端 approval policy 决定。两者是两个独立判断，页面文案和任务 prompt 不能把“可见”解释为“自动批准”。

| 工具或工具类别 | 定时会话审批 | 结果行为 |
| --- | --- | --- |
| `mcp__editor__write_segment` | auto | 工具已暴露且目标 Editor Session 身份、权限、调用 ID 匹配时自动执行 |
| `mcp__editor__insert_widget` | auto | 与上项相同，校验失败则写入失败并记录错误 |
| `mcp__editor__delete_segment` | manual | 创建待确认状态，不自动删除 |
| `mcp__editor__reply_to_comment` | manual | 创建待确认状态，不自动回复 |
| `AskUserQuestion` | manual | 等待用户在执行会话中处理，不把缺失回答改成默认答案 |
| `mcp__user__ask_user` | manual | 等待用户处理，并在任务详情显示“需要操作” |
| `Bash` | manual | 不因定时启动而自动执行 |
| 外部 MCP 写操作 | manual | 维持人工确认；只读工具仍按服务端枚举判断 |

- 普通交互会话完全沿用既有 `tool_choice=auto/manual/none` 与前端确认规则。
- 定时会话审批枚举由服务端拥有；浏览器、本地设置和任务 prompt 不得覆盖。
- 目标笔记或 Editor Session 身份缺失、授权失效、调用 ID 不匹配时，编辑器写入必须失败，历史记录可行动错误；不得扩大权限、寻找同名笔记或降级到其他笔记。

## 6. 详细功能需求

### 6.1 自然语言创建与 Chat 任务标记

1. assistant 通过真实创建结果取得 task ID 后，在该 turn 的正文之后插入 A3；仅在正文提到“已创建”不能生成任务卡。
2. 卡片标题来自任务定义；副标题显示规则摘要与当前应用状态，例如“每 10 分钟 · 已应用”或“每天 09:00 · 正在应用”。
3. 同一 turn 创建多个任务时，按 Tool result 顺序展示多张卡；每张卡绑定自己的 task ID。
4. 整卡是一个点击面，“打开”只作视觉提示，避免嵌套按钮。
5. 刷新后从持久化消息/Tool part 恢复相同卡片和 task ID，不依赖助手正文解析。
6. 创建失败时保留 Tool 错误和可重试入口，不显示伪成功任务卡。

### 6.2 详情查看与 interval 编辑

1. 点击任务卡或日历卡的“详情”后读取当前 task、effective snapshot 和 history，再打开 B1-B7。
2. 默认显示详情态；点击“重复”“每隔”“时区”等行进入内联编辑。产生修改后，B7 显示“取消”和“保存”。
3. 规则改为“间隔”时显示整数输入和分钟单位；输入框允许直接键入，也提供 10 分钟快捷项。快捷项只是当前选择。
4. 切换规则时只显示该规则需要的字段：单次显示日期、时间、时区；每天显示时间、时区；间隔显示 `interval_minutes` 和时区。
5. 保存前执行字段级校验；错误贴近字段显示，并保留用户输入。合法保存不增加确认弹窗。
6. 保存成功后显示 desired，并等待 effective；匹配后状态改为“已应用”。同步失败时显示“仍按上一版计划运行”和重试入口。
7. 点击取消恢复打开详情时的服务端值；若服务端已出现更高 revision，则重新读取并提示“任务已在其他位置更新”。
8. 编辑期间新到达的运行历史可追加，但不能覆盖未保存字段。

### 6.3 运行历史与会话入口

1. 历史默认展示最近结果，按到期时间倒序；用户可继续加载更早记录。
2. 实际执行行显示状态、计划时间、开始/结束时间和简短结果；有 target Thread 时整行或“打开”按钮进入精确 `target_thread_id`。
3. `queued`/`running` 显示进行中；`state_unknown` 显示“状态待确认”，并继续占用 open trigger。
4. manual 工具等待确认时显示“需要操作”，点击进入对应执行 Thread 完成确认。
5. skipped 范围显示起止到期时间和跳过次数，不提供会话入口。
6. 执行失败展示可行动摘要，例如“目标笔记授权已失效，请重新授权后重试”；不展示内部堆栈，也不自动更换目标。

### 6.4 任务表单中的“运行于”和通知

- “运行于”展示任务绑定的目标笔记或 Editor Session；缺失或不可访问时显示明确错误并阻止需要写入的执行。
- 更换运行目标必须经过现有身份认证与权限校验；不能仅凭名称匹配。
- 通知选项决定用户在哪类结果变化时收到提醒。首期至少支持“重要更新”，包括执行失败、需要手动批准、授权失效和状态异常。
- 通知配置不改变 trigger 状态，也不能代替运行历史。

## 7. 状态与恢复

### 7.1 配置状态

| 状态 | 进入条件 | 页面反馈 | 恢复动作 |
| --- | --- | --- | --- |
| 查看中 | desired 与 effective 一致 | “已应用”及下次运行 | 可进入编辑 |
| 编辑中 | 用户修改任一表单字段 | 显示取消/保存和未保存标记 | 保存或取消 |
| 保存中 | 已提交合法表单 | 禁用重复提交，保留输入 | 等待保存结果 |
| 正在应用 | desired 已保存，effective 尚未匹配 | 同时显示新计划与“上一版仍在运行” | 自动刷新状态；可重试读取 |
| 已应用 | fresh effective 的 revision 与四项值均匹配 desired | 合并显示一份计划 | 无需操作 |
| 保存失败 | Admin 写入失败或 capability 不可用 | 字段/表单级错误，effective 不变 | 修正后重试 |
| 配置异常 | 同 revision 异值、revision 回滚或 snapshot 不合法 | “配置异常，仍按上一版计划运行” | 重试读取或查看诊断 |

### 7.2 运行状态

| trigger 状态 | 用户文案 | 是否占用 open trigger | 会话入口 |
| --- | --- | --- | --- |
| `claimed` | 正在准备 | 是 | Thread 建立后提供 |
| `queued` | 等待执行 | 是 | 有 target Thread 时提供 |
| `running` | 正在运行 | 是 | 提供 |
| `state_unknown` | 状态待确认 | 是 | 有 target Thread 时提供 |
| `running` 或 `state_unknown`，且存在待确认工具 | 需要操作 | 是 | 提供并定位到待确认项 |
| succeeded | 已完成 | 否 | 提供 |
| failed | 失败 | 否 | 有记录时提供 |
| skipped range | 已跳过 X 次 | 否；它不是独立执行 | 不提供 |

### 7.3 页面失败与空态

| 场景 | 页面表现 | 允许动作 | 禁止行为 |
| --- | --- | --- | --- |
| 详情加载中 | 先打开详情壳，分组显示浅色占位 | 关闭详情 | 阻断 Chat 输入 |
| task 不存在或无权限 | 显示“任务不存在或当前不可访问” | 关闭、重试 | 猜测另一个 task |
| history 读取失败 | 任务表单仍可用，历史区局部报错 | 重试历史 | 关闭整个详情 |
| 尚未运行 | “尚无运行记录”，保留下次运行 | 返回 Chat | 把空态写成成功 |
| 目标身份缺失 | “目标笔记身份缺失，写入未执行” | 打开设置或重新授权 | 写入其他笔记 |
| 服务重启恢复 | 读取持久化 `next_run_at` 后显示真实下次运行 | 等待或查看历史 | 从当前时间重新起算 |
| open trigger 跨过新到期点 | 追加 skipped 范围 | 打开仍在运行的会话 | 并发创建第二个执行 |

## 8. 视觉与交互要求

- 页面底色为近白纸张色，卡片为白色或极浅灰；边框使用低对比暖灰，主文字为深灰黑，次级文字为中灰。具体色值映射现有语义 token，不新增业务硬编码颜色。
- 任务卡使用约 16–20px 视觉圆角、1px 细边和充足留白；时钟放在独立浅灰圆角方块内。尺寸由现有组件 token 控制。
- 右侧表单使用分组行：左侧标签、右侧当前值与下拉箭头；“每隔 10 分钟”一行中数字输入是主要焦点。
- 红色框线只存在于参考图标注，不进入实现。
- 标题过长时单行省略，完整标题在详情顶栏可换行或通过可访问名称读取；prompt 正文保留换行。
- 所有状态必须同时有文字，不能只靠颜色。点击目标、焦点环、键盘顺序和对比度沿用项目现有无障碍标准。
- 详情打开后焦点移到标题或首个可编辑字段；关闭后回到原任务卡。窄屏返回手势与“返回”按钮行为一致。

## 9. 技术实现建议（建议，未声明已实现）

1. 复用现有 Chat message/Tool part 渲染、右侧栏容器、Thread 导航、任务卡、表单行和历史列表组件，再补 scheduled-task view model；不要复制 SSE、reducer 或 runtime。
2. 前端以 task ID 获取详情，以 revision 做并发编辑检查；视图分别保留 desired 和 effective，不在浏览器推断“已应用”。
3. Admin PostgreSQL 负责 desired、revision 和 `next_run_at` 持久化；Dream 通过独立 provider/composition root 读取并应用，缺少 capability 时 fail closed。
4. 调度器原子判断 open trigger、创建 trigger 并推进 `next_run_at`；skipped 范围由服务端记录，前端只显示结果。
5. scheduled trigger 通过公开生产入口创建 TaskSession、Thread、Turn；历史导航只使用该 trigger 的精确 `target_thread_id`。
6. `tools/allowed_tools` 和 approval policy 使用不同字段、不同校验路径；approval policy 是 immutable server-owned snapshot，随定时会话传入，不能由任务内容覆盖。
7. HTML 设计阶段可使用语义化 HTML 与 Tailwind CSS 2.2.19 表达布局；生产实现需映射仓库现有组件和设计 token。

## 10. 验收标准

### 10.1 创建、标记与详情

- [ ] 自然语言创建成功后，任务卡出现在对应 assistant turn 内；刷新后仍绑定同一 task ID。
- [ ] 卡片展示标题、真实规则摘要和应用状态；点击后在桌面右侧或窄屏全高抽屉打开详情。
- [ ] 创建失败、结果缺 task ID 或正文只是提到任务时，不生成成功卡。
- [ ] 日历任务区展示计划、下次运行、最新结果和详情入口。

### 10.2 规则与编辑

- [ ] 单次、每天和间隔三类表单只显示各自必填字段。
- [ ] `interval_minutes=10` 可创建和编辑；空值、0、负数、小数和非数字不能保存。
- [ ] 保存不增加确认弹窗；desired 保存后显示正在应用，fresh effective 的 revision 与该规则全部适用字段一致后才显示已应用。
- [ ] 保存或同步失败时保留 last-known-good effective，并给出重试动作。
- [ ] 服务重启后按 PostgreSQL 的 `next_run_at` 恢复，页面不把重启时间显示为新起点。

### 10.3 去重、历史与会话

- [ ] 同一任务同时最多一个 `claimed`/`queued`/`running`/`state_unknown` trigger。
- [ ] open trigger 存在时，新到期点被记录为 skipped 范围，不新建并发 TaskSession。
- [ ] 每个实际启动的 scheduled trigger 都有新的 TaskSession、Thread 和 Turn，并走真实 Claude Agent 生产入口。
- [ ] 历史实际执行行打开自己的精确 target Thread；skipped 范围不显示伪会话入口。
- [ ] trigger 处于 `running` 或 `state_unknown` 且有待确认工具时显示“需要操作”，用户可进入对应会话处理。

### 10.4 工具审批与权限

- [ ] `mcp__editor__write_segment`、`mcp__editor__insert_widget` 在工具已暴露且身份/权限校验通过时按 auto 执行。
- [ ] `mcp__editor__delete_segment`、`mcp__editor__reply_to_comment`、`AskUserQuestion`、`mcp__user__ask_user`、`Bash` 和外部 MCP 写操作维持 manual。
- [ ] 工具未出现在 `tools/allowed_tools` 时，即使 approval policy 为 auto 也不能调用。
- [ ] 浏览器设置和任务 prompt 不能覆盖服务端审批策略。
- [ ] 目标笔记/Editor Session 身份缺失、授权失效或调用 ID 不匹配时写入失败，并记录可行动错误；不会扩大权限或改写其他笔记。

### 10.5 响应式与回归

- [ ] 桌面 Chat 与详情并列且各自滚动；Chat 顶栏/输入区、详情顶栏/保存栏保持可见。
- [ ] 窄屏任务详情为全高抽屉或页面；任务表单、任务卡、运行历史和滚动范围均清晰可见。
- [ ] 长 prompt、长标题和长历史不产生页面级横向滚动。
- [ ] 普通交互会话继续执行既有 `tool_choice=auto/manual/none`、前端确认、SSE、turn/resume/cancel 语义。
