# Ink & Memory 定时任务页面层级逻辑

## 1. 结构结论与编号规则

参考图的核心关系是“Chat 中创建并留下任务标记，详情在同一工作区打开”。红色框线是图片标注，不属于产品界面。桌面采用 Chat 与任务详情并列结构；窄屏按 Chat、任务详情、执行会话三个全高页面逐级进入。日历任务区是另一条任务详情入口，不嵌入 Chat 层级。

本文统一使用以下编号，解决前序草图中 `C1` 同时指代“日历任务区”和“执行会话”的冲突：

| 前缀 | 所属层 | 含义 |
| --- | --- | --- |
| `V` | 产品界面 | 桌面视口与桌面布局容器 |
| `M` | 产品界面 | 窄屏视口与窄屏页面容器 |
| `A` | 产品界面 | Chat 主区及自然语言创建入口 |
| `B` | 产品界面 | 定时任务详情、编辑和运行历史 |
| `C` | 产品界面 | 某次真实执行对应的 Thread 页面 |
| `D` | 产品界面 | 日历中的计划任务入口 |
| `S` | 后端业务 | 不直接作为页面模块展示的持久化、调度、执行和审批状态 |

文中的边界标记含义：

- **【界面】**：用户能够看到、操作或进入的页面模块。
- **【界面状态】**：由服务端事实投影出的用户文案和可行动反馈。
- **【后端】**：只在服务端参与判断、持久化或执行，不直接作为控件或技术文案展示。

桌面层级与滚动规则：

1. `V0` 只负责并列容纳 `A0` 和 `B0`，页面外层不产生纵向或横向滚动。
2. `A1`、`A4` 固定，只有 `A2` 在 `L1` 内滚动；打开或关闭详情时保留阅读位置。
3. `B1`、`B7` 固定，`B2 → B4 → B3 → B5` 组成 `B8` 的连续内容流；`B5` 不再产生嵌套滚动条。
4. 点击 `A3` 以卡片绑定的精确 task ID 打开 `B0`。关闭 `B0` 后焦点回到原 `A3`。
5. 点击 `B6` 以该历史行的精确 `target_thread_id` 打开 `C0`；返回详情时恢复 `R1` 的滚动位置。

窄屏层级与滚动规则：

1. `M0`、`M2`、`C0` 是逐级覆盖或路由进入的全高页面，不并排压缩。
2. `M0` 只有 `A2` 在 `M1` 内滚动；`M2` 只有 `B8` 在 `M3` 内滚动。
3. 表单、状态和历史共用 `M3`，避免表单或历史产生第二层滚动。
4. 从 `C0` 返回 `M2` 时恢复 `M3` 的位置；从 `M2` 返回 `M0` 时恢复 `M1` 的位置并将焦点放回原 `A3`。
5. 长标题单行省略，prompt 和历史摘要在容器内换行；任何层级都不产生页面级横向滚动。

## 4. 关键业务路径与界面投影

### 4.1 自然语言创建任务

```text
A4 用户输入自然语言计划
  → A2.1 形成用户消息
  → S1【后端】解析并校验标题、prompt、运行目标、规则和时区
      ├─ 校验失败 → A2.3 显示错误与重试；不生成 A3
      └─ 校验成功 → S2【后端】持久化 ScheduledTask、desired、revision、next_run_at
                       → 创建结果返回真实 task ID
                       → A2.2 保留 Tool result
                       → A3 按 Tool result 顺序显示任务标记卡
                       → 用户点击 A3 → B0 / M2 按该 task ID 加载详情
```

同一 turn 创建多个任务时，每个成功结果各生成一张 `A3`，顺序与 Tool result 一致。页面刷新后从持久化消息或 Tool part 恢复 task ID，不从 assistant 自然语言正文猜测任务。

### 4.2 “每隔 N 分钟”查看与编辑

```text
B3.2 选择“间隔”
  → 只展开 B3.3c interval_minutes 与 B3.4 IANA 时区
  → B3.3c 接受正整数；“10 分钟”可作为快捷项，不作为隐含默认值
  → B7.2 保存
      ├─ 字段非法 → B3.6 贴近字段显示错误；保留输入；不提交
      └─ 字段合法 → S2【后端】只写新的 desired 并递增 revision
                       → B4 显示“正在应用”，必要时并列显示新计划与上一版计划
                       → S3【后端】Dream 读取 fresh snapshot
                           ├─ revision 与全部适用字段匹配 → B4“已应用”
                           ├─ 同 revision 异值 / revision 回滚 / snapshot 非法
                           │   → 保留 last-known-good effective
                           │   → B4“配置异常，仍按上一版计划运行”
                           └─ PostgreSQL / capability / 同步不可用
                               → 保留 last-known-good effective
                               → B4 显示可行动错误与重试
```

`interval_minutes` 的空值、0、负数、小数、非数字和超出服务端安全边界的值均不能保存。持久化 `next_run_at` 是 interval 的调度游标；服务重启后恢复该值，页面展示恢复后的真实下次运行时间。更新间隔只影响保存后的到期点和新 acquire，不改变既有 lease 或历史记录。

### 4.3 到期、运行历史与 Thread 入口

```text
S4【后端】next_run_at 到期
  → 判断同一 ScheduledTask 是否已有 open trigger
      ├─ 没有
      │   → 创建 ScheduledTrigger
      │   → S5【后端】新建 TaskSession、Thread、Turn
      │   → 走真实 Claude Agent 生产入口
      │   → B5.1 显示本次真实执行行
      │   → 有 target_thread_id 时显示 B6
      │       → 点击 B6 → C0 打开该次执行的精确 Thread
      └─ 已有 claimed / queued / running / state_unknown
          → 不创建第二个执行实例
          → 合并记录 skipped 范围的首末到期时间与数量
          → B5.3 显示“已跳过 X 次”且不显示 B6
```

`state_unknown` 继续占用 open trigger。若实际执行在等待 manual 工具确认，`B5` 将该行投影为“需要操作”，用户通过 `B6` 进入 `C0` 处理；详情页不复制一套确认弹窗。

## 5. 产品界面状态与后端状态边界

### 5.1 配置状态映射

| 后端事实【不直接展示】 | 产品界面状态 | 所属模块 | 用户动作 |
| --- | --- | --- | --- |
| desired 与 fresh effective 的 revision、规则类型及全部适用字段相同 | 已应用 | A3.4、B4 | 查看或进入编辑 |
| 新 desired 已持久化，effective 尚未匹配 | 正在应用；上一版仍在运行 | A3.4、B4 | 自动刷新或重试读取 |
| Admin 写入失败或 capability 不可用 | 保存失败；当前计划保持不变 | B3.6、B4 | 修正后重试 |
| 同 revision 异值、revision 回滚或 snapshot 非法 | 配置异常；仍按上一版计划运行 | B4 | 重试读取或查看可行动诊断 |
| 持久化 `next_run_at` 在服务重启后被重新读取 | 显示真实下次运行时间 | B4、D2 | 等待或查看历史 |

页面不展示“fresh snapshot”“last-known-good”“revision 回滚”等内部名词作为主状态；页面使用上表中的具体影响与恢复动作。revision 仅在诊断需要时提供，不进入普通卡片。

### 5.2 运行状态映射

| 后端 trigger / 执行事实【不直接作为页面结构】 | 产品界面文案 | 是否占用 open trigger | B6 Thread 入口 |
| --- | --- | --- | --- |
| `claimed` | 正在准备 | 是 | Thread 建立后显示 |
| `queued` | 等待执行 | 是 | 有 `target_thread_id` 时显示 |
| `running` | 正在运行 | 是 | 显示 |
| `state_unknown` | 状态待确认 | 是 | 有 `target_thread_id` 时显示 |
| `running` / `state_unknown` 且有 manual 工具待处理 | 需要操作 | 是 | 显示并进入待确认项 |
| `succeeded` | 已完成 | 否 | 显示 |
| `failed` | 失败，并附可行动摘要 | 否 | 有执行记录时显示 |
| skipped range | 已跳过 X 次，并显示首末到期时间 | 否；不是一次独立执行 | 不显示 |

claim、lease、数据库字段和内部错误堆栈不进入页面。目标笔记身份缺失、授权失效或调用 ID 不匹配时，页面显示具体失败原因与重新授权或打开设置动作；系统不扩大权限、不寻找同名笔记，也不改写其他笔记。

## 6. 服务端逐工具审批枚举与页面关系

### 6.1 判断顺序

```text
S5【后端】创建定时执行会话
  → S6.1 tools/allowed_tools 判断工具是否暴露
      ├─ 未暴露 → 工具不可调用；approval policy 不改变此结果
      └─ 已暴露 → S6.2 读取 immutable server-owned approval policy snapshot
                     ├─ auto   → 继续身份认证、权限校验、schema 校验和调用 ID 匹配
                     │            ├─ 全部通过 → 执行工具并记录结果
                     │            └─ 任一失败 → 写入失败记录 → B5 显示可行动错误
                     └─ manual → 创建待确认项 → B5 显示“需要操作”
                                  → B6 打开 C0 → C2.2 使用现有确认交互处理
```

工具暴露与工具审批是两个独立判断。浏览器、本地设置、任务 prompt、Deck、Plugin、workspace 和用户环境变量都不能覆盖服务端审批枚举。普通交互会话继续沿用既有 `tool_choice=auto/manual/none` 和前端确认规则。

### 6.2 定时会话审批枚举

| 工具或类别 | 服务端审批值 | 后端行为 | 产品界面投影 |
| --- | --- | --- | --- |
| `mcp__editor__write_segment` | `auto` | 工具已暴露，且目标 Editor Session 身份、权限、schema、调用 ID 校验通过后执行 | 成功时进入正常结果；校验失败时 B5 显示可行动错误 |
| `mcp__editor__insert_widget` | `auto` | 同上 | 同上 |
| `mcp__editor__delete_segment` | `manual` | 创建待确认项，不自动删除 | B5“需要操作”；B6 进入 C2.2 |
| `mcp__editor__reply_to_comment` | `manual` | 创建待确认项，不自动回复 | B5“需要操作”；B6 进入 C2.2 |
| `AskUserQuestion` | `manual` | 等待用户回答，不生成默认答案 | B5“需要操作”；B6 进入 C2.2 |
| `mcp__user__ask_user` | `manual` | 等待用户处理 | B5“需要操作”；B6 进入 C2.2 |
| `Bash` | `manual` | 不因定时启动而自动执行 | B5“需要操作”；B6 进入 C2.2 |
| 外部 MCP 写操作 | `manual` | 维持人工确认 | B5“需要操作”；B6 进入 C2.2 |
| 只读工具 | 由服务端枚举决定 | 按对应服务端条目执行 | 页面只显示运行结果或可行动状态 |

任务详情中不增加“自动批准 / 手动批准”配置项。审批值是服务端运行策略，不是用户可编辑的任务字段；用户只在 `B5` 看见运行影响，并在 `C2.2` 处理需要确认的工具。

## 8. 逻辑一致性说明

1. `A3` 与 `D2` 是同一个 ScheduledTask 的两个入口，均按精确 task ID 打开 `B0 / M2`；它们不各自维护任务副本。
2. `B3` 编辑 desired，`B4` 展示 desired 与 effective 的关系；`B3` 不在浏览器内推断“已应用”。
3. `B5` 的一行对应一个真实 trigger 或一个 skipped 范围。实际 trigger 可关联 `B6`，skipped 范围永远没有伪造的 TaskSession 或 Thread。
4. `C0` 是真实执行会话页面。详情中的“需要操作”只是入口提示，实际 manual 工具确认仍在 `C2.2` 完成。
5. 后端 `S1–S6` 只向产品界面投影标题、规则摘要、应用结果、下次运行、历史状态、可行动错误和精确入口；内部调度术语不作为普通用户控件。
6. 参考图只明确展示了间隔规则和桌面双栏。本稿中的单次、每天、日历入口、运行历史和窄屏页面来自 PRD 业务要求，均以同一层级和编号体系补齐，不暗示参考图已经展示这些状态。
