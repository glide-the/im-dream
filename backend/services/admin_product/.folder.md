# backend/services/admin_product — Folder Contract

## Architecture Summary

Dream exposes same-origin Product BFF routes and validates their request/response
Pydantic DTOs. The shared Admin OAuth dependency supplies the canonical subject;
the Product client signs a short-lived, audience/scope-bound JWT for the existing
Admin Product API. Admin revalidates active canonical/platform identity and owns
all subscription, usage, model and payment persistence and transactions. Dream
does not open PostgreSQL and has no local Product data fallback.

## File Table

| File | Pos | Function |
|---|---|---|
| `config.py` | server configuration | Validate Admin Product origin, JWT and timeout settings. |
| `models.py` | DTO boundary | Define strict Product requests, results and safe error envelopes. |
| `token.py` | service credential | Issue short-lived subject/audience/scope-bound Product JWTs. |
| `client.py` | Admin HTTP client | Make one bounded, no-retry Product call and validate the response field firewall. |
| `service.py` | application service | Validate the Admin-authenticated decimal subject and preserve operation semantics. |
| `runtime.py` | composition root | Lazily construct and close the Admin HTTP client without database dependencies. |
| `errors.py` | safe error mapping | Preserve stable user-facing Product error codes and status. |
