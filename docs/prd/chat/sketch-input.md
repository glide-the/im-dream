# Chat 绘制草图

## 背景与问题

用户有时需要用几笔图形表达布局、位置或外观。上传现成图片无法代替现场画出想法。Chat 需要在输入框旁提供绘制入口，让用户把草图和文字一起交给 Agent。

## 目标与边界

完成“打开画布、绘制和修改、添加图片、发送消息”的连贯体验。草图是用户手画的输入附件；AI 生成或编辑图片属于[图像生成需求](image-generation.md)，由该模块另行交付。

本次提供画笔、橡皮、撤销、重做和清空。不提供文字排版、图层、协作画板、图片导入、选区编辑或画布作品管理。添加阶段将 PNG 暂存到现有附件存储，发送后才保存为会话消息；可编辑笔画仅在当前输入框中暂存，刷新页面、离开会话后不恢复。

## 概念与规则

- 草图：用户在画布中绘制的内容。画布使用白底黑线，深色界面仍保持相同图片内容。
- 添加：把草图变成图片并加入当前消息，不发送消息，不调用图像模型。
- 返回：关闭画布，保留当前输入框中的未添加草图。重新打开可继续画；没有放弃确认弹窗。
- 撤销和重做：逐次恢复笔画、擦除或清空操作。重新绘制会结束原来的重做分支。
- 发送：沿用现有 Chat 图片附件行为。上传完成前不能发送；发送失败恢复待发送的文字和附件。
- 上传失败：保留画布内容，用户可再次添加。空白画布不能添加：白底上已没有可见墨迹时，包括擦完最后一笔后，都视为空白。

## 功能描述与使用流程

| 功能 | 用户目的与功能描述 |
| --- | --- |
| 添加菜单 | 输入框的添加按钮提供“上传文件”和“绘制草图”，已有粘贴、拖拽和文件选择入口继续使用。 |
| 绘制画布 | 鼠标、触控笔和触摸均可绘制，橡皮可局部擦除。 |
| 修改草图 | 撤销、重做和清空帮助用户修正表达；关闭后可继续未添加的草图。 |
| 添加到消息 | 完成后显示为输入框中的图片附件；上传进度与其他图片一致。 |
| 发送与查看 | 可以只发送草图，也可以配文字或其他附件；发送后沿用图片消息的预览和历史查看。 |
| 继续讨论或生成图片 | 草图作为会话参考图片，用文字说明希望 Agent 分析、生成或修改的内容；图像生成与编辑沿用同一聊天中的图片工具。 |

用户打开添加菜单并选择绘制草图，画出想法并修正，点击添加到消息，等待图片上传完成，再输入说明并发送。上传失败时画布保留内容并提示重试；暂不添加时直接返回输入框。已添加图片不提供笔画编辑，需重新绘制时再次打开空白画布。

## 设计与验收

正式交互和边界见[交互设计](../../design/claude-agent/sketch-input-interaction-design.md)，原实施与评审见[原执行记录](../../exec/sketch-input-implementation-20261009.md)，本轮三项功能的完整验证见[合并交付记录](../../exec/chat-image-sketch-delivery-20261010.md)。

验收应覆盖正常绘制、局部擦除、撤销重做、清空恢复、空白禁止添加、返回后继续、PNG 上传、失败重试、发送失败恢复、附件移除、文件上传旧入口、窄屏、深色和键盘操作。历史与模型理解继续依赖既有 Chat 通路；本次前端隔离验证不能证明真实数据库保存或真实模型理解。

草图添加可以在关闭工作区的会话中使用。当前图片内容交给 Agent、以及继续用图片工具编辑，沿用已启用工作区的会话能力；关闭工作区时仅证明附件添加和消息发送，尚不支持把 PNG 内容送入主模型。这个既有缺口不能用画布测试或图片协议转换测试宣称已经解决。
