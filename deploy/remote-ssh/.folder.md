# deploy/remote-ssh/

## 架构概述
Remote SSH 发布脚本目录，用于把仓库同步到已安装 Docker 和 `docker-compose` 的远程服务器，并在远端运行专用 Compose 栈。

## 文件清单

| File | Pos | Function |
|------|-----|----------|
| deploy.sh | Remote SSH 发布入口 | 检查本地 SSH/rsync、`deploy/clash/config.yaml`、远端 docker-compose 与 `/dev/net/tun`，rsync 同步源码和配置（排除本地 virtualenv、QA artifacts、generated output 与持久数据），在远端执行 cache-aware Compose build、`up -d --force-recreate`、验证、日志、清理和上一版镜像回滚；支持可选 Compose override/env file 与 external network；默认创建远端持久目录并传递生产 OAuth/CORS/cookie 配置 |
| docker-compose.yml | 远端 Compose 模板 | 复用 backend/frontend Dockerfile，frontend 运行根 pnpm workspace 生成的 standalone Next.js；`tun-proxy` 发布后端本机端口，backend 共享 proxy 网络命名空间并取得 bubblewrap 权限；当前传入的 `VITE_PUBLIC_SITE_URL` 不被 Next Dockerfile 消费，不能作为前端元数据配置证据 |
| docker-compose.platform.yml | 阿里云 ECS overlay | 让 Dream 加入 Admin-owned external network 访问 embedded-PG alias，让 Gateway/Product API 共用通过安全校验的 Admin HTTPS origin，并按部署预算限制 backend 对 ECS 系统盘的读取带宽与 IOPS |
| prepare-env.sh | 跨仓库配置生成 | 从 Admin mode-0600 env 生成指向 embedded-PG alias 的 Dream DSN，并 fail closed 校验 Admin/Dream HTTPS origins 与 ECS block-device read budget |
| platform.env.example | ECS 配置模板 | 记录 ignored `.env` 的跨服务字段及可回滚 I/O budget，不保存真实 secret |
| .gitignore | Secret 边界 | 禁止提交 Remote SSH `.env` |
| setup-nginx.sh | Host 级 nginx 安装脚本 | 通过 SSH/SCP 在远端服务器安装 nginx、部署按 `REMOTE_BACKEND_PORT` / `REMOTE_FRONTEND_PORT` 渲染后的 `nginx/ink-and-memory.conf` 与 `nginx/suoxya-root.conf`（apex 站点）虚拟主机配置、启用站点；SSH 端口传给 `ssh -p` 与 `scp -P`；安装/启动前检查主机 `80` 端口，非 nginx 占用时中止，已有 nginx 占用时刷新配置并 reload；自动备份并禁用同域名旧 nginx 配置；支持 `WITH_SSL=1` 自动为 `suoxya.com` 及双子域名申请 Let's Encrypt 证书；使用前须设置 `REMOTE_SSH_HOST` |
| switch-edge-relay.sh | Host 边缘转发切换 | 仅用显式 SSH 目标、现有域名与 Dream/Admin relay origins 渲染两份 nginx 站点；保存带 SHA-256 的准确备份，`nginx -t` 后平滑 reload，失败自动恢复，并支持按准确备份目录回滚；不启停应用或修改数据 |
| setup-storage.sh | 远端文件系统初始化脚本 | 创建或修复 `${REMOTE_APP_DIR}/backend/data`、`file-storage`、`agent-workspace`、`backups`，可通过 `REMOTE_STORAGE_OWNER`、`REMOTE_STORAGE_GROUP`、`REMOTE_STORAGE_MODE` 调整权限 |
| setup-swap.sh | 远端 swap 初始化脚本 | 幂等确保远端至少存在 `REMOTE_SWAP_SIZE_MB`（默认 2048MB）swap；该保护仍覆盖容器化 Next.js 构建，但历史 Vite 内存测量不能作为当前 Next.js 容量结论，新的资源下限尚待单独测量 |
| sync-data.sh | 远端数据同步脚本 | 只暴露 `backup`、`upload`、`download` 三个动作；`upload` 先备份远端数据、再上传本地 `backend/data`，并执行 Compose `up -d --force-recreate` 让后端重新加载数据库；`download` 先备份本地数据再下载远端目录 |
| nginx/ink-and-memory.conf | Host 级 nginx 反向代理配置 | 默认按域名路由：`ink-backend.suoxya.com` → `127.0.0.1:8765`，`ink-frontend.suoxya.com` → `127.0.0.1:8080`；前端域名根级 robots/sitemap/llms 直连后端生成器；提供不会阻塞 nginx 启动的 host runtime DNS resolver；由 `setup-nginx.sh` 在部署时按 Remote SSH 端口环境变量渲染；含 WebSocket 升级、SSE 长连接、SSL 模板 |
| nginx/ink-and-memory.relay.conf.template | Dream 边缘转发模板 | 由 `switch-edge-relay.sh` 把既有 Dream 前端/后端域名统一转发到显式 relay origin，保留 `suoxya-root` 消费的共享 `ink_backend` upstream，以及动态 DNS、HTTPS SNI、Host、WebSocket 和无缓冲 SSE |
| nginx/ink-memory-admin.relay.conf.template | Admin 边缘转发模板 | 由 `switch-edge-relay.sh` 把既有 Admin/Gateway 域名转发到独立显式 relay origin，复用 Dream 模板提供的 resolver/upgrade map，并保留 HTTPS SNI、WebSocket 和无缓冲 SSE |
| nginx/suoxya-root.conf | Apex 域名 nginx 反向代理配置 | 主域名 `suoxya.com` 通过运行时解析的 `ink_landing` upstream 保留 `ink-memory.suoxya.com` GitHub Pages 落地页，根级 robots/sitemap/llms 仍走 `ink_backend`；临时 DNS 重启不会阻塞整个 nginx 启动；由 `setup-nginx.sh` 同样渲染并启用 |
