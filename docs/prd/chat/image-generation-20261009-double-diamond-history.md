# 聊天图片生成与编辑

本稿描述待实施的功能。[正式交互设计](../../design/claude-agent/image-generation-interaction-design.md)细化交互和业务图，[实施说明](../../design/claude-agent/image-generation-implementation-notes.md)维护技术边界。[历史原文](image-generation-20261009-history.md)保留，本轮检查见[执行记录](../../exec/image-design-purpose-rewrite-20261009.md)。

## 背景与问题

用户希望在同一段对话中提出图片需求、看到结果，并继续修改。现有聊天已经有附件、图片查看和历史会话基础，本次要补齐图片生成与编辑的完整体验。

## 目标与边界

目的：让用户在原聊天中得到图片、使用图片，并在之后继续围绕图片交流。

范围包括文字生成图片、当前会话参考图编辑、处理反馈、查看下载、保存和重开、后续引用、失败恢复与停止。界面沿用现有会话导航、输入框、过程区、图片查看器和权限操作。

本次交付是调研、产品需求和交互设计，不实现或部署新功能。首期不包含独立画布、局部涂抹、图片管理中心、批量画廊、跨会话图片引用、实时预览和后台生成任务，不新增接口方案选择页面或专用确认弹窗。

## 概念与规则

- 参考图片来自当前会话，编辑产生新图，原图保留。
- 图片结果直接显示在回复中，不只留在折叠过程里。
- 再次生成获得新结果；重新加载只打开已有图片。
- 会话保存保留对话和图片引用；下载将图片保存到用户设备。
- 停止使用原操作，已完成图片保留；停止不能保证上游工作或费用已撤销。
- 生成失败不会自动重复请求；图片可见不能代替会话已保存。

## 功能描述

| 功能 | 用户获得的能力 |
|---|---|
| 图片生成 | 用文字描述画面，在聊天回复中获得图片。 |
| 图片编辑 | 指定当前会话中的参考图和修改要求，获得新图片。 |
| 处理反馈 | 了解图片调用、等待授权、完成、失败和停止的情况。 |
| 查看与下载 | 查看图片，打开共享查看器放大、缩放和下载。 |
| 保存与历史查看 | 重新打开会话，继续查看相关对话和图片。 |
| 后续引用 | 继续使用已有图片提出修改，保留此前结果。 |
| 失败与恢复 | 了解问题，重新加载已有图或重新发送需求。 |

## 用户入口与完整流程

1. 用户打开当前会话，在原输入框描述图片需求；参考图使用原附件入口或会话中已有图片。
2. Agent理解需求，调用图像工具，原过程区显示“图片调用处理中”。
3. 工具授权沿用当前权限设置和已有授权区，提供原批准、拒绝和停止操作。
4. 完成图片直接出现在回复中，用户可以查看、放大和下载。
5. 对话与图片引用按原会话方式保存。用户继续描述修改要求，获得新图片。
6. 用户离开后重新打开会话，继续查看和使用已有结果。

无法生成、读取或保存时，会话保留已有内容并说明问题。重新加载和重新发送含义明确；断线恢复读取已有记录，不自动重复生成。当前会话未启用工作空间等已有使用条件应清楚说明，不自动修改设置。

## 桌面页面骨架

```text
┌ 现有会话/栏目导航 ┬──────────── 当前聊天 ─────────────┬ 原文件侧栏（按已有设置） ┐
│ 原栏目切换入口   │ 顶部：会话标题与原菜单             │ 当前会话文件             │
│ 原会话列表       │ ┌ 消息独立滚动范围 ─────────────┐ │                          │
│                  │ │ 用户需求与参考图片            │ │                          │
│                  │ │ 原过程区：调用反馈/工具授权    │ │                          │
│                  │ │ 回复：图片结果、查看入口      │ │                          │
│                  │ │ 后续修改与新图片              │ │                          │
│                  │ └─────────────────────────────┘ │                          │
│                  │ 原输入框：附件、输入、发送/停止   │                          │
└──────────────────┴───────────────────────────────────┴──────────────────────────┘
点击图片/放大 → 原共享查看器覆盖聊天 → 关闭回到原位置和焦点
查看器：图片查看区域 + 原缩放/下载/关闭入口
```

栏目切换沿用原导航；图片没有独立栏目。消息区独立滚动，输入区不进入消息滚动范围。授权使用原会话授权区，图片查看器是唯一需要打开的查看弹层，不新增生成确认弹窗。

## 窄屏页面骨架

```text
┌──────────── 当前聊天 ────────────┐
│ 原导航/栏目切换、标题、原菜单    │
│ ┌ 消息独立滚动范围 ───────────┐ │
│ │ 用户需求与参考图片          │ │
│ │ 调用反馈/原工具授权区       │ │
│ │ 回复中的图片结果            │ │
│ │ 后续修改与新图片            │ │
│ └────────────────────────────┘ │
│ 原输入框：附件、输入、发送/停止 │
└────────────────────────────────┘
原文件入口 → 沿用既有侧栏方式
图片/放大入口 → 共享查看器覆盖聊天
查看器保留可达的缩放/下载/关闭；关闭回原位置与焦点
```

图片宽度适应消息区域，不产生横向溢出。窄屏与桌面使用相同操作名称和恢复方式。图片说明、键盘操作及焦点恢复沿用现有可访问性要求。

## 验收要求

- 一段会话内能够完成生成、编辑、查看、下载和继续引用。
- 处理反馈与实际情况一致，授权等待、失败和停止含义明确。
- 图片与对话能够保存，重新打开后仍可查看和修改。
- 原图保留，已有图片读取失败不会变成新的生成请求。
- 生成、读取、连接和保存问题有对应反馈与恢复方式。
- 桌面、窄屏及原文本、工具、附件和媒体体验保持可用。

具体场景与业务图由正式设计维护。Image API和Responses API向用户提供同一套功能，由实施阶段选择已发布、获授权的接入方式。当前Codex界面和私有上游路径尚未确认；本轮只验证设计和文档，不宣称新功能或真实模型验收通过。
