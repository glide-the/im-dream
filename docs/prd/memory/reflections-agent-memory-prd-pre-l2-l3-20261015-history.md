# Reflections 到 Agent Memory

## 背景与问题

Reflections 已有“重复回响 / 性格折射 / 行为轨迹”三栏目、分析任务、报告保存与历史阅读。真正缺少的是：把值得在后续任务中使用的信息整理成有来源、可修正的持久记忆，并让用户和 Agent 都能使用这一闭环。

当前 Thread 的 `memory/` 保存程序性提示词和分析状态，不是跨会话用户事实库；Mem0 兼容工具没有完成真实检索。因此本需求不能作为“只加一个保存按钮”的前端任务实施。[本轮证据及方案判断](../../exec/reflections-agent-memory-design-review-20261014.md)区分了已实现能力、历史主张和必要新增能力。

## 目标与边界

复用 `AnalysisView` 和 `ReflectionBlogPage`，以已保存的单份报告为提取对象；分析完成后也使用同一报告入口。Agent 可按当前任务查报告、提取、保存或召回记忆。新增用户所有的持久记忆，不写入 Deck 内容、Agent 人设、程序配置或分析工作区。

本轮只交付设计。第一实施范围覆盖单份报告、同一用户的记忆、来源报告精确返回及后续修正。不增加独立记忆站点、按模式拆分页面、每个 Agent 的私人事实副本、向量库、图数据库、心理诊断、固定标签计数、自动分析日程、多个报告批量保存或模型训练。

## 概念与规则

| 对象 | 产品规则 |
| --- | --- |
| 原始来源 | 日记会话和任务提交时冻结的 Notion 正文；普通来源后续变化不改写原报告的分析历史 |
| 报告 | 一次分析的结果和解释，可包含失败栏目；保存报告不等于保存记忆 |
| 待保存内容 | 从报告整理出的条目，保留范围、时间、陈述性质和证据引用；提取本身不改变正在使用的记忆 |
| Agent Memory | 本需求建议新增的、认证用户所有的跨会话记录；Agent 按任务召回，其他用户、Deck 复制和发布均不能获得 |
| 事实与观察 | 原文直接表达的偏好、事件和意图可作为事实候选；跨情境规律和性格判断保存时仍写明“在什么范围观察到什么”，不能变成确定人格或心理诊断 |
| 来源 | 必须定位原报告及条目；精确原笔记来源只有核对成功时才展示，报告级 Notion 来源不冒充条目级引用 |
| 保存 | 用户在提取结果中点击“保存选中内容”即表达保存意图，不再弹确认；Agent 在用户已要求记住的范围内，可保存有直接证据、无冲突的普通事实；推断、冲突和明确改变信息用途的内容先让用户选择或修正 |
| 重复 | 正文和来源都已存在时只显示“已在记忆中”；正文相同但有新来源时显示“可补充本报告来源”，仍可勾选保存，只合并来源，不新增正文 |
| 冲突与变化 | 并列显示现有信息与新信息、来源日期和适用范围；用户可保留原记录、替换为新版本或补充不同条件；没有根据时不猜测“最新一定正确” |
| 修正 | 修改正文和适用范围后保存为新版本；“不再使用”停止后续召回，保留来源和旧版本；同一列表可“查看已停用”，详情可“重新使用”；原报告不随记忆修正而重写 |
| 三层 | 资料中的内容分层与处理阶段分别采用；第一版不强制填社会属性、人格标签或情绪主题，完整对应关系见正式设计 |

没有新增可配置策略页面。程序所需容量、运行时间和模型限制沿服务端配置，不把任意次数、置信度或相似度常量包装成产品规则。

## 用户入口与完整交互

1. 从最新三份报告或现有时间轴打开报告。在报告顶部点击“提取记忆”，范围为这份报告已完成的全部栏目，显示实际包含栏目；不重新运行分析。报告没有保存时，先沿原“重试保存报告”入口恢复，不能从未保存的流式输出写记忆。
2. 报告正文内展开提取区域，显示整理进度和结果。栏目导航、报告上下文与返回入口保留；使用同一页面，不打开提取向导或第二层弹窗。
3. 普通、有直接来源且无冲突的条目默认选中。推断和冲突条目不默认选中，显示具体原因，用户可编辑和选择。重复条目显示现有记录，无结果时显示“这份报告没有新增可保存的记忆”。
4. 点击“保存选中内容”提交全部选择。成功显示新增、修订、已存在的实际结果，提供“查看记忆”和“返回报告”；未保存的推断仍留在报告中。没有选中条目时不提交。
5. `AnalysisView` 增加轻量“Agent 记忆”入口，在原页切换为记忆列表和详情；报告页提供同名入口。默认查看有效记录，同处提供“查看已停用”；详情显示正文、适用范围、来源报告和“编辑 / 不再使用”，停用详情提供“重新使用”。首次没有记忆时给出返回报告提取的入口，不创建示例记忆。
6. 编辑复用详情内字段及保存操作。离开页面后重新打开，已提交记忆从服务端读取；提取结果和已同步的编辑草稿按原提取记录恢复。尚未同步的输入不宣称已保存，显示“草稿尚未同步”。

多个报告仍分别提取，避免选择来源、合并和部分保存的额外流程。不同模式产生的同一信息在单次提取内合并来源；模式不是目标记忆层，也不是保存归属。

## 失败、重试与恢复

| 情况 | 用户反馈与恢复 |
| --- | --- |
| 提取失败 | 保留报告，显示“记忆整理未完成”和具体可恢复原因；明确失败后才提供重新整理，不重新分析 |
| 提取或保存结果未知 | 显示“正在核对结果”；未取得提取 operation_id 时按原 request_key 只读查询，保存用原 key 查收据，不能提交新 key |
| 离开或重开 | 服务端提取记录恢复进度、候选及已同步编辑；浏览器只保留当前用户的操作标识和返回位置 |
| 保存前记忆已变化 | 保留输入，更新原记忆对比；提示“记忆已更新，请检查这处变化后保存”，不覆盖他人或其他 Agent 的新版本 |
| 无结果或全部重复 | 正文及来源均重复时只查看原记忆；有新增来源时保留“补充来源”选择与一次保存，无新增正文 |
| 部分栏目分析失败 | 仅从报告实际保存的成功栏目提取，明确缺少栏目；不把失败当成无可记内容 |
| 权限或来源失效 | 不读取其他用户资源，不通过凭据重放扩权；保留当前已允许阅读的信息，来源失效时停止新增提取并给出恢复入口 |
| 记忆存储能力未发布 | 原分析和报告阅读继续可用；记忆入口说明暂不可用，不写文件或配置字段代替保存 |
