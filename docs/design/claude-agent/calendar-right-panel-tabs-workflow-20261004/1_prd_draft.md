# Stage 1：产品需求设计

## 背景与问题

优化后的执行提示词：根据原图的选中图标页签规则，核对 Ink & Memory 当前 CalendarPopup、Chat、Notion 连接器与官方 API，输出右侧定时任务、日记、Notion 三个互斥栏目的增量产品合同。保留左月历及既有业务；明确实际资源范围、IANA 时区当日半开区间、上游创建/编辑字段、去重计数、失败与恢复、数据权限、并发和只读效果。严格区分源码事实、建议接口和待实施能力；Search 无法保证全集时保留目标阻塞。仅生成中文文档，不产出功能代码或原型代码。

## 概念与规则

### 图片观察

原图是横向导航：左侧被选中的 Home 有低对比圆角背景，内部同时放房屋图标和名称；中间聊天与右侧日历只有灰色图标。所有项沿同一基线，项间由留白区分。图像没有任务、日记、Notion 的业务字段；只能说明导航密度与选中形式。

### 模块结构（自上而下、自左至右）

| 模块 | 位置 | 功能 |
| --- | --- | --- |
| 月历 | 桌面左列，窄屏上方 | 沿用日期导航和日记标记 |
| 栏目导航 | 右列顶部，窄屏月历下方 | 定时任务 / 日记 / Notion 三个互斥页签 |

### 下游阶段必须保留的决定

1. 首次打开时已登录提供三个栏目并默认选定时任务，未登录仅日记/Notion并默认日记；弹窗已开时登录仅补入口并保留当前栏目。登出使任务项消失时回日记，键盘只遍历可见项；Notion 未连接不隐藏，去 Settings 连接。
2. 原 App 初始日期不一定是今天。非今天不查询、不显示今日清单；显示日期说明与回到今天操作。
3. 同日切栏保留各列表滚动和任务结果，不无条件卸载状态 owner；Modal 打开时沿用背景不可操作规则，不增加未提交确认。
4. 当前 RESULT 不提供编辑或历史按钮，返回 LIST 即可继续操作；不因原稿曾描述按钮就制造额外功能。
5. Chat 的页签是内联实现，`NotionMark` 是 Settings 内部函数。可以复用样式、状态和字形，不能声称已有完整可复用 TabBar 或公共 Notion 图标。
6. Search 可发现页面、授权范围、项目已选范围、本地同步与今日命中分别定义；新元数据边界不能扩大 Agent 正文权限。
7. 创建优先归组，双命中只计一篇并保留两标识；时间来自 Notion 原始 page 字段。
8. 新今日 GET 接口明确标为建议；没有 created_time 与安全部分结果合同便不能声称已满足目标。
9. Search 全页消费仍不是全集；严格完整目标存在阻塞。官方最新 API 不能当作 `ntn 0.15.1` 已固定请求版本。
10. 未连接、过期、拒绝、搜索无候选、今日无命中、网络、限流、部分与刷新旧结果有不同状态，不共用“暂无数据”。

### 阶段结论

Stage 1 文档已完成；功能未实施、真实业务未验收、独立评审尚由后续角色执行。交互设计必须包含完整流程、状态、可访问性、权限和追踪矩阵，评审不得把 API 限制改写成目标已经满足。
