## Architecture

- Scope: `docs/stage`
- Function: 保存跨模块技术依赖、阶段顺序、验收证据和回滚边界。
- Rule: 计划中的先后关系必须来自代码、制品、配置、安全或验证依赖。

## Files

| File | Pos | Function |
|---|---|---|
| `stage_*.md` | `technical-stage-plan` | 按依赖组织工作项、验收、失败语义与回滚。 |
| `stage_mcp-apps-system-architecture.md` | `mcp-apps-phase-plan` | MCP Apps Phase 0→3 当前技术执行顺序和证据要求。 |
| `stage_official-appserver-offline-supply.md` | `official-appserver-supply-plan` | 官方 AppServer 固定身份、离线闭包、标准 MCP smoke、消费与清理顺序。 |

## Maintenance Rules

- 依赖变化时同时更新 Mermaid、阶段表、验收和回滚。
- 只在当前候选上存在命令、退出码、关键输出和可回读证据时声明技术完成。
- 旧版本或旧 lock 的结果必须标明历史适用范围。
- 真正的安全或运行条件缺失时 fail closed，并保留普通业务路径。
