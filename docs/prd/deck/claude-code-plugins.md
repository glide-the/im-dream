# Claude Code Plugins 产品需求

## 背景与问题

用户创建或编辑思维模式时，需要从 Admin 已发布的 Claude Code Plugins 清单中选择所需插件。当前页面和历史设计同时出现“Deck 工作流插件”“ClaudeAgent 运行时插件”和“Claude Code Plugins”，并把工作流发布、插件安装和思维模式选择放在同一插件页面，用户无法判断这些名称是否代表不同产品，也无法判断自己只需要完成哪项操作。

历史设计还保留 Voice、Paperclip、测试 Harness、插件文件准备和任务运行过程。这些内容不能说明用户为何选择插件，也不属于思维模式创建流程。

## 目标与边界

本需求只解决一件事：用户在创建或编辑思维模式时，从 Admin 已发布且当前可选的 Claude Code Plugins 清单中选择插件，并清楚知道选择是否已经保存。

本次范围包括：

- 在思维模式创建流程中查看和选择 Claude Code Plugins；
- 在已有思维模式中查看和调整插件选择；
- 展示插件名称、用途、版本和当前是否可选；
- 区分尚未保存、保存中、已保存和保存失败；
- 当清单无法读取、插件不再可选或保存失败时，提供明确反馈和恢复操作。

本次范围不包括：

- Deck 工作流插件的创建、发布、运行和工作台交互；
- 独立的“ClaudeAgent 运行时插件”产品或管理页面；
- Claude Code Plugins 的安装、卸载、版本发布和来源维护；
- 远程 Marketplace 的注册、提交、审核、发布和运营平台；
- Voice、Paperclip 任务、测试 Harness 或 Claude Agent 内部加载过程；
- 会话内临时安装、旧会话升级和插件开发工具。

## 概念与规则

### Deck 工作流插件

Deck 工作流插件服务于 Dream 类型 Agent 的创作工作台，定义用户在工作台中使用的业务工作流。它不属于 Claude Code Plugins 清单，现行规则见[独立 PRD](./deck-workflow-plugin.md)。

### Claude Code Plugins

Claude Code Plugins 是用户创建或编辑思维模式时可以选择的 Claude 插件。每个清单项至少说明插件名称、用途和版本。用户只负责选择，不负责安装、发布或维护插件来源。

### Admin 发布清单

Admin 发布当前允许选择的 Claude Code Plugins。本文只把发布结果作为选择清单的来源，不设计 Admin 如何注册、审核或发布插件。

### ClaudeAgent 运行时插件

“ClaudeAgent 运行时插件”不作为用户产品分类。现有代码中与运行阶段有关的内部对象可以保留原标识，但页面和产品文档统一使用 Claude Code Plugins，并通过具体状态说明插件是否可以选择。

### 远程 Marketplace

远程 Marketplace 发布平台尚未设计。本文不提供入口、角色、状态、流程或验收要求，也不把已有安装和来源检查代码解释为完整的发布平台。

### 选择规则

- 用户只能选择 Admin 当前发布且允许用于思维模式的插件。
- 未选择插件是有效状态，表示该思维模式不附加 Claude Code Plugin。
- 用户勾选或取消插件后，页面先显示“尚未保存”；只有服务端确认后才显示“已保存”。
- 保存成功只表示思维模式记录了插件选择，不表示某次对话已经使用插件。
- 已有思维模式中不再可选的插件应保留名称和原选择提示，避免用户把清单变化误解为自己的选择被自动删除；具体迁移处理需要单独设计，不在本次增加自动替换。

## 功能描述

| 功能模块 | 功能描述 |
| --- | --- |
| 可选插件清单 | 展示 Admin 已发布且当前可以用于思维模式的 Claude Code Plugins。 |
| 插件信息 | 展示插件名称、用途和版本，帮助用户判断是否需要选择。 |
| 创建时选择 | 用户创建思维模式后，在同一维护流程中选择插件，并保存本次选择。 |
| 编辑时调整 | 用户打开已有思维模式，查看已经保存的插件，增加或取消选择。 |
| 选择结果 | 明确区分尚未保存、保存中、已保存和保存失败。 |
| 不可用反馈 | 清单无法读取、插件不再可选或保存失败时，说明受影响内容和可执行的恢复操作。 |

## 页面信息架构

Claude Code Plugins 只出现在思维模式创建或编辑弹窗的“Claude Code Plugins”栏目。设置页中的工作流发布、插件安装和来源管理不属于本需求。

创建思维模式仍沿用现有“创建后打开维护弹窗”的流程。用户可以先填写基本信息，再进入 Claude Code Plugins 栏目完成选择。已有思维模式通过同一维护弹窗调整选择。

## 用户流程

1. 用户创建思维模式，系统打开维护弹窗；或者用户打开已有思维模式。
2. 用户进入 Claude Code Plugins 栏目。
3. 页面显示 Admin 已发布且当前可选的插件，以及已经保存的选择。
4. 用户查看插件用途和版本，勾选、取消或保持空选择。
5. 页面显示“尚未保存”，用户执行保存。
6. 保存成功后显示“已保存”；保存失败时保留本次选择并显示失败原因。

## 状态与失败反馈

| 状态或场景 | 用户看到的内容 | 用户可以执行的操作 |
| --- | --- | --- |
| 正在读取 | 显示正在读取，不显示空清单 | 等待读取完成 |
| 清单为空 | 显示“当前没有可选插件” | 继续保存空选择或返回其他栏目 |
| 读取失败 | 显示清单暂时无法读取，保留已有可确认信息 | 重新读取 |
| 已保存 | 显示服务端确认的插件选择 | 继续编辑或关闭弹窗 |
| 尚未保存 | 显示当前选择已经变化 | 保存或继续调整 |
| 保存中 | 显示正在保存并避免重复提交 | 等待结果 |
| 保存失败 | 保留当前勾选并说明保存未完成 | 检查选择后重新保存 |
| 保存结果无法确认 | 不显示成功，说明需要重新读取 | 重新读取已保存选择，不自动再次提交 |
| 已选插件不再可选 | 显示插件名称、原选择和“当前不可选” | 保留现状并等待管理员处理；本次不提供自动替换 |

错误信息说明用户需要知道的结果和恢复操作。接口名称、服务器路径、文件摘要、命令行退出码和任务运行过程不进入普通页面文案。

## 影响范围

目标交互涉及：

- 思维模式创建后的维护弹窗；
- 已有思维模式的维护弹窗；
- Claude Code Plugins 清单与选择反馈；
- 现有重复插件分类和设置页入口的后续收敛。

当前代码仍在“设置 → 工作台 → 插件”同时展示旧工作流管理和 Claude Code 插件安装管理，并在旧区域展示“ClaudeAgent 运行时插件”。这些页面不属于本 PRD 的目标用户流程，属于实现与现行产品边界的差距。本轮只完成设计，不修改程序。

## 验收条件

- 用户可以在创建或编辑思维模式时查看并选择 Claude Code Plugins。
- 页面只使用“Claude Code Plugins”作为该清单的产品名称。
- 用户能够理解插件名称、用途、版本和选择状态。
- 未选择插件可以保存，不增加无业务依据的必选限制。
- 保存结果与对话实际使用结果明确区分。
- 读取失败、保存失败和插件不再可选都有明确反馈与恢复操作。
- Deck 工作流插件不再作为 Claude Code Plugins 页的分类。
- “ClaudeAgent 运行时插件”不再作为用户可管理的独立产品。
- 当前设计不包含插件安装、卸载、来源维护或远程 Marketplace 发布平台。
- Voice、Paperclip 和测试 Harness 不出现在本功能的用户流程与页面说明中。

上述验收条件是产品与文档标准。页面代码完成并经过对应用户流程验证前，不得标记为功能已经实现。
