# Dream Chat 单个 Thread 的用户消息轮次导航 — PRD

> 本稿依据用户提供的两张 Codex 截图和 Dream 当前 Chat 结构编写。截图里的消息正文、产品名称、颜色和气泡样式仅是视觉参照，不是本项目的业务指令或验收文案。配套文档为[结构草图](./turn-navigation-structure.md)、[层级逻辑](./turn-navigation-hierarchy.md)和[视觉规范](./turn-navigation-ui.md)。

## 背景与问题

单个 Dream Thread 可以积累多次用户提问、助手回复和工具过程。当前 `ChatPanel` 把消息放在独立滚动区，历史消息按页加载；用户要回看某次提问，需要在长消息流里反复滚动。现有右侧 HistorySidePanel 用于切换 **Thread**，不能定位当前 Thread 内的一条用户消息。截图突出的是贴近消息区左边的一列细刻度：每个刻度代表一次用户输入，指向它会出现含本轮内容的浮层。

此功能让用户从当前 Thread 内的任意已发送消息进入对应交互，既能回看最初的问题，也能看到本轮助手的结果；它不改变消息发送、Agent 执行或现有 Thread 导航。

## 目标与边界

1. 在有已发送用户消息的 Thread 中，消息滚动区左侧显示一条窄导航轨道；**每条由用户实际发送并出现在当前 Thread 对话历史中的消息恰好有一个导航项**，顺序与消息时间线相同。文字、附件和混合输入都计入；草稿、未派发的排队卡片、系统消息、工具步骤、助手回复及自动修复产生的系统输入不冒充用户导航项。
2. 点击导航项后，在当前 Thread 的消息滚动区定位对应用户消息，使该消息位于可读区域，并可顺序阅读其后的回复；不切换 Thread，不重新发送消息，不展开或重跑工具。
3. 鼠标悬浮或键盘聚焦某项时，显示该次交互摘要：用户输入预览、对应助手结果预览或明确的进行中／失败／暂无回复状态。摘要只从当前用户可读取的本 Thread 消息及现有状态形成，不生成新的模型摘要，不展示其他 Thread 内容。
4. 导航适用于 Chat 主视图以及复用同一个 `ChatPanel` 的窄列／侧边任务会话；布局遵循 Dream 当前亮色和暗色语义 token。不得从截图复制 Codex 的黑灰蓝配色、气泡、书签按钮或产品文字。
5. 本期不添加新的会话分类、跨 Thread 总览、置顶／收藏、编辑历史消息、数据库表或资源策略；不改变现有右侧历史面板和移动端底部导航。

## 概念与规则

| 概念 | 输入与判断 | 展示与行为 |
| --- | --- | --- |
| 导航消息 | 当前 `thread_id` 的用户消息；由现有持久化历史和实时消息按稳定 `message.id` 去重。自动修复等由系统注入且带明确来源元数据的输入不算用户主动发送。 | 每条对应一个短横刻度。重新渲染、SSE 重连、历史分页合并后不出现重复项；Thread 切换后清除旧项。 |
| 交互范围 | 从该用户消息起，到下一条用户消息之前的消息；未出现下一条时延伸到当前最新内容。 | 当前轮摘要只取本范围的助手结果，不把下轮回复误配给上轮。工具日志仅用于判断“处理中／失败”等状态，不逐条列在浮层中。 |
| 摘要正文 | 用户消息的可见文本和附件名称／类型；助手最后一段可供用户阅读的文本结果。 | 用户预览为主行，回复预览为次级行。保留原文含义，按容器截断；不解释或改写模型回答。纯附件消息显示附件名称或“已发送附件”。 |
| 无回复／处理中／失败 | 当前范围没有助手结果时，以现有轮次状态和错误回执区分。 | 分别显示“暂无回复”“正在回复”“本轮失败”等明确文字；结果待核对时显示“状态待核对”，不得推断完成。后续真实回复到达时更新同一项。 |
| 当前阅读位置 | 消息滚动区内当前主要可见的用户消息；一次点击定位会将目标暂设为当前项。 | 刻度通过对比度和形状／长度增强，并提供语义上的当前位置；不能仅靠颜色。滚动阅读时随可见消息更新。 |
| 历史未加载 | 当前历史页没有目标消息，或完整导航索引尚未取得。 | 若可通过现有受权历史分页取得，加载到包含目标消息后定位；加载时仅在轨道或浮层显示进度。不可取得完整索引时明确显示“仅显示已加载消息”，不能把部分刻度冒充完整 Thread。 |

“一次交互”按用户消息分段，而不是按助手分段：连续两条用户消息各有刻度；某轮无助手结果时仍保留该用户消息入口。用户消息被现有产品规则隐藏或不可读取时，不从客户端猜测正文；若服务端返回可见占位，则导航对准该占位并显示“内容不可用”。导航项所用 ID 是消息定位键，不展示给用户。

## 页面模块结构（从上到下、从左到右）

| 区块 | 位置与形态 | 信息和功能 | 与现有模块的关系 |
| --- | --- | --- | --- |
| A 顶部 Chat 标题与操作 | 消息区上方，沿用 Dream 现有页头 | Thread 标题、既有任务／历史等操作 | 本功能不占用页头，不新增一级按钮。 |
| B 轮次导航轨道 | **消息滚动区内部左缘**，紧凑窄列；没有贯穿竖线，每条消息只是一根短横 | 一条已发送用户消息对应一个可点击刻度；当前／悬浮项与邻近刻度形成平滑伸缩的长度层次。轨道不覆盖正文或原滚动条。 | 属于当前 `ChatPanel` 的消息阅读区，不是全局会话侧栏，也不移动右侧 HistorySidePanel。 |
| C 交互摘要浮层 | 指向或聚焦 B 的刻度时，在轨道右侧、消息正文之前或其上层出现的紧凑纸面浮层 | 用户预览、助手结果／状态、必要时的附件说明；内容过长截断，可从定位后的原消息阅读全文。 | 遵守现有 Chat tooltip、阴影、边框和字体 token；贴边时向可用区域调整，不能盖住输入 Dock。 |
| D 消息正文 | B 的右侧，保留当前用户气泡、助手 Markdown、工具折叠区和错误块 | 点击 B 后滚到该用户消息，随后阅读同一轮互动。 | 复用 `ChatMessageList` 的消息节点和当前滚动容器；不另建消息渲染路径。 |
| E 底部输入 Dock | 消息区下方，原位置 | 发送、停止、排队等现有操作 | 刻度列和浮层不遮挡 Dock，也不改变其状态。 |

截图中的红框是标注，不属于最终界面。补充截图明确了“贴边短刻度＋邻近伸缩动画＋小型悬浮摘要”的信息密度；具体间距、色彩、圆角与动效以[当前视觉规范](./turn-navigation-ui.md)为准。刻度按消息顺序排列，而不是按截图中刻度数量或实际像素位置硬编码；历史很长时，轨道可自身滚动并保持每项独立可操作。

## 交互、状态和失败反馈

1. **进入 Thread**：读取已有消息后生成导航。没有已发送用户消息时不画空轨道；首次消息成功进入当前 Thread 后新增对应刻度。历史加载中显示低调加载状态，不生成假刻度。
2. **悬浮与聚焦**：对应刻度显示浮层；鼠标离开刻度与浮层、焦点移出或按 Escape 时关闭。浮层打开时不更改消息滚动位置。用户长文本和助手长回复只显示可读预览，完整内容在原消息中查看。读屏能够获知“第几条用户消息”、预览及回复状态。
   当前阅读项或悬浮／聚焦项是刻度伸缩的中心，邻近项按距离逐级缩短、变淡；过渡只在位置变化时触发，系统设置减少动态效果时直接切换。
3. **点击与键盘激活**：刻度支持点击、Enter 与 Space。定位时让对应用户消息及其开头进入可见区域，避开顶部遮挡；滚动动画遵循系统减少动态效果设置。定位后焦点回到可继续键盘导航的轨道项，视觉上突出目标消息片刻，不改动消息数据。
4. **实时回复变化**：已发送消息在助手生成中仍有刻度；浮层状态从“正在回复”更新到结果或真实失败。刷新、重连与历史分页以服务端已保存的消息为准，不能因临时 SSE 断开直接标记失败。
5. **历史分页**：点击未在当前渲染列表中的消息时，请求既有历史页并按消息 ID 找到目标。加载失败时留在原位置，浮层附近显示“暂时无法定位”及“重试”；重试不发送消息。切换 Thread 或重复点击其他项时，较早请求不能把页面滚回旧目标。
6. **错误与权限**：历史读取失败保留当前已加载的项，显示其范围有限和重试入口；当前 Thread 不可读取时沿用原认证／权限反馈，不泄露摘要。摘要构造失败时该项仍可导航，浮层只显示可用的用户预览及“摘要暂不可用”。

## 响应式与可访问性

- 宽桌面沿消息区左缘放窄轨道，不新增占据整列的大侧栏。右侧历史／文件面板打开时，轨道随 `ChatPanel` 实际宽度收缩，正文保持可读，不产生横向滚动。
- 窄桌面和侧边任务聊天保留轨道，但扩大刻度的实际点击区域；视觉短线仍可细。浮层按消息容器边界定位，必要时移到刻度右下方，允许换行。
- 手机视口若固定左轨道会压缩正文，使用消息区内可展开的“本对话消息”轻量入口，展开后按时间顺序列出同一批用户消息和摘要；选中后关闭列表并定位。该入口不覆盖底部 Chat／Dream／Decks／More 导航或输入 Dock。触屏通过点击查看摘要和选择定位，不依赖 hover。
- 刻度和移动入口具备清晰名称、可见焦点、足够的点击区域；当前项同时使用 `aria-current` 或等价语义与视觉差异。浮层文字对比度遵循主题；状态文字不只用颜色或动画表达。

## 实现建议与边界

- 由 `ChatPanel` 维护当前 Thread 的滚动容器和分页定位协调；从 `ChatMessageList` 已渲染消息的稳定 ID 建立锚点。复用现有 `UIMessage`、消息历史查询及已有轮次状态，不复制一套消息列表或运行状态机。
- 若既有分页响应没有足够信息构成完整 Thread 导航，先核对现有可用历史读取能力；仍不足时在受权服务端提供只读的消息索引／预览投影。该投影只读已有持久化消息，返回当前用户有权读取的字段，不引入数据库 schema、额外 Agent 推理或新 Thread 行为。
- 摘要预览按显示文本安全转义，链接、Markdown 与附件名称均按现有消息渲染安全边界处理；浮层不执行消息中包含的内容。存量内容和未来消息使用同一规则。
- CSS 引用 Dream `tokens.css` 的语义变量，不硬编码参考产品颜色。文案加入现有中英文国际化资源。实现阶段同步受影响目录 `.folder.md` 与源码文件头。

## 验收

1. 一个 Thread 有三条已发送用户消息（含一条纯附件）时，轨道恰有三个按时间顺序排列的刻度；草稿、排队卡片、工具和自动修复输入不新增刻度。
2. 逐项悬浮与键盘聚焦可见正确用户预览和对应轮助手结果；连续用户消息、无回复、进行中、失败及结果待核对互不串轮。长文本和附件摘要可读且不溢出。
3. 点击首条、中间和末条刻度，均在同一 Thread 的滚动区定位到正确用户消息；不重发、不重跑工具、不改变输入草稿。滚动阅读后当前刻度随阅读位置变化。
4. 在只有最近页已加载的长 Thread 中选择更早消息，可加载对应历史并定位；网络失败有明确重试，失败时不误跳转，重复点击或切换 Thread 不产生过期定位。
5. 新消息发送成功、助手流式输出、完成、刷新和 SSE 重连后，刻度与摘要保持一致且不重复；暂时断线不伪报本轮失败。
6. 在 Chat 主视图、右侧面板展开、侧边任务会话、亮／暗主题及约 390px 手机视口检查：消息正文、浮层、输入 Dock 和移动底部导航均不被遮挡，不出现页面级横向滚动。
7. 用键盘和读屏完成打开摘要、遍历刻度、定位、关闭；无权限的 Thread 不返回或显示消息预览。
8. 桌面轨道保持约 `2.5rem` 的视觉宽度，短横紧凑排列、无贯穿线；悬浮卡最多显示简短的用户与助手预览，不使消息正文为大卡片额外让位。
