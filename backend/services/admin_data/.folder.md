# Admin authentication/data consumers

## 架构概述

统一消费Admin OAuth和领域数据协议，无PG/SQL/fallback。现Product客户端绑定HS256与Product专属过滤，不能复用为全域transport；保留其业务DTO，接入时迁移authority。

资源操作 input/output 版本均为1；pins来自Admin实际 [operation artifact](../../../docs/architecture/admin-auth-data-interaction.md)。缺广告/hash不匹配/网络或响应错误 fail closed；provider保留LKG。observer未知写尚无committed回执时阻止后续snapshot写入，不能认为absent意味着失败。历史 `resource_postgres_sink` 名称继续作为内部标识，已无SQL；不借文档清理更改Agent接口。

Runtime四special route在`auth.delegations`单独广告，不走generic data operation dispatch；缺schema/任一路径、method、version/hash不匹配时create fail closed。当前create digest按Admin实际非空text IDs生成，不额外增加160字符业务限制。public Runtime config仅含Admin origin与transport边界，无service/DB/Gateway秘密。Keeper已接公开turn服务器持久化和Editor exact Session grant；CLI及其余后台持久化仍待接线。

Editor runtime由公开Chat的OAuth actor创建，grant固定为当前Thread、`editor-stdio`、exact Editor Session、`editor:read`与`editor:write`，并在创建前核对两个Editor operation hash。主进程用opaque idg调用public load/replace/receipt，写响应未知时只查询原UUID且absent继续阻止新写。子进程经随机turn-local capability访问`127.0.0.1`有界broker；MCP配置不投影OAuth、service secret、idg、actor ID、`DATABASE_URL`或Admin origin。切换Session先让Admin创建新exact grant并完成load，随后主进程采用缓存；Factory只在有Editor上下文时于admission后启动broker，并在terminal/cancel的Phase4清理所有owner。

公开Chat Workflow context在已有Deck/Voice绑定后、message预留/SSE前通过明确OAuth读取；read failure拒绝，null不会触发旧PG mapper。Service只接收与actor/thread匹配的immutable snapshot；内部confirmation/launch仍保留原guard/mapper，未据此声明全Workflow/Runtime迁移。

公开user-turn采用server-persistence idg绑定whole Thread/authoritative Run，Admin原子执行stored confirmation guard、rawmessage和missing title。Service复用已确认同一输入，complete/partial assistant再用同一owner调用原`chat-message.persist`与四项exact schema gate。unknown保存原UUID并只查原receipt，absent阻止新操作。Keeper HTTP不占current短锁，Factory在既有admission后启动并在terminal/cancel安排自有Phase4 cleanup，SSE disconnect不停止后台turn；cleanup等待已经dispatch的同步writer和自有renewal线程后关闭独立Runtime client。内部dispatcher assistant、后台Session上下文、其余领域和Gateway/Editor仍待接。

公开Session仅由当前request OAuth授权；Session Handler不接受Thread server-persistence grant，ContextBuilder/Session工具仍待独立领域合同。metadata省略内部text:null、时间保留PG微秒ISO，Dream计算date_key/metrics；update/delete只在command确认后发原event，unknown不发event/不retry。

公开Agent Thread读取/SDK init/final/repair Session回写与公开assistant完整/部分消息使用同一exact server grant。user/session/assistant pending保留原operation/input/UUID，只同输入原receipt恢复；最近确认Session可复用，A→B→A重写。SDK init失败保持原callback日志/运行turn与cancel；内部dispatcher assistant与Run DB仍不属于此屏障。Thread读取同样由cleanup drain，reply actor/thread错配拒绝。

公开Deck content state/preview/commit/history/detail只走request OAuth，拒绝Runtime purpose作为Deck管理授权。四schema为identity/unified/content-versions/canonical-storage exact v1；capability缺失/hash drift时在domain I/O前503。rawsnapshot只校验闭集shape并还原原public dict/creator int/微秒，写ID错配unknown；safe409保留两revision，unknown原UUID无retry。其余Deck14/refs/voice/runtime和内部版本Service仍待consumer迁移。

公开preferences只用current request OAuth。GET缺记录{}，required nullable rawconfig保留Pythonfloat/negativezero/bigint再还原dict，firstlogin只读JSON-safe int，时间保留offset/微秒。POST五optional公共字段转requirednullable wire，null保留，emptyobject/emptytext写入，strict拒外部actor/firstlogin/System字段。无法投影公共JSON的stored config503且无heal；unknown保留原UUID/no retry。System/defaultvoice/Runtime/后台context与import不扩权。

公开Settings的get/patch与Chat/Workspace预检使用current OAuth SystemConfig operation；active Agent turn通过同一`AdminTurnPersistence`的exact Thread grant fresh读取。raw `config_json`由Python解析，保留bigint、float、negative zero、Unicode与未知key；非object、invalid或非有限数503且不默认/修复。Settings patch保持十字段闭集、Gateway模型校验和post-patch fresh get；unknown只查原UUID receipt。缺owner的内部guidance/dispatcher在SystemConfig前fail closed。

公开Reflections配置GET/PUT/DELETE与`memory-init`使用current OAuth读取或写入用户分区配置。save/delete响应未知时，用同一OAuth和原request ID查询一次原operation receipt；只有committed且原output DTO有效才返回成功，absent、查询失败或坏回执保持outcome unknown，不POST重发。Dream继续管理静态default、显示字段、五个文件名过滤、partial merge、`usedCustomConfig`和文件写入；`memory-init`在配置读取前先用Admin Chat确认Thread归属。后台Reflections task没有可续期OAuth或已发布领域grant，仍保留旧read helper并列为待迁移。

Client catalog readiness/完整refresh/operation广告检查共享RLock；fresh失败清空ready/广告，下一认证重新加载。领域HTTP在短检查锁外保持并发，actor/DTO/UUID每次显式传入，receipt原二态无retry。

PF execute 原请求 receipt 单独按三态 DTO 读取；通用 receipt 两态方法保持，不在 absent/in_progress 时重发或resume检查。PF POST仅关闭领域执行旧service依赖，default Workspace仍未迁移。

公开Deck update/delete/publish/collect/sync只调用单Admin领域operation。Version/Voice/Deck mutation共享原four exact schema检查；错误详情按code限制为Version两revision或Delete四reason，缺省Delete反馈仍复用原纯message类。Deck list/detail/create/default/provision与内部SQL仍保留迁移依赖。详见[现行稿](../../../docs/design/deck-mutations-current.md)。

公开Deck detail单Admin读取还原原owner int/ISO微秒/Voice Memory JSON。database只以原名alias复用提取的纯projection，其它函数不改。Admin producer目前把empty Memory归null而原Dream保留emptytext，该兼容缺口仍需Admin修正；consumer正确投影与技术PASS不表示该真实值已验收。
